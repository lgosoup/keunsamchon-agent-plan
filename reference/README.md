# reference — 원문 자료 보관소 (수정 금지)

**가공하지 않은 원본만 둔다.** 요약·해석·판단이 섞인 문서는 `../docs/`에 있고, 여기 있는 것은 그 문서들이 인용하는 **출처**다.
파생 문서와 원문이 어긋나면 **원문이 이긴다.** 그래서 여기 있는 파일은 오타·구어체·비문까지 그대로 보존한다.

**여기 있다는 것만으로 근거 순위가 높아지지 않는다.** 자료마다 지위가 다르다 (`../CLAUDE.md` 4절 근거 우선순위).

## 파일

| 파일 | 무엇인가 | 근거 지위 | 주의 |
|---|---|---|---|
| `기업과제_원문.pdf` | 참여기업(큰삼촌컴퍼니)이 배포한 기업과제 원문 | **1순위** — 기업이 직접 말한 것 | ⚠ **한글 텍스트 추출이 안 된다.** 원문 대조가 아직 미완이고, 브리프 인용은 `docs/00`에 옮겨 적은 문장을 쓰고 있다 |
| `사용자_플로우_원문_2026-07-30.md` | 사용자가 직접 쓴 **해외 기업 접촉 플로우 원안** + 같은 날 내려온 기능 분해 방침(폭포수·기능 단위는 크게) | 요구·제약의 근거가 **아니다.** ③단계(해결 설계)의 **1차 입력** | 파생본은 `docs/31_기능구조.md`. 파생본과 어긋나면 **이 원문이 사용자 의도의 정본**이다 |
| `상담_카톡원문_2026-07-28.md` | 실무자(문성호, 컴공) 상담 메모 + **그 자료의 지위를 밝힌 서문** | **3순위** — 이 과제를 모르는 상태에서 들은 일반론 | `docs/02_작업원칙.md`의 출처. 기업 발언(`docs/13`)과 어긋나면 **진다.** 심사·미팅에서 "실무자가 그렇게 말했다"를 근거로 쓰지 않는다 |

## 규칙

- **내용을 수정하지 않는다.** 오타 교정도 하지 않는다 — 원문이라는 것이 이 디렉터리의 유일한 존재 이유다.
- **예외는 사용자가 지시한 디렉터리 정리뿐이고**, 그때도 내용은 건드리지 않고 이동 사실만 이 README에 남긴다 (`../CLAUDE.md` 5절).
- 파일을 추가할 때는 이 표에 **무엇인가 · 근거 지위 · 주의** 세 칸을 함께 채운다. 지위를 안 적은 원문은 나중에 아무나 1순위처럼 인용한다.
