# 회차 파일 — 배치1(20건, 라쿠텐 공식 API 발굴분)

> **이 파일은 임시 회차 파일이다.** `specs/candidates/후보목록.md`에 다른 세션(배치2·배치3)이 동시에 쓰고 있어 충돌을 피하려고 별도 파일에 썼다. 병합은 나중에 한 사람이 순서대로 `후보목록.md`에 옮긴다(G1 Spec 「제약」— 병렬 수집 시 회차 파일로 나눠 병합).
> **소스**: `specs/candidates/_배치1_20건.json` (라쿠텐 상품검색 API로 발굴, `scripts/rakuten_api_discover.py`)
> **관찰 방법 공통 메모**: 20건 전부 입력 URL이 `www.rakuten.co.jp/{매장}/` 형식이고, 이 저장소에서 이미 20건 이상 반복 확인된 패턴상 WebFetch 직접 접근은 100% 차단(403)되므로 이번 회차는 직접 시도를 생략하고 바로 `접근차단_Jina리더재시도`(Jina AI Reader 경유)로 관찰했다. O8(광고 메일 거부 표시)은 이번 회차에서 시간상 생략하고 `?`로 남긴다(G4가 재확인, Spec상 블로커 아님).
