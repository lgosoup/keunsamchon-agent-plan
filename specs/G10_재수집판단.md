# spec.md – 재수집 판단 (G10)

## 목표
G3 보류분·G4 미확보분·G8 조사 오류·가치 低 판정분과 외부 시간 경과·트렌드 신호를 받아, **다시 열 대상**과 **무엇을 다시 볼 것인지**(전체 재조사 / 특정 관찰 항목만 / 연락처만)를 정한다.

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자
사용 목적: 이 기능이 없으면 플로우가 한 번 흐르고 끝나 **한 번 걸러진 기업이 영구히 사장된다.** 지금 커머스가 없는 곳이 6개월 뒤에 열 수도 있고, 지금 연락처를 못 찾은 곳이 담당자 정보를 갱신할 수도 있다.
**본 플로우와 다른 리듬으로 돈다.** 앞 단계가 끝나야 도는 것이 아니라 **네 곳의 출력이 수렴하는 지점**에서 주기적으로 판단한다.
**"무엇을 다시 볼 것인지"가 출력에 반드시 있어야 한다.** 전체 재조사와 연락처만 재탐색은 드는 비용이 전혀 다르다 — 이 구분이 없으면 매번 전체를 다시 돌게 된다.

## 입력
**단위 — 재수집 후보 1건(기업 1곳 + 유입 사유)씩 넣는다.**

- G3 **보류분**(적합도 낮음)
- G4 **미확보분**
- G8 **조사 오류·가치 低** 판정분
- **외부** — 시간 경과 신호 · 트렌드 변화 신호(무엇이 바뀌었는지의 설명 포함)

**[발송 금지] 상태는 이 기능의 입력이 아니다.** 주소를 찾았고 보내면 위법인 것은 다시 열어도 결론이 같다(`31` 3-3절).

## 범위
포함: 재수집 대상 판정 / "무엇을 다시 볼 것인지" 결정(전체/특정 항목/연락처만) / 재수집 사유 기록
제외: **실제 재조사 수행**(전체·항목 재조사는 G1의 일, 연락처만 재탐색은 G4의 일) / 원인 분석(G8) / 재수집을 확인하는 주기 자체의 확정(운영 방식, 이 Spec 뒤 단계)

## 제약
- **소스별 기본 대응**이 있다 — 벗어나려면 근거를 적는다

  | 유입 소스 | 기본 재조사 범위 |
  |---|---|
  | G8 조사 오류 | **연락처만**(G4) — 관찰 자체가 아니라 연락처 탐색이 틀렸던 것 |
  | G4 미확보 | **연락처만**(G4)이 기본. 단, 미확보 상태가 오래 지속되면 전체·항목 재조사로 승격할 수 있다(확인 후 채울 것 참조) |
  | G3 보류(적합도 낮음) | **기본은 재조사하지 않는다.** 외부 시간 경과·트렌드 신호가 함께 와야 특정 항목(규모·한국 진출 신호 등)을 다시 본다 |
  | 외부 시간 경과·트렌드 | **무엇이 바뀌었는지에 따라 다르다** — 신호 설명에 명시된 항목만 재조사 범위로 지정 |

- **"특정 항목만"을 지정할 때는 G1 관찰 항목 코드(O1~O9)에 있는 것만 쓴다.** 코드에 없는 항목을 스스로 만들어 지정하지 않는다
- **G1의 관찰층/규칙층 분리가 이 구분의 전제다** — 관찰 항목 하나만 갱신하고 규칙층을 재계산할 수 있어야 "특정 항목만"이 성립한다. 이 전제가 성립하는지는 `40` V1 결과로 확정된다(아래 확인 후 채울 것)
- **재수집 주기(며칠마다 확인할지)는 이 기능이 정하지 않는다.** 트리거는 외부에서 온다 — 언제·얼마나 자주 확인할지는 이 기능의 범위 밖(운영 단계, Build Order ⑤ Hook)이다. **구 설계의 60일·90일 수치를 재사용하지 않는다** — 그 값들은 근거를 잃어 폐기됐다(`90` 리스크 4)
- 미확인 값을 추정치로 채우지 않는다
- **재수집 후보 1건 = 판단 1단위.** 앞 건의 판단이 다음 건에 남지 않게 한다

**실행 형태 — Workflow다.** 소스 확인 → 재조사 범위 결정의 순서로 돌고 **실패하면 멈춘다.** 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 재조사 항목으로 G1 코드에 없는 것을 지정하려 한다 | **지정을 거부하고 사람에게 알린다.** 스스로 새 관찰 항목을 만들어내지 않는다 |
| 외부 트렌드 신호가 무엇이 바뀌었는지 불명확하다 | **재수집 대상에 넣지 않고 "신호 불명확"으로 보류한다** |
| 대상이 [발송 금지] 상태로 잘못 들어온다 | **즉시 제외한다** — 이 기능의 입력이 아니다(위 범위) |

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | 재수집 후보 1건(기업 1곳 + 유입 사유)을 **1건씩** |
| 출력 | 재수집 대상 1건당 재조사 범위 1행 |
| 도구 권한 | **입력 파일 읽기 + 결과 파일 쓰기까지만.** 웹 접근·메일 발송 권한 없음 — 재조사 자체는 G1·G4가 한다 |
| 독립 컨텍스트 | **재수집 후보 1건 = 판단 1단위** |

## 출력 형식
**파일: 재수집 대상 1건당 `재수집대상/{기업식별자}-{판정일}.md` 1개.**

- 기업 식별자 · 판정일 · **유입 소스**(G3 보류 / G4 미확보 / G8 조사 오류 / 외부 신호)
- **재조사 범위** — 전체 / 특정 항목(G1 코드 목록) / 연락처만
- 재수집 사유

## 성공 기준
산출물 1건(파일 1개)마다 확인한다.
- [ ] 유입 소스가 4종 중 하나로 명시됨
- [ ] 재조사 범위가 3종 중 하나이고, "특정 항목"이면 **G1 관찰 항목 코드로만** 표시됨(코드 아닌 임의 서술 0건)
- [ ] [발송 금지] 상태 건이 재수집 대상에 없음 (0건)
- [ ] 재수집 사유가 있음 (사유 없는 대상 0건)
- [ ] 판정일이 있음

## 확인 후 채울 것
- **"특정 항목만 재조사"가 실제로 성립하는가** ← `40` **V1** 결과 — G1의 관찰층/규칙층 층 배치가 이 결과로 확정된다(`31` 6절 #4)
- **G4 미확보 상태가 며칠·몇 회 지속되면 전체·항목 재조사로 승격할지** ← 실제 미확보 지속 사례를 보고 정한다
- **재수집 확인 주기**(외부 신호를 얼마나 자주 확인할지) ← 운영 단계(Build Order ⑤ Hook)에서 정한다. **구 수치(60일·90일)는 재사용하지 않는다**
