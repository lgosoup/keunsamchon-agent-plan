# spec.md – 사람 접촉 위임 브리프 (G9)

## 목표
연락처를 못 찾은 기업(경로 1)과 재시도 가치가 높은 기업(경로 2)을 모아, **사람이 시간을 크게 들이지 않고 판단할 수 있는 브리프 1건**으로 만들어 사용자에게 넘긴다. 사람이 직접 찾아낸 연락처는 G4로 되돌려 흐름에 합류시킨다.

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자
사용 목적: 원문의 **"사람이 다른 주변 연락 돌려서 찾아내는 방식"**이 이 기능이다. 공개 정보만으로는 실제 의사결정권자 연락처 확보가 어렵고 담당자 도달률을 기업 자신도 **"굉장히 낮은 퍼센트"**로 본다(`90` 리스크 7) — 그래서 사람이 움직일 대상을 이 기능이 좁혀서 넘긴다.
**유입 경로는 둘이지만 출력 형태는 같다.** 경로 1(G4가 연락처를 못 찾음)과 경로 2(G8이 재시도 가치가 높다고 판단)는 사유가 다르지만, 사람이 받아 볼 화면은 하나다 — 나누면 같은 브리프를 두 곳에서 각자 만들게 된다.
**무제한으로 넘기지 않는다.** 적합도(G3)로 대상을 좁힌다 — 좁히지 않으면 위임 큐가 곧 방치된다(`31` 4-2절).

## 입력
**단위 — 기업 1곳씩 넣는다.**

- **[경로 1]** G4 [미확보] 상태 1건 + G3 적합도 + G1 관찰 근거
- **[경로 2]** G8 재시도 가치 **高** 1건 + 원인 가설 + G1 관찰 근거
- (별도 흐름) 사람이 이 브리프를 보고 찾아낸 연락처 — 이 기능이 받아 **G4로 되돌린다**

## 범위
포함: 두 경로를 같은 브리프 형식으로 통합 / 적합도 문턱 적용(미달이면 큐에 안 넣음) / 유입 사유 표시 / 사람이 찾은 연락처를 받아 G4 포맷으로 변환해 되돌리기
제외: 연락처를 직접 탐색하는 것(사람이 한다) / 원인 분석(G8) / 적합도 산정(G3) / 실제 접촉 행위(시스템 밖, 사람이 한다) / 메일 발송(G5, G9는 발송을 하지 않는다)

## 제약
- **적합도(G3)가 문턱 미달인 건은 큐에 넣지 않는다.** 제외로 처리하지 않고 **지금은 대상이 아닌 것**으로 두며, 나중 재평가는 G10의 일이다
- **자료를 나열하지 않는다.** "어떤 기업인지 / 우리 회사와 맞는 이유와 근거 / 유입 사유"만 압축해서 넣는다 — 성립 조건은 **"사용자가 시간을 크게 들이지 않고 그 기업을 알게 되는 것"**
- **사람이 찾아낸 연락처를 받으면 `기준/G4_연락처유효성기준.md` 1절 등급 판정을 그대로 적용한다.** 사람이 찾았다고 등급 판정을 건너뛰지 않는다
- **개인 연락처가 포함되면 별도로 표시만 하고 다른 칸에 복제하지 않는다** — G1·G7과 같은 개인정보 제약을 여기서도 지킨다. 법인 공개 창구가 원칙이므로, 개인 연락처만 있는 경우는 **G4 [확보]로 자동 승격하지 않고** "개인 연락처 — 별도 처리 필요"로 표시한다
- 미확인 값(적합도 문턱의 확정치)을 추정치로 채우지 않는다
- **기업 1곳 = 브리프 1건.** 여러 기업을 한 브리프에 묶지 않는다 — 판단 단위가 흐려진다

**실행 형태 — Workflow다.** 문턱 확인 → 브리프 작성의 순서로 돌고 **실패하면 멈춘다.** 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 적합도가 문턱 미달이다 | **큐에 넣지 않고 종료한다.** 스스로 문턱을 낮춰 넣지 않는다 |
| G1 근거가 부족하다(판정 불가 항목이 많다) | **있는 근거만으로 작성**하고 "근거 부족"이라고 표시한다. 없는 근거를 추측으로 채우지 않는다 |
| 사람이 넣은 연락처가 개인 연락처뿐이다 | **G4 [확보]로 승격하지 않고** "개인 연락처 — 별도 처리 필요"로 표시해 사람에게 되돌린다 |

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | 기업 1곳분(경로 1 또는 경로 2)을 **1건씩** |
| 출력 | 기업 1곳당 브리프 1건. (있으면) 연락처 합류 레코드 1건 |
| 도구 권한 | **입력 파일 읽기 + 결과 파일 쓰기까지만.** 메일 발송·외부 접촉 도구에 접근하지 않는다 — 접촉은 사람이 한다 |
| 독립 컨텍스트 | **기업 1곳 = 컨텍스트 1단위.** 앞 기업의 브리프 내용이 다음 기업 브리프에 섞이지 않는다 |

## 출력 형식
**파일 1 — 기업 1곳당 `위임브리프/{기업식별자}.md` 1개.**

- 기업 식별자 · 작성일 · **유입 경로**(1: 연락처 미확보 / 2: 재시도 대상)
- **어떤 기업인지** — G1 관찰 근거 요약(업종·규모·한국 진출 신호)
- **왜 우리와 맞는지** — G3 적합도 + 그 근거
- **유입 사유** — 경로 1이면 G4가 어디까지 찾아봤는지, 경로 2면 G8 원인 가설과 재시도 가치 근거

**파일 2 — 사람이 연락처를 찾아냈을 때만, `contacts/{기업식별자}.md`에 추가.** G4 출력 형식 그대로(상태 [확보], 등급 판정 포함) + **"사람이 확보"**라고 출처 표시.

## 성공 기준
브리프 1건(파일 1개)마다 확인한다.
- [ ] 유입 경로가 명시됨(1 또는 2)
- [ ] "어떤 기업인지"와 "왜 맞는지"가 G1·G3 근거와 함께 있음 (근거 없는 서술 0건)
- [ ] 적합도 문턱 미달 건이 큐에 없음 (0건)
- [ ] 자료 나열이 아니라 판단 가능한 요약 형태임(원본 파일을 그대로 붙여넣은 건 0건)
- [ ] 작성일이 있음

연락처 합류 레코드가 있으면:
- [ ] `기준/G4` 유효 등급 판정을 거쳤음(등급 없는 합류 0건)
- [ ] 개인 연락처뿐인 건이 [확보]로 자동 승격되지 않음(0건)
- [ ] "사람이 확보"로 출처가 표시됨

## 확인 후 채울 것
- **적합도 문턱의 확정값** ← `12` **Q3** — `기준/G3`·`기준/G8`과 같은 대기 항목을 공유한다
- **큐 방치 판단 시점**(브리프가 며칠 이상 처리 안 되면 다시 알릴지) ← 실제 운영에서 처리 소요 시간을 보고 정한다
