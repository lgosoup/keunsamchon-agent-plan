# spec.md – 적합도 평가 (G3)

## 목표
G1이 후보로 통과시킨 기업(타겟 조건 4종 충족)마다, **자원을 쓸 가치**를 하나의 척도로 매겨 **순위**를 내고, 그 순위의 **근거**를 함께 낸다. 필터가 아니라 **정렬**이다 — 통과분을 다시 떨어뜨리지 않는다.

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자, 그리고 이 순위를 쓰는 뒤 작업(연락처 확보 순서·발송 순서·사람 위임·재수집 판단)
사용 목적: 기업이 이미 겪은 병목은 **수량이 아니라 순위와 근거**다 — Qoo10·라쿠텐에서 수백 개를 뽑아 봤지만 검증하지 못했다. **"후보 풀은 넓게 두고, 접촉 순서를 적합도로 정한다"**가 이 기능의 존재 이유다.
**넷이 이 순위를 쓴다** — G4(어느 순서로 연락처를 찾을지), G5(어느 순서로 발송할지), G9(사람을 움직일 만큼 가치가 있는지), G10(다시 열 가치가 있는지). **하나의 척도 + 하나의 근거를 내고, 소비처마다 자기 기준선을 적용한다** — 척도 자체를 넷으로 쪼개지 않는다. 근거는 `../docs/33_설계근거.md` **D9**.
판정 기준 정본: **`../기준/G3_적합도기준.md`** — 채점 축, 각 축의 방향(가점/감점), 미확인 값이 여기 있다. **이 Spec과 함께 반드시 읽는다.**

## 입력
**단위 — 기업 1곳씩 넣는다.** 순위는 전체를 한 번에 재계산해야 의미가 있으므로, 채점 자체는 1곳씩 하되 **정렬은 후보 전체를 모아서 한다**(범위 참조).

- G1 관찰층 값 전체(값 + 근거) — **규칙층의 통과 판정(포함)까지만.** 제외·판정 불가 건은 이 기능에 들어오지 않는다
- **G2 세그먼트는 입력으로 받지 않는다.** 이유는 아래 범위·제약.

## 범위
포함: 기업 1곳의 관찰값으로 축별 점수 계산 / 축 점수를 합쳐 하나의 순위값 산출 / 순위 근거(어느 축이 얼마나 기여했는지) 기록 / 후보 전체를 모아 순위 정렬 / 동점 처리
제외: **새로운 관찰**(G1의 일) / **후보를 탈락시키는 것**(필터는 G1에서 이미 끝났다 — 이 기능은 순위만 매긴다) / 세그먼트 배정(G2) / 연락처 탐색·발송 가능 판정(G4) / 메일 제작·발송(G5) / **세그먼트 축이나 척도 자체를 스스로 조정하는 것**(G11의 일 — 이 기능은 조정된 척도를 받아 쓸 뿐 스스로 고치지 않는다)

## 제약
- **필터링하지 않는다.** 통과분을 이 기능에서 다시 떨어뜨리지 않는다 — 떨어뜨릴 근거가 생기면 그건 G1 조건이나 G4 발송 가능 판정으로 가야 할 것이지 순위 문제가 아니다
- 값과 근거를 함께 적는다. 근거는 **"어느 관찰 항목이 몇 점으로 채점됐는가"**다
- **새로 관찰하지 않는다.** 정보가 부족한 축은 그 축만 0점(또는 "채점 불가")으로 두고 전체를 막지 않는다 — 웹을 다시 뒤지는 것은 G1의 일이다
- **하나의 척도만 낸다.** G4용 점수, G5용 점수를 따로 내지 않는다. 소비처가 서로 다른 기준선(상위 몇 %·상위 몇 곳)을 적용하는 것은 이 기능의 범위 밖이다(`31` 6절 #3 해소)
- **스스로 가중치를 바꾸지 않는다.** 축의 가중치·방향이 흔들리면(예: 회신 데이터가 축적돼 조정이 필요하면) 그건 G11이 조정 제안을 내고 사람이 승인한 뒤에만 바뀐다
- 웹 접근·메일 발송 도구에 접근하지 않는다
- 미확인 값(축 가중치 확정값, 배제 임계값)을 추정치로 채우지 않는다
- **기업 1곳 = 채점 1단위.** 앞 기업의 채점이 다음 기업 채점에 남지 않게 한다. 단 **정렬은 별도 단계**로, 채점이 끝난 후보 전체를 모아 한 번에 수행한다

**실행 형태 — Workflow다.** 채점(기업 단위) → 수집(전체 모으기) → 정렬(전체 단위) 순서로 돌고 **실패하면 멈춘다.** 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 채점에 쓸 관찰값이 비어 있다(G1 판정 불가 이력) | **그 축만 비우고 전체를 막지 않는다**(처리 표기는 `../기준/G3_적합도기준.md` 3절) |
| 축 가중치가 미확정이다 | **잠정 가중치**(기준 카드 명시)로 채점하고 산출물에 "잠정"이라고 표시한다. 스스로 확정치를 만들어내지 않는다 |
| 동점이 다수 발생한다 | **임의 순서로 정하지 않고 사람에게 넘긴다**(처리 표기는 `../기준/G3_적합도기준.md` 2절) |

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | 채점 단계 = 기업 1곳분(G1 통과분)을 **1건씩**. 정렬 단계 = 채점된 후보 **전체를 한 벌** |
| 출력 | 채점 단계 = 기업 1곳당 축별 점수 + 합산값 1행. 정렬 단계 = 전체 순위표 1개 |
| 도구 권한 | **입력 파일 읽기 + 결과 파일 쓰기까지만.** 웹 접근·메일 발송 권한 없음 |
| 독립 컨텍스트 | **채점은 기업 1곳 = 컨텍스트 1단위.** 정렬은 전체 채점 결과를 한 컨텍스트에 모아야 성립한다(정렬 자체가 상대 비교이므로) |

## 출력 형식
**파일 1 — 채점: 기업 1곳당 `scores/{기업식별자}.md` 1개.** G1의 `candidates/{기업식별자}.md`와 짝을 이룬다.

- 기업 식별자 · 채점일 · 채점 주체
- 축별 점수표 — 축 이름 · 관찰값(G1 참조) · 점수 · **점수를 준 이유**(어느 관찰값이 어느 방향으로 작용했는지)
- 합산 점수
- 채점 불가 축이 있으면 사유

**파일 2 — 정렬: 후보 전체당 `순위표-{작성일}.md` 1개.**

- 기업 식별자 · 합산 점수 · 순위 · 동점 그룹 여부
- 사용한 채점 기준의 버전(가중치 확정판인지 잠정판인지)
- 정렬 대상 건수 · 채점 불가로 빠진 건수

## 성공 기준
채점 산출물 1건(파일 1개)마다 확인한다.
- [ ] 모든 축에 값과 점수 이유가 함께 있음 (이유 없는 점수 0건)
- [ ] 채점 불가 축이 사유와 함께 표시됨 (사유 없는 채점 불가 0건)
- [ ] 합산 점수가 축별 점수만으로 다시 계산됨 (재계산 시 다른 값 0건)
- [ ] G1 통과분이 아닌 기업(제외·판정 불가)이 채점 대상에 없음 (0건)
- [ ] 채점일·채점 주체가 있음

정렬 산출물(파일 1개)마다 확인한다.
- [ ] 순위표의 모든 기업이 채점 파일 1개씩과 연결됨 (짝 없는 행 0건)
- [ ] 동점이 임의 순서로 갈라지지 않고 동점 그룹으로 표시됨
- [ ] 사용한 가중치가 확정판인지 잠정판인지 표시됨

**표본 검사 (매 건이 아니라 절차를 점검할 때)**
- [ ] 같은 기업을 두 번 채점해 합산 점수가 같음 (불일치 0건)

## 확인 후 채울 것
- **축 가중치 확정값** ← `12` **Q3**(6개월 뒤 성공 기준 숫자). 리드 다수가 목표면 넓고 얕은 가중치, 계약 1건이 목표면 좁고 깊은 가중치가 된다
- **배제·감점 임계값**(수입·시장 규모가 어느 선 이하면 감점인지) ← `12` **Q5**(받고 싶지 않은 고객 유형)
- **이미지 전문성을 가점으로 쓸 때의 방향** ← `12` **N2**(지불 고객이 원래 촬영을 하던 곳인가) — 방향이 틀리면 가점이 감점이 된다
- **"제품·학습" 축의 실제 의미** ← `12` **N15**(출처 C 표현의 축어 확인) — 의미가 불명확해 지금은 축에 넣지 않는다
- **이 척도가 실제 회신과 상관관계가 있는가** ← 실제 회신 데이터, `31` **G11**이 이 검증을 담당한다. **우리가 세운 척도를 우리가 검증하는 것은 검증이 아니다**
