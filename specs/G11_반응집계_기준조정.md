# spec.md – 반응 집계·기준 조정 (G11)

## 목표
**(부가 — MVP 범위 밖. 발송·회신 데이터가 쌓여야 돈다. `../docs/31_기능구조.md` 8-1절)**

발송·상태·회신·원인 데이터를 세그먼트·조건 조합별로 집계해 **무엇이 통했는지**를 보여주고, G2 세그먼트 축·G3 적합도 척도를 조정할 **제안**(근거 포함)을 낸다. **제안이지 자동 적용이 아니다.** (G3이 아직 이연 상태면 조정 대상은 G2 축 하나뿐이다)

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자
사용 목적: 이게 없으면 **G2·G3의 기준이 한 번 정해지고 영원히 바뀌지 않는다.** 맞춤의 단위를 세그먼트로 골랐으므로(`../docs/33_설계근거.md` D6), 그 축이 맞았는지 확인하는 **유일한 경로가 그룹별 반응 집계**다. 기업이 말한 *"우리나라 시장 이외에 해외 시장에 대해서도 학습에 넣는 게 편해지면"*(`13S` F30)이 이 기능에 대응한다.
**출력은 "조정 제안"이지 자동 적용이 아니다.** 판별 기준이 사람 모르게 바뀌면 "왜 이 기업이 선택됐는가"를 설명할 수 없게 되고, 그건 이 과제가 요구하는 설명 가능성과 반자동 원칙을 동시에 깬다.

**이 Spec은 부분적으로만 지금 쓸 수 있다.** 구조(입력·출력·집계 방식)는 데이터 없이도 지금 확정하고, 실제 값(집계 결과·조정 제안 자체)만 데이터를 기다린다(아래 성공 기준 (a)/(b) 참조). 근거는 `../docs/33_설계근거.md` **D11**.

## 입력
**단위 — 집계 시점 1회당, 그 시점까지 쌓인 데이터 전체를 한 벌로 받는다.**

- G5 발송 기록 — 세그먼트 · 인용한 근거 · 제안 내용 · 발신 언어·번역 검증 결과
- G6 상태 — 회신 / 무응답 / 주소 오류 (정정 반영된 최종값)
- G7 회신 성격 — C1~C8 분류 (자동응답 C6은 이미 G6에서 무응답으로 정정됨)
- G8 원인 가설 — 무시 / 도달 실패 / 조사 오류
- G2 세그먼트 체계 (버전 포함)
- G3 적합도 (채점에 쓴 가중치 버전 포함)

## 범위
포함: 세그먼트 × 조건 조합별 반응률 집계(회신율/무응답율/주소오류율) / 표본 부족 조합 표시 / 조정 제안 생성(무엇을·왜·근거·크기) / 이전 제안의 기각 이력 참조
제외: **조정을 스스로 적용하는 것**(사람 승인 없이 G2·G3 파일을 고치지 않는다) / G6·G7·G8이 이미 낸 결론의 재해석 / 신규 발송·조사

## 제약
- **표본이 최소 기준에 못 미치는 조합은 집계에서 "표본 부족"으로 표시하고 조정 제안에 넣지 않는다.** 최소 기준 값은 미확인이므로(확인 후 채울 것) 지금은 **표본 부족 표시 자체**가 성공 기준이지 특정 숫자가 아니다
- **조정 제안은 반드시 "무엇을 · 왜(근거 데이터) · 어느 방향으로 얼마나"를 명시한다.** 근거 없는 제안은 내지 않는다
- **스스로 G2·G3의 파일을 고치지 않는다.** 조정 제안 목록만 내고, 사람이 승인한 뒤 별도 작업으로 G2·G3에 반영한다
- **G6·G7이 이미 정정한 값을 그대로 쓴다** — 자동응답을 회신으로 다시 세거나 하지 않는다(이중 집계 방지)
- **G7 레코드 중 식별자가 `-미확정`인 것은 기업 단위 조인에 넣지 않는다** — 발신 도메인 추정이라 G1 식별자와 일치를 보장할 수 없다(`../specs/G7_회신해석정리.md` 출력 형식). 이런 건은 "식별 불가" 건수로만 별도 집계한다
- 미확인 값을 추정치로 채우지 않는다
- **집계 1회 = 컨텍스트 1단위.** 전체 데이터를 한 번에 봐야 세그먼트 간 비교가 성립한다

**실행 형태 — Workflow다.** 데이터 수집 → 집계 → 조정 제안 생성의 순서로 돌고 **실패하면 멈춘다.** 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 조합의 표본이 최소 기준 미달이다 | **"표본 부족"으로 표시**하고 그 조합은 조정 제안에서 뺀다 |
| 같은 세그먼트인데 조건 조합별로 반응이 상충한다(양방향 신호) | **조정 제안을 내지 않고** "신호 상충 — 재검토 필요"로 사람에게 올린다. 스스로 한쪽으로 판단하지 않는다 |
| 이전 회차에 낸 제안이 기각됐는데 같은 조합이 다시 나온다 | **기각 이력을 표시하며 다시 제안한다.** 기각 이력 없이 새 제안처럼 반복하지 않는다 |

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | 집계 시점까지의 **전체 데이터를 한 벌** |
| 출력 | 집계표 1개 + 조정 제안 목록 1개 |
| 도구 권한 | **입력 파일 읽기 + 결과 파일 쓰기까지만.** 웹·셸·위임(`Agent`)은 도구 권한에서 실제로 닫는다. **G2·G3 파일을 고치지 않는 것은 도구 권한으로 막히지 않는다** — 집계 파일을 쓰려면 `Write`가 열려 있어야 하고 `disallowed-tools`는 경로 단위가 아니다. **쓰는 자리를 집계 출력 하나로 제한하는 지침**으로 지킨다(`g10-재수집판단`·`g12-질의응답`과 같은 방식). 조정은 사람이 승인한 뒤 별도 작업으로 반영한다 |
| 독립 컨텍스트 | **집계 1회 = 컨텍스트 1단위** |

## 출력 형식
**파일: 집계 1회당 `집계/{집계일}.md` 1개.**

1절 조합별 집계표
- 세그먼트 ID(버전 포함) · 조건 조합 · 발송 건수 · 회신율 · 무응답율 · 주소오류율 · **표본 부족 여부**

2절 조정 제안 목록
- 무엇을 조정하는가(세그먼트 축 / 적합도 가중치) · **왜**(근거 데이터 인용) · 어느 방향·크기로 · **이전 기각 이력**(있으면)

## 성공 기준

**(a) 지금 확정 — 데이터 없이도 판정 가능**
- [ ] 출력 형식(1절·2절)이 정의된 대로 존재함
- [ ] 표본 부족 조합이 조정 제안에 포함되지 않음 (0건)
- [ ] 조정 제안마다 근거 데이터 인용이 있음 (근거 없는 제안 0건)
- [ ] G2·G3 파일이 이 기능에 의해 직접 수정된 적이 없음 (0건 — **쓰는 자리를 집계 출력 하나로 제한하는 지침으로 지킨다.** 도구 권한으로는 못 막는다: 집계 파일을 쓰려면 `Write`가 열려 있어야 하고 `disallowed-tools`는 경로 단위가 아니다)
- [ ] 신호 상충 조합이 조정 제안이 아니라 "재검토 필요"로 표시됨

**(b) 대기 — 실제 데이터가 있어야 판정 가능**
- [ ] 조정 제안이 실제로 반응률을 개선했는가(제안 승인 후 다음 회차 집계로 확인)
- [ ] 최소 표본 기준이 실제 반응률 변동성과 맞는가

## 확인 후 채울 것
- **최소 표본 크기** ← 실제 발송·회신 데이터의 분포. 지금은 값 없이 "미달이면 표본 부족 표시"라는 구조만 확정한다
- **실제 발송·회신 데이터 자체** ← G5가 실제로 돌기 시작해야 존재한다. 이 Spec의 (b) 전부가 여기 걸린다
- **조정 승인 절차의 실제 화면 형태** ← `13` 7-2절 R2(반자동 실물 되묻기)와 같은 자리에서 정한다
