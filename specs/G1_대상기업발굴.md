# spec.md – 일본 대상 기업 발굴 (G1)

## 목표
일본 기업 1곳의 공개 페이지를 열어 **관찰 항목**(O1~O6·O8~O9 — **O7은 결번, 관찰하지 않는다**)을 기록하고, **타겟 조건 3종**(제품 있음 / 커머스 있음 / 업종이 패션·뷰티·푸드) 충족 여부를 판정해 **근거가 붙은 후보 목록 1행**을 만든다. 앞 단계로 주어진 소스에서 기업 명단을 수집하는 것까지 포함한다. **MVP는 이 기능(탐색) + G2(그룹화) + G5(발송)이 핵심이다** — 순위매기기(G3)는 부가 기능으로 이연됐고, 이연된 값(자본금·종업원수·한국 진출 신호)은 G1이 보지 않는다(`../docs/31_기능구조.md` 8-1절).

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자, 그리고 이 목록을 받아 쓰는 뒤 작업(세그먼트화 · 연락처 확보)
사용 목적: 제안 메일을 보낼 후보 기업을 **근거와 함께** 골라낸다. 파는 것은 *제품 사진만 있으면 AI로 광고용 모델 사진·영상을 만들어 주는 서비스*이므로, 제품과 커머스가 없는 기업은 제안이 성립하지 않는다.
산출물의 본체: **목록이 아니라 목록에 들어온 근거다.** 근거 칸이 비면 뒤 작업의 *"왜 귀사인가"*가 성립하지 않는다 — 근거는 `../docs/33_설계근거.md` D4.
판정 기준 정본: **`../기준/G1_기업판정기준.md`** — 무엇을 보고 O/X를 주는가, 조건 3종의 상세 정의, 외부 표준 근거가 여기 있다. **이 Spec과 함께 반드시 읽는다.**
판정해 보는 양식: `../기준/판정시트_G1.md`

## 입력
**단위 J (기업 판정) — 1건씩 넣는다**
- 기업명(원어) + 국가(일본) + 공개 페이지 URL 1개 이상 (홈페이지 / 상품 목록 / 회사 개요 / 입점몰 중 아는 것)
- URL이 홈페이지 하나뿐이어도 성립한다. 나머지 페이지는 그 안에서 찾는다.
- **여러 기업을 한 번에 넣지 않는다** (제약 참조)

**단위 L (명단 수집) — 소스 1개씩 넣는다**
- 소스 1개의 진입 URL + 수집 범위(카테고리·페이지 수) + 이미 수집된 명단(중복 제거용)
- **어느 소스를 쓸지는 이 작업이 고르지 않는다.** 밖에서 지정해 준다. 현재 후보는 일본 커머스 플랫폼(Qoo10·라쿠텐 등) / 업계 디렉토리·협회·전시회 참가기업 목록.

## 범위
포함: 주어진 소스에서 명단 수집·중복 제거(L) / 기업 1곳 공개 페이지 관찰(J) / 관찰 항목(O7 제외) 기록 / 타겟 조건 3종 판정 / 제외 판정과 사유 / 판정 불가 판정과 사유 / 수집일·수집 주체 기록
제외: 국가 선정(일본으로 확정됨) / 어느 소스를 쓸지의 선택 / 비슷한 기업끼리 묶기(세그먼트화) / **적합도 점수·순위(G3, 부가 기능으로 이연)** / 연락처 탐색과 그 주소로 보낼 수 있는지의 판정 / 메일 제작·발송 / 재수집 주기 결정

## 제약
- 공개 정보만 쓴다 — 로그인·회원가입 화면, 유료 DB, 추측으로 채운 값 금지
- 값과 근거를 함께 적는다. 근거는 **본 페이지 URL + 그 페이지에서 무엇을 봤는지**
- 관찰과 판정을 다른 칸에 쓴다 — 관찰층은 "무엇을 봤다", 규칙층은 "그러므로 무엇이다"
- **"봤는데 아니다"(X)와 "못 봤다"(?)를 같은 칸에 넣지 않는다** — X는 결론, ?는 다시 볼 대상
- 일본어 원어 표기를 번역으로 덮어쓰지 않는다
- 개인을 수집하지 않는다 — 개인 이름·개인 SNS 계정·개인 직통 연락처 금지. 법인 공개 창구만
- 메일 발송·외부 전송 도구에 접근하지 않는다
- 목록 건수 상한은 `../docs/50_실사용_도입설계.md` 1절이 유일한 출처다. 값이 없으면 무제한으로 처리한다 — 이 Spec은 상한을 스스로 만들지 않는다
- **기업 1곳 = 작업 1단위.** 앞 기업을 보며 관찰한 내용이 다음 기업 판정에 남지 않게 한다
- **결과는 목록 파일 끝에 추가만 하고, 기존 목록 내용을 컨텍스트에 넣지 않는다.** 중복 확인은 식별자 조회로만 한다 — 안 지키면 앞서 적재된 다른 기업의 판정이 지금 판정에 새어 「기업 1곳 = 작업 1단위」가 실제로는 깨진다
- **G1은 순차 실행한다.** 목록이 단일 파일이라 병렬로 append하면 쓰기 충돌이 난다. 병렬 수집이 필요하면 회차 파일로 나눠 수집한 뒤 병합한다

**실행 형태 — Workflow다.** 정해진 순서로 돌고 **실패하면 멈춘다.** 스스로 다른 경로를 찾지 않고, 규칙이 없는 케이스를 O나 X로 밀어 넣지 않는다(밀어 넣으면 판정 규칙을 실행체가 발명한 것이 되고 그 발명이 어디에도 남지 않는다). 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 항목을 관찰할 수 없다 | **그 기업을 종료한다. 제외로 넘기지 않는다**(표기·사유 목록은 `../기준/G1_기업판정기준.md` 3절) |
| 도중에 끊긴다 | **이미 채운 항목은 유지**하고, 못 채운 항목만 `?`로 남긴다 |
| 소스가 차단된다 (단위 L) | **어디까지 수집했는지 범위를 기록하고 멈춘다.** 다른 소스로 갈아타지 않는다 — 소스 선택은 밖에서 지정한다 |

**실행체 경계 4개** — 넷 중 하나라도 안 지켜진 실행체로는 `../docs/40_검증계획.md` **V1-b를 돌리지 않는다.**

| 경계 | 값 |
|---|---|
| 입력 | 기업 1곳분(J) 또는 소스 1개분(L)을 **1건씩** |
| 출력 | 아래 출력 형식 그대로 — **기업 1곳 = 단일 목록 파일 안의 섹션 1개(append)** |
| 도구 권한 | **공개 페이지 읽기 + 결과 파일 쓰기까지만.** 위 제약 1·7번을 물리적으로 만든 것 |
| 독립 컨텍스트 | **기업 1곳 = 컨텍스트 1단위.** 여러 기업을 한 맥락에 넣으면 판정이 갈린 원인이 기준 문장인지 맥락 오염인지 구분되지 않는다. **목록이 단일 파일이어도 마찬가지다** — 기존 목록 내용을 읽어 컨텍스트에 넣지 않고, 새 섹션을 끝에 추가만 한다 |

## 출력 형식
**파일: `candidates/후보목록.md` 단일 파일.** 기업 1곳 = 그 안의 섹션 1개(`## {기업식별자}`, 식별자는 홈페이지 도메인 — 예: `example-co-jp`), **파일 끝에 추가(append)한다.** 기존 섹션은 읽지도 고치지도 않는다 — 중복 여부는 식별자로만 조회한다. **합본을 별도로 만들지 않는다** — 단일 파일 자체가 곧 합본이다. **G2가 쓰는 축약표는 이것과 다르며 G2가 스스로 만든다**(`../specs/G2_세그먼트화.md` 입력 참조) — G1이 별도로 만들 필요는 없다.

**옛 형식(`candidates/{식별자}.md` 파일 1개씩)으로 만들어진 3건(INGNI·ROPÉ PICNIC·Honeys)은 구 기준(한국 진출 신호 게이트 존재 시점)의 판정이라 그대로 못 쓴다.** 새 기준·새 형식으로 재판정해 `후보목록.md`에 새로 넣는다 — 옛 파일은 지우지 않고 이력으로 남긴다(`../specs/README.md`).

관찰층 — 각 칸에 「값 + 근거」 또는 「? + 사유」
- **O1** 기업명(원어) · 영문명 · 홈페이지 URL
- **O2** 취급 품목 (원어 그대로) + 대표 품목 3개 이내
- **O3** 제품 사진 보유 — 있음 / 없음 / ?
- **O4** 커머스 보유 — 있음 / 없음 / ? + **본 것 표시**(구매·장바구니 버튼 / 가격 표시 / 결제·배송 안내 / 외부몰 입점 링크)
- **O5** 업종 — 패션 / 뷰티 / 푸드 / 기타
- **O6** 규모 신호 — 상품 개수 · 판매채널 수 (각각 값 또는 「기재 없음」). **점수화하지 않는다.** (자본금·종업원수·설립연도, 한국 진출 신호는 2026-08-03부터 G1이 보지 않는다 — 부가 기능 G3이 착수 시 별도 수집)
- **O8** 광고 메일 거부 표시 — 있음 / 없음 / ? + 있으면 **그 문구를 일본어 그대로** + 어느 주소의 앞·뒤인지
- **O9** 판정 불가 사유 — 해당 항목 + 사유
- 수집 메타 — 수집일 · 수집 주체(사람 이름 또는 실행체 ID) · 열어본 URL 전체 목록

규칙층 — **관찰층 값만으로 계산한다**
- 조건 3종 각각 O / X / ? (계산 규칙은 기준 카드)
- 후보 판정 — 포함(3종 모두 O) / 제외(하나라도 X) / 판정 불가(X 없고 ? 있음)
- 제외 사유 — 어느 조건이 X인지
- **발송 가능성 확인 필요** — O8을 그대로 옮긴다. **여기서 위법 여부를 판정하지 않는다.** 뒤 작업(연락처 확보)이 이 칸을 보고 판정한다
- 재수집 대상 여부 + 다시 볼 항목 — ?가 있으면 예

## 성공 기준
산출물 1건(목록 파일 안 섹션 1개)마다 확인한다.
- [ ] 목록 파일에 같은 식별자의 섹션이 2개 이상 없음 (중복 0건)
- [ ] 관찰 항목 모든 칸이 「값+근거」 또는 「?+사유」로 채워짐 (빈 칸 0건)
- [ ] 근거에 **URL과 무엇을 봤는지**가 모두 있음 (인상 서술만인 근거 0건)
- [ ] 관찰층 칸에 판정·결론 문장이 섞이지 않음 (0건)
- [ ] **규칙층을 지우고 관찰층 값만으로 다시 계산해 원래와 같음** (다른 행 0건)
- [ ] 판정 불가가 제외와 다른 칸에 사유와 함께 있음 (혼재 0건)
- [ ] 제외 건에 어느 조건이 X인지 적혀 있음 (사유 없는 제외 0건)
- [ ] 수집일과 수집 주체가 있음
- [ ] 일본어 원어 표기가 보존됨
- [ ] 개인 이름·개인 SNS·개인 직통 연락처가 기록되지 않음 (0건)
- [ ] O8에 문구가 있으면 일본어 원문과 위치가 함께 적혀 있음

**표본 검사 (매 건이 아니라 절차를 점검할 때)**
- [ ] 같은 기업을 두 번 돌려 규칙층 판정이 같음 (불일치 0건)

## 확인 후 채울 것
- 목록 건수 상한 ← `../docs/50_실사용_도입설계.md` 1절이 유일한 출처. 값이 오면 이 Spec은 고칠 것이 없다
- 관찰 항목이 사람 사이에 갈리는지 ← `../기준/판정시트_G1.md`로 **두 사람이 5~10곳 독립 판정**
- 관찰 항목 자체가 옳게 골라졌는지 ← **국내 고객사 업종·규모 분포** (미확인). 국내에서 통한 고객 유형에서 신호를 역산해 대조한다
