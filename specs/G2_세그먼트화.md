# spec.md – 세그먼트화 (G2)

## 목표
후보 기업 목록 1벌을 받아 **같은 문안을 써도 될 기업끼리 무리로 묶고**, 무리마다 대표 1곳을 정하고, **무엇을 보고 그렇게 묶었는지**를 함께 낸다. 어느 무리에도 안 들어가는 기업은 **[미분류]**로 사유와 함께 남긴다. 산출물은 **세그먼트 정의 1벌**(정의 · 배정 · 미분류)이다.

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자, 그리고 이 무리를 받아 문안을 만드는 뒤 작업(제안 메일 제작)
사용 목적: **맞춤 메일의 단위를 정한다.** 과제 원문이 요구한 *"고객 특성에 맞춘 제안 메일"*의 절반이 여기서 결정된다 — 나머지 절반은 무리별 문안 작성이다.
**맞춤의 단위는 개별 기업이 아니라 무리다.** 그렇다고 개별 특성이 사라지지는 않는다 — 뒤 작업이 **무리 문안 + 그 기업의 관찰 근거**를 함께 받는다. 이 단위를 고른 근거는 `../docs/33_설계근거.md` D6.
**분류축은 아직 확정이 아니다.** 품목인지 규모인지 담당자 직급인지는 기업에 물어야 안다. 그래서 이 Spec은 축의 내용을 담지 않고 **축이 갖춰야 할 조건과 출력 형식**만 정한다.
판정 기준 정본: **`../기준/G2_세그먼트기준.md`** — 분류축 3안과 되물을 방법, 무리 배정 판정 문장, 대표 선정 규칙, 미분류 4종이 여기 있다. **이 Spec과 함께 반드시 읽는다.**

## 입력
**목록 1벌씩 넣는다.** 앞 작업(대상 기업 발굴)이 기업 1곳씩 처리하는 것과 반대다 — 묶는 일은 전체를 봐야 성립한다.

- **관찰 값 축약표** — 기업 식별자 + 축으로 쓰는 관찰 항목의 **값만**. **이 표는 G1이 별도로 내주는 산출물이 아니다.** G2가 0단계로 G1의 `candidates/{기업식별자}.md`(포함 판정분 전체)를 직접 읽어 축만 뽑아 스스로 만든다 — 제약의 "앞 작업의 개별 관찰 파일을 참조만 한다"가 이 읽기를 이미 허용한다. G1이 만드는 `candidates-{수집일}.md`(사람이 훑어보는 합본)와는 다른 것이다
- **근거 원문은 넣지 않는다.** 이유 둘: ① 수백 개 × 항목별 서술을 한 맥락에 넣으면 앞에서 정한 축이 뒤에서 밀려난다 ② 근거는 **문안을 만들 때** 필요하지 묶을 때 필요하지 않다. 근거까지 보고 묶으면 축에 없는 것으로 묶게 된다
- **단, `?`(판정 불가)와 불확실 표시는 축약표에 반드시 남긴다** — 값만 보면 「상품 40개」와 「상품 40개(카테고리 페이지만 세었음)」가 같아 보인다. 이런 건은 미분류 후보다
- 이전 회차의 **세그먼트 정의 표**(있으면). **이전 배정 결과는 넣지 않는다** — 앞 회차 배정이 이번 판단에 남는다

**축으로 쓸 수 있는 항목은 앞 작업이 관찰한 것뿐이다.** 목록과 못 쓰는 것의 이유는 기준 카드 0절.

## 범위
포함: 분류축 적용 / 무리 정의 / 각 기업 배정과 배정 근거 / 대표 1곳 선정과 선정 이유 / 미분류 판정과 사유 4종 / 세그먼트 ID·버전·작성일 부여 / 재조사가 필요한 건 표시
제외: 새로운 관찰(대상 기업 발굴의 일) / 적합도 점수·순위 / 연락처 탐색 / 문안 작성 / **분류축이 옳은지의 검증**(회신이 와야 판정된다) / 반응 집계

## 제약
- **분류축은 앞 작업이 관찰한 항목만으로 만든다** — 관찰하지 않은 것으로 묶으면 근거가 없다
- **새로 관찰하지 않는다.** 정보가 부족하면 미분류로 두고 무엇이 부족한지 적는다. 웹을 다시 뒤지는 것은 앞 작업의 일이다
- 값과 근거를 함께 적는다. 배정 근거는 **"그 기업의 어느 관찰 값이 이 무리의 규정에 맞는가"**다. 무리 이름을 다시 쓰는 것이 아니다
- **앞 작업의 개별 관찰 파일을 고치거나 옮겨 적지 않는다.** 참조만 한다 — 같은 값이 두 곳에 있으면 하나만 고쳐지고 나머지가 썩는다
- **무리 하나에 2곳 이상.** 1곳짜리는 무리가 아니라 개별 맞춤이므로 미분류로 보낸다
- **세그먼트 정의에 ID·버전·작성일을 붙인다.** 축을 바꾸면 새 버전이고 **이전 버전 파일을 지우지 않는다.** 축이 그대로인 채 G10 재수집으로 관찰값만 채워져 배정이 바뀌면 **새 버전을 만들지 않고 같은 버전의 2절 배정을 갱신**한다(판정일을 새로 남긴다) — 축이 바뀐 게 아니라 데이터가 채워진 것이므로 버전을 올릴 이유가 없다
- **대표를 적합도로 고르지 않는다** — 적합도 평가가 무리 소속을 입력으로 받을 수 있어 서로를 기다리게 된다
- 미확인 값(월 제작 캐파, 무리 크기 상한)을 추정치로 채우지 않는다

**실행 형태 — Workflow다.** 축 적용 → 배정 → 대표 선정 → 미분류 판정의 순서로 돌고 **실패하면 멈춘다.** 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 미분류가 과다하다 | **사람에게 넘긴다.** 스스로 다른 축으로 다시 묶지 않는다 — **축은 사람이 정한다** |
| 축으로 쓸 관찰 값이 비어 있다 | **U-정보없음**으로 두고 재조사 대상에 넣는다. 다른 항목으로 대체해 묶지 않는다 |
| 무리가 1곳뿐이다 | **U-단독**으로 미분류에 보낸다. 규정을 넓혀 억지로 2곳을 만들지 않는다 |

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | **목록 1벌씩** (관찰 값 축약표). 앞 작업이 1곳씩 처리하는 것과 반대다 — 묶는 일은 전체를 봐야 성립한다 |
| 출력 | 아래 출력 형식 그대로 — 세그먼트 정의 1벌 = 파일 1개 |
| 도구 권한 | **입력 파일 읽기 + 결과 파일 쓰기까지만. 웹 접근·메일 발송 권한이 없다** — *"새로 관찰하지 않는다"*를 문장이 아니라 물리적으로 강제한 것이며, 이것이 앞 작업과의 권한 차이다 |
| 독립 컨텍스트 | **목록 1벌 = 컨텍스트 1단위.** 이전 회차의 **배정 결과**를 넣지 않는다(앞 회차 배정이 이번 판단에 남는다). 정의 표는 넣어도 된다 |

## 출력 형식
**파일: 세그먼트 정의 1벌당 `segments/SEG-{축코드}-v{버전}.md` 1개.** 축을 바꾸면 새 파일이고 이전 파일은 남긴다.

머리
- 세그먼트 세트 ID · **버전** · 작성일 · 작성 주체
- 분류축 (그때 쓴 축) · **축의 출처**(관찰 항목 코드) — 제약 1번의 확인 지점

1절 무리 정의
- 세그 ID · 무리 이름 · **이 무리의 규정(축의 값)** · 소속 수 · 대표 기업 · **대표로 고른 이유**
- 무리 이름은 규정을 대신하지 못한다. 「소규모 여성복」만 있고 축의 값이 없으면 불합격

2절 배정
- 기업 식별자 · 세그 ID · **배정 근거** · 판정 주체 · 판정일
- 배정 근거 문장의 형식(O/X 예)은 `../기준/G2_세그먼트기준.md` 2절 그대로 따른다

3절 미분류 — **사유 코드 4종. 코드가 없으면 무엇 때문에 남았는지 집계할 수 없다.** 각 코드의 조건·판단 근거는 `../기준/G2_세그먼트기준.md` 4절이 정본이다.
- **U-단독** → 미분류로 보낸다(다음 회차 재시도)
- **U-경계** → 미분류로 보낸다(억지로 한쪽에 넣지 않는다)
- **U-정보없음** → 미분류로 보내고 **G10 재수집 후보**(`../specs/G10_재수집판단.md` 입력)에 넣는다
- **U-이질** → 미분류로 보내고 사람 판단을 기다린다

4절 이번 회차 관찰값
- 가장 큰 무리의 크기 · 미분류 건수(코드별) · 재조사 요청 건수. **판정하지 않고 수치만 남긴다** — 상한이 아직 없다

## 성공 기준
산출물 1벌(파일 1개)마다 확인한다.
- [ ] 모든 기업이 어느 무리에 속하거나 미분류 사유를 가짐 (둘 다 없는 건 0건)
- [ ] 각 무리에 **축의 값**과 그렇게 묶은 근거가 있음 (값 없는 서술만 0건)
- [ ] **축에 쓰인 항목이 전부 앞 작업의 관찰 항목 목록 안에 있음** (목록 밖 항목 0건)
- [ ] 무리마다 대표 1곳과 **왜 그곳인지**가 있음 (대표 없는 무리 0건)
- [ ] **1곳짜리 무리 0건** (해당 건은 U-단독으로 미분류에)
- [ ] 세그먼트 세트에 ID·버전·작성일이 모두 있음
- [ ] 미분류가 배정과 다른 절에 **사유 코드와 함께** 있음 (혼재 0건)
- [ ] 앞 작업의 관찰 파일을 고치지 않음 — 참조 형태임 (복사해 옮긴 값 0건)
- [ ] 배정마다 판정 주체와 판정일이 있음 (빈 칸 0건)

**표본 검사 (매 건이 아니라 절차를 점검할 때)**
- [ ] 두 사람이 같은 기업을 같은 무리에 넣음 (불일치 0건) — 갈리면 **무리 규정 문장이 모호한 것**이므로 기준 카드 2절을 고친다

## 확인 후 채울 것
- **분류축** ← **기업 확인 필요.** 추상적으로 묻지 않는다 — **축 3안 + 각 안으로 만든 메일 초안**을 놓고 고르게 한다 (기준 카드 1절에 3안이 준비돼 있다)
- 규모로 나눌 때의 경계값(소/중/대) ← **실제 목록의 분포.** 분포를 보기 전에 선을 긋지 않는다
- 한 무리의 크기 상한 ← **실제 회신.** 같은 무리에서 반응이 갈리기 시작하는 크기가 그 값이다
- 미분류 과다의 기준(멈추고 사람을 부를 시점) ← 몇 번 돌려 보고 정한다
- 무리 개수의 상한 ← **월 제작 캐파** (미확인, 기업 확인 필요). 무리 1개 = 집중 문안 1건이므로 무리 수가 곧 작업 횟수다
- **축이 실무에 맞는지** ← 위 기업 답 + **실제 회신.** 같은 무리에 같은 문안을 보내 **무리 안에서 반응이 갈리는지** 본다. 갈린 사례가 1건이라도 나오면 그 무리의 규정을 다시 본다. **우리가 고른 축을 우리가 검증하는 것은 검증이 아니다** (절차는 `../docs/40_검증계획.md` V7)
