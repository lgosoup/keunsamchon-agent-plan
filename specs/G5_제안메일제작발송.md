# spec.md – 제안 메일 제작·발송 (G5)

## 목표
세그먼트 1개당 **대표 기업 1곳**에 집중해 문안을 만들고, 그 문안을 **세그먼트 전체로 확장 생성**한 뒤, 일본어로 발신하고 번역을 검증하고, **사람이 승인한 건만** 발송한다. 산출물은 **발송 기록**(어느 기업에 언제 어떤 문안으로 보냈는지, 그리고 뒤 기능이 요구하는 항목까지 포함한)이다.

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자
사용 목적: 브리프 요구 ②(고객 특성에 맞춘)의 나머지 절반(G2가 앞 절반)과 요구 ③(반자동)의 **구조적 실현 지점**이 여기다. **완전자동 발송 경로는 두지 않는다** — 원문이 "자동으로 보낼거지"라 했지만 기업도 *"100% 자동화는 어렵다, 사람의 터치는 없을 수 없다"*고 말했고(`13S` K6), 브리프 원문이 요구한 것 자체가 "반자동"이다.
**노력을 그룹 수에 비례시킨다**는 것이 이 기능의 설계 의도다 — 그룹 대표 1곳에 집중해 만든 문안을 그룹 전체로 확장하되, **개별 기업의 관찰 근거는 확장 시에도 각자 다르게 인용**해 개별 특성이 사라지지 않게 한다.
판정 기준 정본: **번역 검증은 `../기준/G7_회신판정기준.md` 3절을 그대로 쓴다** — 그 절 자체가 *"G7 전용이 아니다, G5의 발신 번역도 이 기준을 그대로 쓴다"*고 못 박아 두었다. 이 Spec은 새 번역 기준을 만들지 않는다.

## 입력
**단위가 둘이다.**

**단위 M (대표 문안 제작) — 세그먼트 1개당**
- 세그먼트 정의 1건(G2) — 무리 규정 · 대표 기업 식별자
- 대표 기업의 G1 관찰 근거
- 회사 자산 — AI-Studio 소개 자료. **사례·가격 자료는 아래 제약에서 제외**

**단위 E (확장 생성) — 세그먼트 1개 + 그 대표 문안 1건당**
- 대표 문안 M의 산출물
- 같은 세그먼트 소속 기업 전체의 식별자 + **각 기업의 G1 관찰 근거**(인용을 기업마다 다르게 하기 위해 필요)
- G4 [확보] 상태의 연락처(직통/일반 등급 포함)
- **일일 발송 상한** — `../docs/50_실사용_도입설계.md` **1-1절**이 유일한 출처(제작 캐파·승인 시간 같은 다른 상한과 달리 **이것만 진짜 상한이다** — 도메인 평판 보호 목적). 이번 회차에 포함할 몫은 세그먼트별로 고르게(라운드로빈) 후보 목록에서 가져온다(아래 실패표)
- **`발송금지.md`**(G7이 쌓는 수신 거부 목록) — 발송 직전 최종 확인용

## 범위
포함: 대표 1곳 집중 문안 제작 / 그룹 전체로 확장 생성(근거 인용은 기업마다 개별) / 일본어 발신 문안 작성 + 번역 검증(`기준/G7` 3절 재사용) / 법정 표시 의무 4종 삽입 / 발송 상한 확인 / **발송 전 확인 지점 제공**(사람 승인) / 승인된 건만 발송 / 발송 기록 작성
제외: 세그먼트화(G2) / 적합도 평가(G3) / 연락처 탐색(G4) / 번역 검증 기준 자체를 새로 정하는 것(`기준/G7` 3절이 정본) / 발송 결과 판정(G6, 발송 이후는 이 기능의 범위 밖)

## 제약
- **그룹 대표 1곳에 먼저 집중한다.** 그룹 전체를 동시에 개별 작성하지 않는다 — 그러면 그룹화(G2)의 목적(노력을 그룹 수에 비례시키기)이 사라진다
- **확장할 때 근거 인용은 기업마다 바꾼다.** 문구 틀은 같아도 "귀사의 공개 정보에서 이런 점을 확인했다"에 들어가는 내용은 그 기업의 G1 관찰 근거여야 한다. **템플릿 문구만 복사해 넣지 않는다**
- **법정 표시 의무 4종을 모든 메일에 고정 포함한다** (일본 특정전자메일법):

  | 표시할 것 | 위치 |
  |---|---|
  | 송신자의 성명 또는 명칭 | 본문 안 필수 |
  | 수신 거부가 가능하다는 사실 | 본문 안 필수 |
  | 수신 거부를 접수할 메일 주소 또는 URL | 본문 안 |
  | 송신자의 주소, 그리고 문의·불만 접수처 | 링크된 페이지도 허용 |

- **발신 번역은 발신 주체가 스스로 검증하지 않는다** — `기준/G7` 3절의 T/V 분리 원칙을 그대로 적용한다. 문안을 만든 실행과 번역을 검증하는 실행은 **다른 컨텍스트**여야 한다
- **번역·언어 처리 과정에 대한 메타 언급을 본문에 넣지 않는다** — 예: "일본어로 보내도 됩니다", "번역을 통해 전달드립니다" 같은, 우리 내부의 번역 처리를 상대에게 드러내는 문장. 상대는 처음부터 자연스러운 일본어 비즈니스 메일 하나를 받아야 한다 — 번역 과정이 문면에 드러나면 그 자체가 부자연스러운 정황이 된다
- **레퍼런스 사례와 가격 자료는 지금 쓰지 않는다** — 사례는 인용 허가가 `(미확인)`이고(`13S` U5), 가격 구조는 확인됐으나(2026-07-31, 비공개 보유) **회사 비공개 자료라 메일 문안에 인용하지 않는다**(`CLAUDE.md` 6절). 최소 수주 금액은 여전히 미확인(`../docs/50_실사용_도입설계.md` 3절 참조). 확인 전에는 **템플릿에서 물리적으로 제외**한다. 추측으로 채우지 않는다
- **일일 발송 상한은 `../docs/50_실사용_도입설계.md` 1-1절이 유일한 출처다.** 제작 캐파·승인 시간(같은 문서 1·1-2절)과 달리 **이 값은 무제한이 기본이 아니다** — 도메인 평판이 걸린 유일한 예외이므로, 그 절의 값(낮은 값에서 시작해 담당자가 직접 늘려가는 값)을 그대로 상한으로 쓴다. 넘는 만큼은 세그먼트별로 고르게(라운드로빈) 대기열에 남긴다(`90` 리스크 11·12)
- **발송 전 확인 지점을 반드시 거친다.** 승인 기록이 없는 건은 발송 도구를 호출하지 않는다(아래 도구 권한)
- 미확인 값(발송 상한 정확한 수치, 응대 준비 상태)을 추정치로 채우지 않는다
- **세그먼트 1개 = 대표 문안 제작의 컨텍스트 1단위.** 확장 생성 시에는 그룹 소속 기업의 개별 근거를 각자 참조하되 대표 문안의 틀은 공유한다

**실행 형태 — Workflow다, 단 발송 직전에 사람 승인 게이트를 강제로 둔다.** 문안 제작 → 확장 생성 → 번역·검증 → **[정지: 사람 승인 대기]** → 발송의 순서로 돌고, **승인 없이는 정지 지점을 넘지 않는다.** 이것이 브리프 요구 ③(반자동)의 구조적 실현이다. 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 번역 검증이 불일치한다 | **재번역 1회.** 두 번째도 안 맞으면 **그 건을 발송 대기열에서 빼고** 사람에게 원문·두 번역본·불일치 지점을 함께 올린다(`기준/G7` 3절과 동일 절차) |
| 일일 발송 상한(`50` 1-1절)을 넘는 대상이 있다 | **넘는 만큼은 이번 회차에서 보류한다.** 세그먼트별로 고르게(라운드로빈) 상한만큼만 이번 회차에 포함한다 — 한 세그먼트가 상한을 다 채우게 두지 않는다 |
| 승인이 거부되거나 응답이 없다 | **발송하지 않는다.** 거부 사유가 있으면 그 사유를 문안 개선 재료로 남기고, 응답이 없으면 대기 상태로 둔다 — 스스로 재승인 요청을 반복하거나 발송으로 넘어가지 않는다 |
| 승인된 건의 수신 주소가 `발송금지.md`에 있다 | **그 건만 발송 대상에서 뺀다.** 나머지 승인 건은 그대로 발송한다 |

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | 단위 M = 세그먼트 1개분, 단위 E = 세그먼트 1개 + 대표 문안 1건 + 소속 기업 전체분 |
| 출력 | 기업 1곳당 발송 기록 1행(아래 출력 형식) |
| 도구 권한 | **문안 생성·번역까지는 문서 읽기/쓰기만.** **메일 발송 도구는 접근 권한이 있으나, 사람 승인이 기록된 건에만 그 권한을 행사한다** — 승인 기록이 없는 건에는 발송 도구를 호출하지 않는다. 이 경계가 다른 기능(G1·G2·G7)과 다른 유일한 지점이다(그것들은 발송 권한 자체가 없다) |
| 독립 컨텍스트 | **세그먼트 1개 = 대표 문안 제작의 컨텍스트 1단위.** 번역과 검증은 **서로 다른 컨텍스트**(위 제약) |

## 출력 형식
**파일: 발송 1건당 `발송기록/{기업식별자}-{발송일시}.md` 1개.**

| 항목 | 누가 요구하는가 |
|---|---|
| 기업 식별자 · 발송일시 · 수신 주소 · 제목 · 본문 | G6·G7 (최소 요구) |
| **어느 세그먼트의 문안이었는가** | G11 — 세그먼트별 반응 차이를 보는 축 |
| **본문에서 G1 관찰층의 무엇을 근거로 인용했는가** | G11 — 어느 근거가 통했는지 |
| **무엇을 제안했는가** | G11 · G7(회신이 답인지 판정) |
| 발신 언어와 번역 검증 결과 | G7(회신이 어긋난 원인 구분) · G11 |
| **사람 승인 기록**(승인자·승인일시) | 이 Spec 자체 — 반자동 요구의 증빙 |

## 성공 기준
발송 1건마다 확인한다.

**무관용 — 하나라도 어기면 그 건을 발송하지 않는다**
- [ ] **사람 승인 기록이 있다** — 어기면 브리프 요구 ③(반자동)을 정면으로 위반한다
- [ ] 번역 검증 3층이 전부 일치 판정된 뒤 발송됐다 — 어기면 정중함이 무너지거나 제안의 단정·가능성이 뒤집힌 채 나갈 수 있다(`기준/G7` 3절 G5용 판정 문장과 동일 근거)
- [ ] 법정 표시 의무 4종이 본문(또는 링크)에 모두 있다 — 어기면 일본 특정전자메일법 위반
- [ ] 레퍼런스 사례·가격 자료가 인용되지 않았다(승인 전) — 어기면 무단 인용·미확정 가격 고지의 법적·신뢰 리스크
- [ ] 수신 주소가 `발송금지.md`에 없다 — 어기면 수신 거부 의사를 밝힌 곳에 재발송해 일본 특정전자메일법 위반

**서식 점검**
- [ ] 항목표 전 항목(세그먼트·인용 근거·제안 내용·발신 언어·번역 검증 결과)이 채워짐 (빈 칸 0건)
- [ ] 인용 근거가 기업마다 다름(템플릿 문구만 복사된 건 0건) — 같은 세그먼트 안에서 인용 문장이 완전히 동일한 건을 센다
- [ ] 일일 발송 상한(`50` 1-1절)을 넘긴 건이 없음 (초과 발송 0건)
- [ ] 대표 문안 제작 순서가 세그먼트 단위로 먼저이고, 확장이 그 뒤에 옴 (순서 위반 0건)
- [ ] 본문에 번역·언어 처리에 대한 메타 언급이 없음 (0건)

## 확인 후 채울 것
- **일일 발송 상한의 초기값·조정** ← `../docs/50_실사용_도입설계.md` **1-1절**이 유일한 출처(`12` Q15). 담당자가 직접 늘려가는 값이라 이 Spec은 고칠 것이 없다 — `50`을 참조하고 있으므로
- **레퍼런스 사례 사용 가능 여부** ← `12` **Q7**(레퍼런스 인용 허가). 답이 오면 사례를 템플릿에 넣을지 결정
- **가격 자료 포함 여부·형태** ← `13S` **U4**(가격 자료 미확보)
- **발송 전 확인 지점의 실제 화면 형태**(무엇을 보여주고 무엇을 누르면 승인인지) ← `13` 7-2절 **R2**(실물로 되묻기) — 승인 화면 목업 + 메일 초안 3종을 놓고 기업에 확인받는다
