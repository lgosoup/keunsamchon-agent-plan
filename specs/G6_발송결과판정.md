# spec.md – 발송 결과 판정 (G6)

## 목표
G5가 보낸 메일 1건마다, 메일 시스템이 돌려준 응답(바운스 코드 포함)과 경과 시간을 보고 **회신 / 무응답 / 주소 오류** 셋 중 하나로 상태를 판정한다. G7이 자동응답이라고 되돌리면 그 판정을 **정정**한다.

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자, 그리고 이 상태를 받는 뒤 작업(회신 해석 / 원인 분석 / 반응 집계)
사용 목적: **G5와 시간차가 있어 따로 다시 돌려야 한다.** 발송은 한 번에 끝나지만 결과는 시간을 두고 도착한다 — 발송과 한 단위로 묶으면 결과 판정만 재실행할 수 없다.
**기업이 직접 요구한 "안 읽은 건지 주소가 틀린 건지 구분"이 여기서 실현된다**(`13S` F24). 실현 수단은 픽셀 읽음 추적이 아니라 **바운스 코드 분류**다 — 픽셀은 차단·규제로 정확도가 낮지만, 바운스는 메일 시스템이 실제로 돌려주는 값이다.
판정 기준 정본: **`../기준/G6_판정기준.md`** — 바운스 코드를 3상태로 매핑하는 규칙, 무응답 판정에 필요한 대기, 판정 정정 절차가 여기 있다. **이 Spec과 함께 반드시 읽는다.**

## 입력
**단위 — 발송 기록 1건(기업 1곳)당.** 이 기능은 **1회성이 아니라 반복 조회**다 — 같은 발송 건을 시간을 두고 여러 번 다시 확인할 수 있다.

- G5 발송 기록 1건 — 기업 식별자·발송일시·수신 주소
- 메일 시스템 응답 ← 외부 — 바운스 코드(있으면) · 회신 도착 여부 · 조회 시점
- (있으면) **G7의 정정 신호** — 이전에 [회신]으로 판정한 건이 자동응답이었다는 되돌림

## 범위
포함: 바운스 코드를 3상태로 분류 / 무응답 판정(대기 시간 경과 확인) / 회신 도착 판정(사실 확인만, 성격은 안 봄) / G7 정정 신호 반영 / 상태와 판정 근거 기록
제외: 회신의 **성격**(관심·거절 등, G7의 일) / 무응답·오류의 **원인**(G8의 일) / 재시도 여부 판단(G8) / 메일 발송(G5)

## 제약
- **회신의 내용을 읽거나 판단하지 않는다.** "회신이 도착했다는 사실"만 본다 — 관심인지 거절인지는 G7의 일이다
- 값과 근거를 함께 적는다. 근거는 **어떤 응답을 받았는지**(바운스 코드 원문 또는 회신 도착 시각)
- **하드 바운스와 소프트 바운스를 다른 결론으로 다룬다** — 하드는 즉시 주소 오류, 소프트는 재시도 후에도 실패해야 주소 오류다(기준 카드 참조)
- **무응답은 "아직 안 왔다"와 다르다.** 대기 기간이 지나지 않은 건은 **[대기중]**이지 [무응답]이 아니다. 대기 기간이 안 지났는데 무응답으로 확정하지 않는다
- **G7의 정정 신호가 오면 즉시 반영한다.** 정정을 미루거나 무시하지 않는다 — 정정되지 않은 자동응답이 회신으로 남으면 회신율 통계와 G8 원인 분석이 오염된다
- 미확인 값은 임의값(잠정 10영업일, `../기준/G6_판정기준.md` 3절)으로 채워 진행한다 — 검증 대상은 `../docs/93_구현_검증대기.md` 참조
- **발송 건 1개 = 조회 1단위.** 여러 건을 한 맥락에서 같이 보되, 한 건의 판정이 다른 건의 판정에 영향을 주지 않는다

**실행 형태 — Workflow다.** 조회 → 분류 → (정정 신호 있으면) 갱신의 순서로 돌고 **실패하면 멈춘다.** 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 바운스 코드가 표준 형식이 아니다(판독 불가) | **[대기중]으로 유지**하고 사유를 기록한다. 임의로 3상태 중 하나로 추측해 넣지 않는다 |
| 대기 기간 확정값이 없다(미확인) | **기준 카드의 잠정값**으로 판정하고 산출물에 "잠정 기준 사용"이라고 표시한다 |
| G7 정정 신호가 기존 레코드와 안 맞는다(대상 발송 건을 못 찾음) | **정정을 적용하지 않고 사람에게 알린다.** 추측으로 아무 레코드에나 붙이지 않는다 |

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | 발송 기록 1건 + 그 건의 최신 메일 시스템 응답을 **1건씩** |
| 출력 | 발송 건 1개당 상태 1행(아래 출력 형식) |
| 도구 권한 | **메일 시스템 응답(바운스 로그) 조회 + 결과 파일 쓰기까지만.** 메일 발송·회신 열람 권한 없음 |
| 독립 컨텍스트 | **발송 건 1개 = 조회 1단위.** 한 건의 바운스 이력이 다른 건의 판정에 섞이지 않는다 |

## 출력 형식
**파일: 발송 건 1개당 `상태/{기업식별자}-{발송일시}.md` 1개.** G5의 발송 기록과 같은 식별자를 쓴다.

- 기업 식별자 · 발송일시 · **조회일시**
- **상태** — [대기중] / [회신] / [무응답] / [주소 오류] 중 하나
- 판정 근거 — 받은 바운스 코드 원문 또는 회신 도착 시각, 사용한 대기 기간(확정/잠정 표시)
- **정정 이력** — G7이 되돌린 적이 있으면 이전 상태 · 정정일 · 정정 사유

## 성공 기준
산출물 1건(파일 1개)마다 확인한다.
- [ ] 상태가 4종 중 하나로 명확히 기록됨 (모호한 상태 0건)
- [ ] 판정 근거(바운스 코드 원문 또는 회신 도착 시각)가 있음 (근거 없는 판정 0건)
- [ ] [무응답] 건마다 사용한 대기 기간이 표시됨(확정/잠정 구분 포함)
- [ ] [주소 오류] 건이 하드/소프트 바운스 중 어느 쪽 근거인지 구분됨
- [ ] 회신의 성격(관심·거절 등)이 이 기능의 출력에 섞이지 않음 (0건)
- [ ] G7 정정이 있는 건은 정정 이력이 남아 있음 (정정 누락 0건)
- [ ] 조회일시가 있음

**표본 검사 (매 건이 아니라 절차를 점검할 때)**
- [ ] 같은 발송 건을 같은 시점 기준으로 두 번 조회해 같은 상태가 나옴 (불일치 0건)
