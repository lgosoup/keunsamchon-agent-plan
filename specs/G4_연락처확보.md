# spec.md – 연락처 확보 (G4)

## 목표
**세그먼트(G2)의 대표 기업을 먼저**, 그다음 같은 세그먼트 나머지 기업 순으로 열어 **의미 있는 연락 창구**를 찾고, 그 주소로 **보내도 되는지**(일본 특정전자메일법 옵트인 예외 여부)를 판정해, **[확보] / [발송 금지] / [메일 없음] / [미확보]** 넷 중 하나로 낸다. (**[메일 없음]은 2026-08-03 신설** — 이메일 주소 없이 웹 문의 폼만 있는 경우. 사용자 결정으로 [확보]에서 분리했다 — G5는 메일 발송 도구이지 웹 폼 제출 도구가 아니다. `../기준/G4_연락처유효성기준.md` 1절) (2026-08-03 — 탐색 순서 재료가 G3 적합도에서 G2 세그먼트 대표로 바뀌었다. G3은 부가 기능으로 이연됐고, 대표 기업의 연락처가 없으면 그 그룹 전체의 발송이 막히므로 MVP 플로우엔 이 순서가 더 맞는다. `../docs/31_기능구조.md` 8-1절)

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자, 그리고 이 상태를 받는 뒤 작업(메일 제작·발송 / 사람 위임 / 재수집 판단)
사용 목적: 원문이 요구한 **"딥서치"**가 이 기능이다. **연락처를 찾는 것과 그 주소로 보낼 수 있는지는 다른 판정**이다 — 주소를 찾았어도 옵트인 예외가 적용되지 않으면 보내면 위법이다. 그래서 출력이 확보/미확보 둘이 아니라 **네 상태**다.
**"유효"는 존재가 아니라 의미 있는 창구인지다.** 담당자·제안 접수처에 닿는 이메일 주소와, 이메일 주소 자체가 없이 문의 폼만 있는 경우를 구분한다 — 후자는 이메일이 아예 없으므로 등급의 문제가 아니라 **[메일 없음]이라는 별도 상태**다. 실제 담당자 도달률은 기업 자신도 **"굉장히 낮은 퍼센트"**로 예상한다(`90` 리스크 7) — 일반 등급(대표 이메일 주소)으로 수렴되는 경우가 흔하다는 뜻이며, 그 경우는 [확보]로 보되 **등급을 남긴다.**
판정 기준 정본: **`../기준/G4_연락처유효성기준.md`** — 유효 등급 판정 문장, 옵트인 예외 판정, 일본어 거부 문구 목록(`../기준/G1_기업판정기준.md` 2-2절 재사용)이 여기 있다. **이 Spec과 함께 반드시 읽는다.**

## 입력
**단위 — 기업 1곳씩 넣는다.**

- G1 통과분 1건 — 기업 식별자·URL·**O8(광고 메일 거부 표시) 관찰값**
- **G2 세그먼트 정의(대표 기업 표시)** — **탐색 순서를 정한다.** 각 세그먼트의 대표 기업을 먼저 열고, 그다음 같은 세그먼트의 나머지 기업을 연다
- G9의 `연락처후보/{기업식별자}.md` (있으면) — 사람이 찾아낸 주소 원값. 다시 찾지는 않되, **등급 판정·거부 표시 확인은 새 주소와 똑같이 거쳐 이 기능이 `contacts/{기업식별자}.md`를 직접 쓴다**(아래 제약)
- G7 담당자 정보 갱신분 (있으면, **식별자가 확정된 건만** — `../specs/G7_회신해석정리.md` 출력 형식) — 기존 연락처를 이 값으로 갱신
- G10 재탐색 대상 (있으면) — 연락처만 다시 찾는다. 다른 항목은 건드리지 않는다
- **`발송금지.md`**(G7이 쌓는 수신 거부 목록 + **2026-08-03부터 G1도 O8=있음·애매 확인 시 직접 append**, append 전용) — 새 주소를 [확보]로 내기 전 이 목록에 이미 있는지 확인한다

## 범위
포함: 공식 홈페이지 우선 확인 → 안 되면 딥서치(공개 SNS·업계 디렉토리·기업 정보 사이트)로 확장 / 창구의 유효 등급 판정(직통/일반/메일 없음) / **새로 찾은 주소마다 거부 표시 재확인**(아래 제약) / 4상태 판정과 사유 기록 / **G2가 정한 순서(대표 우선)를 따른 탐색**
제외: 연락처의 **가치 판단**(부가 기능 G3이 착수되면 그 일 — G4는 지금은 세그먼트 순서를 받아 쓸 뿐 순위를 매기지 않는다) / 메일 제작·발송(G5) / **웹 문의 폼에 내용을 채워 제출하는 것**(2026-08-03 — 이건 메일 발송이 아니라 별도 기능이라 이 프로젝트 범위 밖) / 개인 연락처 수집 / 유료 DB 조회

## 제약
- **개인을 수집하지 않는다** — 개인 이름·개인 SNS 계정·개인 직통 연락처 금지. **법인 공개 창구만.** (G1과 같은 제약을 여기서도 지킨다 — 탐색 범위가 넓어질수록 이 경계가 더 쉽게 넘어간다)
- 공개 정보만 쓴다 — 로그인·회원가입 화면, 유료 DB, 추측으로 채운 값 금지
- **G1이 O8을 관찰한 주소와 다른 새 주소를 찾으면, 그 새 주소에도 거부 표시가 있는지 직접 확인한다.** G1은 자신이 본 주소 옆만 관찰했으므로, 딥서치로 찾은 주소든 G9가 사람을 통해 찾아온 주소든 아직 그 확인을 거치지 않은 것이다
- **어느 주소든 [확보]로 내기 전 `발송금지.md`에 이미 있는지 먼저 확인한다.** 있으면 새로 관찰할 것 없이 바로 [발송 금지]로 낸다 — 과거 회신에서 이미 거부 의사를 밝힌 주소다
- 값과 근거를 함께 적는다. 근거는 **어디서(어느 URL) 무엇을 확인했는지**
- **G2가 정한 순서(대표 우선)를 바꾸지 않는다.** 순서가 마음에 안 들어도 스스로 재정렬하지 않는다 — 재정렬은 부가 기능(G3·G11)이 도입되면 그때의 일이다
- 미확인 값(최소 수주 금액 등 연락처 유효성과 무관한 값)을 추정치로 채우지 않는다
- **기업 1곳 = 작업 1단위.** 앞 기업에서 찾은 패턴이 다음 기업 판정에 남지 않게 한다

**실행 형태 — Workflow다.** G2 순서(대표 우선)대로 돌고 **실패하면 멈춘다.** 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 딥서치 소스가 차단되거나 접근 불가하다 | **어디까지 찾아봤는지 범위를 기록하고 [미확보]로 종료한다.** 다른 소스로 무단 확장하지 않는다 |
| 거부 표시 판정이 갈린다 | **[발송 금지]로 종료한다.** 판정 규칙은 `../기준/G4_연락처유효성기준.md` 2절 |
| 직통/일반 등급이 애매하다 | **더 낮은 등급(일반)으로 기록하고 계속 진행한다.** 판정 규칙은 `../기준/G4_연락처유효성기준.md` 1절 |
| 이메일 주소 자체가 없고 문의 폼만 있다 | **[메일 없음]으로 종료한다.** 폼을 채워 제출하지 않는다 — 그건 이 기능의 범위 밖이다 |

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | 기업 1곳분을 **1건씩**, G2가 정한 순서(대표 우선)대로 |
| 출력 | 기업 1곳당 4상태 중 하나 + 근거, 1행 |
| 도구 권한 | **공개 웹페이지 읽기(딥서치 확장 포함) + 결과 파일 쓰기까지만.** 메일 발송·개인정보 DB 조회 권한 없음 |
| 독립 컨텍스트 | **기업 1곳 = 컨텍스트 1단위.** 앞 기업에서 찾은 창구 패턴이 다음 기업 판정에 넘어가지 않는다 |

## 출력 형식
**다음 기능 연결(제어 흐름)**: [확보] → **G5**로 이어진다. [발송 금지] → **종료**한다(G10 재수집 대상에서도 뺀다 — 다시 열어도 결론이 같다). [미확보] → **G9**(사람 위임) 큐로 넘어가고, 동시에 **G10**(연락처만 재탐색 대상)에도 들어간다. **[메일 없음] → MVP 기간에는 G9·G10이 부가 이연이라 갈 곳이 없으므로, `../specs/candidates/보류목록.md`에 append한다**(2026-08-03, `90` 리스크 35) — 버리지 않고 담당자가 주 1회 훑어보는 잔여 목록. G9·G10이 MVP로 올라오면 그때 정식 큐로 옮긴다.

**파일: 기업 1곳당 `contacts/{기업식별자}.md` 1개** — 상태와 무관하게 항상 이 파일을 쓴다(4상태 전부 여기 기록). **추가로 [메일 없음]·[미확보]는 `../specs/candidates/보류목록.md`에도 한 줄 append한다** — `contacts/`를 매번 열어보지 않고 잔여 전체를 한 파일에서 볼 수 있게 하기 위함이다. 두 파일은 서로 다른 기능이 소유하지 않는다(G4만 이 둘에 쓴다) — G1의 `candidates/후보목록.md`(append-only, 다른 기능은 건드리지 않음)와는 별개 파일이라 소유권 충돌이 없다.

- 기업 식별자 · 탐색일 · 탐색 주체 · **세그먼트 소속 + 대표 여부**(탐색 순서 근거로 기록)
- **상태** — [확보] / [발송 금지] / [메일 없음] / [미확보] 중 하나
  - [확보]일 때: 연락처 값 · 어디서 찾았는지(URL) · **유효 등급**(직통/일반) · **거부 표시 없음 확인**(어느 주소를 확인했는지) · **`발송금지.md` 미등재 확인**
  - [발송 금지]일 때: 연락처 값 · 거부 표시 원문(일본어) · 위치(주소 앞/뒤)
  - [메일 없음]일 때: 확인한 문의 폼 URL · 이메일 주소가 없음을 확인한 근거(어느 페이지들을 봤는지)
  - [미확보]일 때: 어디까지 찾아봤는지(확인한 소스 목록) · 사유

## 성공 기준
산출물 1건(파일 1개)마다 확인한다.
- [ ] 상태가 4종 중 하나로 명확히 기록됨 (모호한 상태 0건)
- [ ] [확보] 건에 유효 등급과 출처 URL이 있음 (등급 없는 확보 0건)
- [ ] [확보] 건마다 거부 표시 없음이 **어느 주소를 확인했는지와 함께** 기록됨 (확인 근거 없는 확보 0건)
- [ ] [확보] 건마다 `발송금지.md` 미등재 확인이 기록됨 (확인 근거 없는 확보 0건)
- [ ] [발송 금지] 건에 거부 표시 원문(일본어)과 위치가 있음 (사유 없는 발송 금지 0건)
- [ ] [메일 없음] 건에 확인한 문의 폼 URL과 근거가 있음 (근거 없는 메일 없음 0건)
- [ ] [미확보] 건에 탐색 범위(어디까지 찾아봤는지)가 있음 (범위 없는 미확보 0건)
- [ ] [메일 없음]·[미확보] 건이 `../specs/candidates/보류목록.md`에도 append됨 (누락 0건)
- [ ] 개인 이름·개인 SNS·개인 직통 연락처가 기록되지 않음 (0건)
- [ ] 각 세그먼트의 대표 기업이 소속 기업보다 먼저 탐색됨 (순서 위반 0건)
- [ ] 탐색일·탐색 주체가 있음

**표본 검사 (매 건이 아니라 절차를 점검할 때)**
- [ ] 같은 기업을 두 번 돌려 상태 판정이 같음 (불일치 0건)

## 확인 후 채울 것
- 유효 등급 하한(일반 창구도 확보로 볼지, 아니면 미확보로 내릴지) ← **`12` N4·Q12**(회신 응대 인력·준비 상태). 응대 인력이 부족하면 일반 창구로도 충분할 수 있고, 반대면 직통만 확보로 좁혀야 한다
- 딥서치로 확장할 구체적 소스 목록 ← 지금은 "공개 SNS·업계 디렉토리·기업 정보 사이트"로만 열어둔다. 실제 시험 실행에서 어느 소스가 실질적으로 유효했는지를 보고 좁힌다
