# 핵심 문제와 해결 — 근본원인 하나에서 두 갈래로

> **이 문서가 하는 일**: 기업서치 병목(확정 사실)과 이메일 병목(설계 가설)을 하나의 근본원인 아래 이어, 발표·심사에서 쓸 수 있는 짧은 스토리로 정리한다. **기능을 새로 만들거나 바꾸지 않는다** — 아래 G1~G11은 각 기능의 `specs/`·`criteria/` 정의를 그대로 참조한다.
> **근거·버린 대안·뒤집힐 조건은 여기 쓰지 않는다.** 이 문서는 확정된 서사만 담는다.

---

## 1. 근본원인

> **해외영업 판단(누구를 접촉할지 + 무엇을 어떻게 제안할지)이 회사 내부 자산이 아니라, 협력사라는 외부의 암묵적 경험에 갇혀 있다.**

협력사는 자기 경험 영역만 다루고(F10), [우리 추론 — 그 판단이 회사에 명시적으로 옮겨진 적이 없다는 후반절은 F10이 직접 뒷받침하는 범위를 넘는다] 이 결핍이 아래 두 병목을 동시에 만든다.

## 2. 두 병목 — 근본원인의 두 갈래

두 병목은 지위가 다르다. 기업서치 병목은 **확정 사실**이고, 이메일 병목은 **설계 제약(가설)**이다 — 후자는 기업이 겪은 실패 사례가 아니라, 1차 병목을 기업별 개별 맞춤으로 풀면 협력사 병목을 그대로 재생산하기 때문에 우리가 세운 제약이다.

| | 기업서치 | 이메일 제작·발송 |
|---|---|---|
| **병목** | 협력사 경험 밖의 후보를 판별할 기준과 근거가 없다 | (**가설**) 기업별 개별 맞춤은 기업 수에 비례해 협력사 병목을 재생산한다 — 그래서 세그먼트로 묶는 설계 제약이 필요하다 |
| **지지사실** | F10·F11·F14·F15 | 기업이 이 부담을 실제로 겪었다는 확인 사실 없음 — N29 확인 대기 |

두 병목을 각각 독립으로 정당화하지 않는다 — 둘 다 1절의 근본원인에서 나온다.

## 3. 해결 — 하나의 자산, 두 방향

> **협력사의 암묵적 판단을 회사 내부의 명시적·재사용 가능하고, 반응으로 계속 갱신되는 자산으로 옮긴다.**

두 병목 모두 같은 시간 구조를 따른다 — **지금은 재사용, 나중은 학습.** 어느 한쪽 병목이 재사용 또는 학습 하나로만 처리되는 게 아니다.

| | 기업서치 | 이메일 제작·발송 |
|---|---|---|
| **지금 (재사용, 공간적 확장)** | G1이 관찰 근거를 명시화해 여러 후보에 반복 적용 | 세그먼트·기준 문안을 여러 기업에 반복 적용 |
| **나중 (학습, 시간적 개선)** | 접촉 반응으로 판별 기준을 갱신 | 접촉 반응으로 문안·세그먼트를 갱신 |

## 4. 기능(G1~G12) 연결 — 그리고 구현 범위

**기능 자체는 G1~G12 12개 그대로다.** 아래는 각 함수가 재사용/학습 중 무엇을 주로 담당하는가만 표시한다.

| 함수 | 주로 |
|---|---|
| G1 대상 기업 발굴 | 재사용(관찰 근거 명시화) + 학습(판별 기준 갱신) |
| G2 세그먼트화 | 재사용 |
| G3 적합도 평가 | 학습 |
| G4 연락처 확보 | 재사용 |
| G5 제안 메일 제작·발송 | 재사용 |
| G6 발송 결과 판정 | 재사용+학습 (반응의 원재료) |
| G7 회신 해석·정리 | 재사용+학습 |
| G8 원인 분석 | 학습 |
| G9 사람 접촉 위임 브리프 | 학습 |
| G10 재수집 판단 | 학습 |
| G11 반응 집계·기준 조정 | 학습 (루프를 닫는 지점) |
| G12 질의응답 | 조회 전용 — 재사용/학습 축 밖(G1~G11의 결과를 읽기만 하는 별도 진입점) |

**지금 시연 가능한 것은 "재사용" 방향뿐이다.** "학습"(G3·G8·G9·G10·G11)은 구조만 확정돼 있고 실제 가동은 발송·회신 데이터가 쌓인 뒤다. **발표·시연에서 이 둘을 섞어 말하지 않는다.** MVP로 지금 시연하는 것은 확정된 기업서치 병목(G1 재사용)과 이메일 병목(G2·G5 재사용) 둘 다다 — 어느 한쪽만 다루는 게 아니다.

## 5. 발표용 한 줄

> 일본 진출 잠재고객 탐색에서 협력사에게만 있던 판단(누구를 접촉하고 무엇을 제안할지)을 회사 내부의 재사용 가능한 자산으로 옮겨, 세그먼트별 제안 메일을 사람 승인 후 발송하고 실제 반응으로 그 자산을 계속 고친다.

나머지 근거·버린 대안·반례는 이 패키지 밖의 설계 과정 문서에 있다.
