# Harness — G7 회신 해석·검증 (제출용 패키지)

이 폴더 **하나만으로** G7(일본어 회신 해석·정리) 기능의 하네스 구조를 이해하고 재현할 수 있어야 한다. 부트캠프 최종 제출 기준(`평가항목.md`)의 "Harness 폴더만으로 구조를 이해하고 재현할 수 있는가"에 대응한다.

## 이 폴더가 무엇인가

이 저장소는 평소 작업할 때 Spec(`specs/`)·판정 기준(`기준/`)·실행체(`.claude/`)를 **역할별로 분리**해 관리한다(`CLAUDE.md` 4·5절 — 같은 값을 두 곳에 적지 않기 위해서다). 이 폴더는 그중 **G7 한 기능**에 필요한 것만 골라 **제출 형태(spec.md / skills / agents / role-table / workflow)**로 한 자리에 모은 스냅샷이다.

**정본은 여기가 아니다.** 실제로 고치는 곳은 아래 표의 "원본 위치"이고, 이 폴더는 그 결과를 복사한 것이다. 원본이 바뀌면 이 폴더도 다시 복사해 갱신한다(아래 "갱신 방법").

## 구성

```
Harness/
├─ spec.md                          # G7 6요소 Spec (원본: specs/G7_회신해석정리.md)
├─ 기준.md                          # G7 판정 기준 카드 (원본: 기준/G7_회신판정기준.md)
├─ skills/
│  └─ g7-회신처리/SKILL.md          # 오케스트레이팅 스킬 — T→V 호출·분기·병합·자체점검
├─ agents/
│  ├─ g7-회신해석.md                # 단위 T — 해석 (원본: .claude/agents/g7-회신해석.md)
│  └─ g7-번역검증.md                # 단위 V — 번역 검증 (원본: .claude/agents/g7-번역검증.md)
├─ role-table.md                    # Skill·Agent별 역할/입출력/도구권한 표
├─ 워크플로우_절차서.md              # 실행 순서·단계별 입출력·실패 시 처리
└─ README.md                        # 이 파일
```

`data/`·`hooks/`는 두지 않았다 — G7은 별도 데이터 파일이 필요 없고(회신 원문을 그때그때 붙여넣는 구조), Hook(자동 트리거)은 이 저장소 전체에서 아직 아무 기능에도 없다(`CLAUDE.md` 7절 — 새 트리거 주기값이 미정이라 지금 만들면 근거 없는 값이 된다).

## 원본 위치 (갱신 시 여기서 다시 복사한다)

| 이 폴더의 파일 | 원본 | 원본이 정본인 이유 |
|---|---|---|
| `spec.md` | `specs/G7_회신해석정리.md` | 실제 작업은 이 저장소 안에서 계속되고, 다른 기능(G1 등)의 Spec과 형식·번호 체계를 공유해야 한다 |
| `기준.md` | `기준/G7_회신판정기준.md` | 실제 회신을 판정해 보며 **자주 고치는** 문서라 여기 복사본을 고치면 원본과 어긋난다 |
| `skills/g7-회신처리/SKILL.md` | `.claude/skills/g7-회신처리/SKILL.md` | 이 스킬은 이 저장소의 다른 실행체(`g1-기업판정` 등)와 같은 호출 규약을 쓴다 |
| `agents/g7-회신해석.md` | `.claude/agents/g7-회신해석.md` | 위와 같음 |
| `agents/g7-번역검증.md` | `.claude/agents/g7-번역검증.md` | 위와 같음 |

**`spec.md`·`기준.md` 안의 상대 경로(예: `../기준/...`, `../specs/README.md`)는 원본 저장소 기준으로 쓰인 것이다.** 이 폴더 단독으로 열면 `../기준/G7_회신판정기준.md`는 곧 이 폴더의 `기준.md`를 가리킨다고 읽는다 — 파일 내용은 원본과 동일하게 유지하기 위해 경로를 고쳐 쓰지 않았다.

## 갱신 방법

원본 5개 파일 중 하나라도 바뀌면 이 폴더의 대응 파일을 다시 복사해 덮어쓴다. `role-table.md`·`워크플로우_절차서.md`는 원본이 없는 이 폴더 전용 문서이므로, T·V의 역할·입출력·실패 처리 로직이 바뀌면(즉 `SKILL.md`·`agents/*.md`의 절차 자체가 바뀌면) 손으로 맞춰 고친다.

## 왜 별도 오케스트레이터 서브에이전트가 없는가

`워크플로우_절차서.md`의 "에이전트 구성" 절에 근거를 남겼다 — 짧게 말하면, 이 파이프라인은 서브에이전트를 여러 번 반복 호출하는 루프가 없어서(회신 1통 = 실행 1회) 스킬 자신이 오케스트레이터를 겸해도 실행 흐름이 흐려지지 않는다.
