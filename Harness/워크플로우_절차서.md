# 워크플로우 절차서 — G7 회신 해석·검증 파이프라인

> 이 문서는 `skills/g7-회신처리/SKILL.md`가 이미 실행하는 순서를 제출용 표로 옮긴 것이다. 실행 중 실제로 참조하는 정본은 SKILL.md이고, 이 파일과 어긋나면 **SKILL.md가 이긴다** — 판정 문장·임계값은 여기 다시 적지 않고 `기준.md`를 가리킨다.

## 패턴

**체이닝(Chaining) + 조건 분기(Conditional Branching)**

- 기본 골격은 체이닝: 해석(T) → 검증 입력 추출 → 검증(V) → 병합·자체점검. 각 단계의 출력이 다음 단계의 입력이 된다.
- 조건 분기가 필요한 지점 셋: ① T가 판독 불가(C8)로 끝나면 V를 호출하지 않고 바로 종결 ② V가 불일치를 내면 T로 되돌아가 재번역 1회 후 V를 다시 호출 ③ 재번역 후에도 불일치면 더 되돌아가지 않고 원문+두 번역본을 함께 올린다.

## 에이전트 구성

**멀티 에이전트 — 단, 별도 오케스트레이터 서브에이전트는 두지 않는다.**

`g7-회신처리` 스킬 자신이 오케스트레이터 역할을 겸하고, 실행 단위 T(`g7-회신해석`)·V(`g7-번역검증`)만 독립 서브에이전트로 둔다.

**별도 오케스트레이터 서브에이전트를 안 둔 이유**: 이 파이프라인에는 "같은 서브에이전트를 여러 번 반복 호출하는 루프"가 없다 — 회신 1통이 곧 실행 1회이고, 사람이 매번 스킬을 직접 부른다(G1·G3처럼 후보 여러 곳을 한 번에 순회하는 구조가 아니다). 관리할 반복 루프가 재번역 1회 재시도 정도뿐이라 스킬 안의 분기표 하나로 충분하고, 별도 오케스트레이터 파일을 하나 더 등록해도 **출력이 달라지지 않는다**(절차 상한 판별법). 다만 이 판단은 "실행 단위가 T·V 둘뿐이라 로그에서 실패 지점을 구분하기 쉽다"는 전제 위에 있다 — 나중에 실행 단위가 늘어나 추적이 어려워지면 재검토한다.

## 실행 순서

```
[g7-회신처리 오케스트레이션]
1.  회신 원문 1통을 받는다 (헤더 + 참조 발신 정보 포함, 없으면 "참조 문안 없음") → T 호출 프롬프트 준비
2.  g7-회신해석(T)을 독립 컨텍스트로 호출 → 레코드 파일 생성(검증층은 비움) + 발송금지 등재(해당 시)
3.  T 응답을 확인한다
    ├─ 수신거부/의심인데 미등재면 그 자리에서 발송금지.md에 등재 (V를 기다리지 않는다)
    └─ 판독 불가(C8)면 4~8 건너뛰고 9로 (V 호출 안 함)
4.  (판독 가능 시) 레코드에서 원문층 전문 + 해석층 전문만 뽑아 검증입력 파일(-r1)에 쓴다
5.  g7-번역검증(V)을 독립 컨텍스트로 호출 (경로가 아니라 두 블록을 인라인으로 전달)
6.  V 판정을 레코드 검증층에 그대로 옮겨 적고 분기한다
    ├─ 3층 전부 일치 → 9로
    ├─ 불일치(1회차) → 7로
    └─ (7~8을 거친 뒤) 2회차도 불일치 → 9로 (C8로 내리고 원문+두 번역본+불일치지점 함께)
7.  (조건부) T를 재호출(재번역. 원문 + 불일치 지점만 전달, 1회차 해석은 주지 않는다) → 새 해석층·판단층으로 레코드를 덮어쓴다
8.  (조건부) 4~5를 반복(-r2)해 V를 다시 호출 → 그 재판정을 6으로 되돌려 반영한다
9.  최종 레코드를 spec.md 「성공 기준」 13개 항목(무관용 3 + 서식점검 10)으로 자체 점검, 걸리면 고쳐서 재확인
10. 사용자에게 「사용자 조치 요청」 중심으로 보고
```

번호는 아래 "단계별 입출력" 표와 1:1 대응한다 — 이 문서 안에 다른 번호 체계를 두지 않는다.

## 단계별 입출력

| 단계 | Skill/에이전트 | 입력 | 출력 |
|---|---|---|---|
| 1 | g7-회신처리 (오케스트레이터) | 회신 원문 1통(헤더·첨부목록·참조발신정보 포함, 사용자가 붙여넣음) | T 호출 프롬프트 |
| 2 | g7-회신해석 (T) | 위 입력 그대로 | `replies/{수신일시}-{식별자}.md` (원문층·해석층·판단층, 검증층 빈칸) + 수신거부 시 `발송금지.md` 1행 |
| 3 | g7-회신처리 | T 응답(레코드 경로·판독가능여부·발송금지 등재여부) | 수신거부 즉시 처리 확인, C8 분기 판단 |
| 4 | g7-회신처리 | 레코드의 원문층 전문 + 해석층 전문 | `replies/_검증입력/{레코드파일명}-r1.md` (원문+해석 이 둘만) |
| 5 | g7-번역검증 (V) | -r1.md의 두 블록(인라인 전달, 경로 아님) | 검증층 판정 텍스트(층1·2·3 일치/불일치 + 불일치 지점 + 권고) |
| 6 | g7-회신처리 | V 응답 | 레코드 검증층에 그대로 옮겨 적음 |
| 7 (조건부) | g7-회신해석 (T, 2회차) | 원문 전문 + V가 지목한 불일치 지점(1회차 해석은 주지 않음) | 새 해석층·판단층 (같은 레코드 파일 덮어씀) |
| 8 (조건부) | g7-번역검증 (V, 재검증) | 4번을 되풀이한 -r2.md | 재판정 |
| 9 | g7-회신처리 | 최종 레코드 | `spec.md` 「성공 기준」 13개 항목 자체점검 결과 |
| 10 | g7-회신처리 | 자체점검 결과 | 사용자 보고 (조치 요청 중심) |

**단계 간 입출력 일치 확인**: 2단계 T 출력(레코드 파일 경로)을 3·4단계가 그대로 받고, 4단계 출력(-r1.md 두 블록)을 5단계 V가 그대로 받으며, 5단계 V 출력(판정 텍스트)을 6단계가 그대로 레코드에 옮긴다 — 형식이 다음 단계 입력과 일치하지 않는 지점은 없다.

## 실패 시 처리

| 실패 항목 | 되돌아갈 단계 | 처리 (판정 값은 `기준.md` 참조) |
|---|---|---|
| 판독 불가(인코딩 손상·본문 없음·언어 불명) | 4~8 생략, 9로 | C8 기록 + 원문을 그대로 사용자에게. 재시도하지 않는다 |
| 번역 검증 불일치 (1회차) | 7단계(T 재호출·재번역) → 8단계(V 재호출)로 | T 재호출 1회. 1회차 해석은 주지 않는다 |
| 번역 검증 불일치 (2회차) | 되돌아가지 않음 | C8로 내리고 원문 + 두 번역본 + 불일치 지점을 함께 올림. 어느 쪽도 확정으로 제시하지 않음 |
| 검증층 미완성 (V 호출 실패·응답 없음) | 되돌아가지 않음 | 사용자에게 보내지 않는다(보류). 무관용 3종은 검증층이 채워진 뒤에만 판정 가능 |
| 수신 거부/의심 판정 | 없음(항상 즉시) | 분류·검증의 성패와 무관하게 즉시 `발송금지.md` 등재. 이 처리는 위 네 실패 중 무엇이 나든 먼저 끝나 있어야 한다 |

## (선택) 스케줄

- 주기: 수동. 회신 1통이 도착할 때마다 사람이 원문을 붙여넣어 스킬을 호출한다.
- 매 실행 시 입력: 회신 원문 텍스트(붙여넣기). 메일함 자동 수신 연동은 반자동 범위가 확정된 뒤의 과제다(`spec.md` 「확인 후 채울 것」).
