# spec.md – 질의응답 (G12)

## 목표
**(부가 — MVP 범위 밖. `../docs/31_기능구조.md` 8-1절)**

저장된 산출물(G1~G11)에 대한 사용자의 자연어 질문에, **근거(출처 파일·항목)를 인용해** 답한다. 실행·수정 권한 없이 **읽기만** 한다.

## 맥락
대상: 큰삼촌컴퍼니 해외영업 담당자
사용 목적: 기업이 요구한 "대시보드"(`13S` F9·F22)가 G1+G2+G4(+부가 시 G3) 결과를 한 화면에 늘어놓는 목록형 화면이라면, 이 기능은 **그 위에서 담당자가 궁금한 걸 바로 물어보는 창구**다 — "이번 주 회신 몇 건 왔어", "이 기업은 왜 제외됐어" 같은 질문에 여러 파일을 직접 열어보지 않고 답을 받는다.

**원안(`30` ⑦)에는 "전역 LLM 에이전트와 대화로 조정·자연어로 재분석 요청"이 있었는데, `../docs/90_미결정과_리스크.md` #8이 이걸 기각했다** — 파이프라인 실행 경로 자체를 대화로 바꾸는 것(Agent형)은 Workflow와 오류 처리가 정반대이고 "판단 근거를 설명할 수 있는가"를 해친다는 이유였다. **이 기능은 그 기각된 것과 다르다.** 파이프라인을 조정하지 않고 **이미 나온 결과만 읽고 답한다** — 이 경계(아래 「도구 권한」)가 `90` #8이 우려한 문제를 물리적으로 차단한다. 상세 근거는 `../docs/33_설계근거.md` **D20**.

G1~G11은 각자 다른 파일에 결과를 낸다(`후보목록.md` · `segments/` · `contacts/` · `발송기록/` · `상태/` · `replies/` · `집계/` 등). 이 기능은 **그 파일들을 그대로 두고 필요한 만큼만 읽는다** — 새 파일로 데이터를 복제하지 않는다(`CLAUDE.md` 5절 "값을 두 곳에 적지 않는다"). **⚠ 2026-08-06 정정 — "전부 기업식별자를 키로 씀"은 틀린 문장이었다.** 파일마다 키가 다르다 — 대부분 기업식별자가 파일명 맨 앞이지만(`contacts/`·`발송기록/`·`상태/`·`원인분석/`·`위임브리프/`·`재수집대상/`), `replies/`는 **날짜가 앞**(`{수신일시}-{식별자}`)이고, `집계/`는 **세그먼트 단위**(`{집계일}`)라 기업식별자 키 자체가 없고, `scores/`는 채점 파일(기업식별자)과 순위표(`{작성일}`)가 같은 디렉터리에 섞여 있다. **정확한 파일별 키 형식은 `.claude/skills/g12-질의응답/SKILL.md`「산출물 자리」표가 정본이다** — 여기서 다시 나열하지 않는다.

**별도 기준 카드 없음** — 판정 문턱이 아니라 조회이므로 `../기준/`에 짝이 되는 카드를 두지 않는다(G9·G10·G11과 같은 처리).

## 입력
**단위 — 질문 1건씩 받는다.**

- 질문 텍스트(자연어)
- G1~G11 산출물 중 **그 질문이 요구하는 범위만** — 기업식별자로 조인해 선택적으로 열람한다. **G11("집계 시점까지 전체 데이터를 한 벌")과 다르다** — 전체를 매번 다 읽지 않는다

## 범위
포함: 질문 해석 / 필요한 산출물 파일 선택적 열람(기업식별자 조인) / 답변 생성 + 출처 인용 / 답변 로그 기록
제외: **산출물 수정**(G1~G11 파일에 쓰지 않는다) / **파이프라인 실행·재실행**(G1~G11 어느 기능도 이 기능이 대신 돌리지 않는다) / G11의 기준 조정 제안 실행 / 발송·접촉 행위 / 질문 범위 밖의 예측·추천(데이터에 없는 판단을 스스로 만들어내지 않는다)

## 제약
- **도구 권한은 읽기 + 답변 로그 쓰기까지만.** 웹·발신·실행 도구는 `disallowed-tools`로 물리적으로 닫혀 "이 기능은 파이프라인을 조정하지 않는다"를 강제한다(위 맥락, `90` #8과의 구분). **⚠ 2026-08-06 정정 — G1~G11 산출물 파일에 대한 "쓰기 권한 없음"은 도구 차단이 아니라 지침이다.** `Write`·`Edit` 자체는 열려 있다(질의응답로그/를 쓰려면 있어야 한다) — `disallowed-tools`는 경로 단위로 막지 못해 특정 디렉터리만 쓰기 금지하는 것이 불가능하다(`g10-재수집판단`이 이미 같은 이유로 이렇게 적어 뒀다). **쓰는 자리는 아래 「산출물 자리」 표의 답변 로그 한 곳뿐**이고, 그 외 모든 디렉터리는 읽기만 한다는 것으로 실제로는 지켜진다
- **`-미확정` 식별자(G7 발신 도메인 폴백)는 기업 단위 조인에 넣지 않는다** — G1 식별자와 일치를 보장할 수 없다(`../specs/G7_회신해석정리.md` 출력 형식, `../specs/G11_반응집계_기준조정.md` 제약과 동일 규칙). 답변에 이런 레코드가 섞이면 "식별 불가"로 표시하고 확정 사실처럼 말하지 않는다
- **데이터에 없는 값을 추정으로 채우지 않는다.** 질문에 답할 근거가 없으면 "확인 불가"로 답한다 — 지어낸 답보다 모른다는 답이 안전하다(`CLAUDE.md` 5절 "발명 금지")
- **답변마다 출처(파일명 + 항목)를 인용한다.** 인용 없는 답은 사용자가 검증할 방법이 없다
- **인용을 확정하기 전에 그 파일·항목을 다시 열어 실제로 그렇게 적혀 있는지 확인한다**(2026-08-06 추가) — 조회 기능의 유일한 산출물이 "답변 + 그 답변이 스스로 붙인 근거"라, 인용 확인 없이 내보내면 이 기능 자신이 자기 답을 검증 안 한 것과 같다. 별도 실행 단위를 새로 만들지 않고 **같은 실행 안에서 재확인 단계로 둔다** — 조회는 생성이 아니라 대조라 T/V처럼 컨텍스트를 가를 이유(앞 회차를 못 봐야 함/결론을 못 봐야 함)가 없다
- **조회 범위를 벗어난 요청은 실행하지 않고 범위 밖임을 알린다** — "지금 발송해줘", "다시 조사해줘" 같은 실행 요청이 오면 이 기능은 조회만 한다고 답하고 해당 기능(G1·G4·G5 등)으로 안내한다

**실행 형태 — Chatbot이다.** G1~G11의 "Workflow"(고정 순서, 실패 시 중단)와 다르다 — 질문마다 독립적으로 응답하고 고정된 실행 순서가 없다. **다만 실행 권한이 없으므로 Chatbot이라도 `90` #8이 우려한 위험(통제 불가능한 재실행)이 발생하지 않는다.** 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 질문이 요구하는 데이터가 아직 없다(예: 발송 이력이 없는데 회신 건수를 물음) | **"데이터 없음"으로 답한다.** 없는 데이터를 추정치로 채우지 않는다 |
| 조인 키가 여러 후보로 갈린다(`-미확정` 포함, 또는 파일명만으로 기업식별자가 안 갈리는 경우 — 기업식별자 자체에 하이픈이 들어가는 사례가 있다) | **특정 불가로 표시**하고 후보를 나열하되 하나로 단정하지 않는다. **파일명을 쪼개 식별자를 추측하지 않는다** — 파일 본문의 「기업 식별자」 항목값만 조인 키로 쓴다 |
| 질문이 조회 범위를 벗어난다(실행 요청·예측·기획 판단 요구) | **답하지 않고 범위 밖임을 알린다.** 해당하는 기능·문서로 안내만 한다(스스로 판단해 실행하지 않는다) |
| **읽어야 할 디렉터리·파일이 아예 없다**(예: `발송금지.md`가 아직 생성 전) (2026-08-06 추가) | 파일 부재 자체를 "데이터 없음"의 한 형태로 답한다 — 존재하지 않는 파일을 열려다 오류로 죽지 않는다 |
| **인용하려는 파일에 「시험 실행 — 확정 아님」 등 잠정 표시가 있다**(2026-08-06 추가) | 그 표시를 답변에 그대로 옮긴다 — 잠정 산출물을 확정 사실처럼 말하지 않는다 |
| **같은 기업에 대해 서로 다른 시점의 파일 둘이 모순된 값을 담고 있다**(예: 구 `candidates/{식별자}.md` 개별 파일과 현행 `candidates/후보목록.md`)(2026-08-06 추가) | **최신 형식·최신 파일을 우선**하고, 옛 파일은 "이력"으로만 언급한다. 어느 쪽이 최신인지 판단이 안 서면 "판정 불가 — 상충하는 기록 있음"으로 답한다 |

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | 질문 1건 + 그 질문이 요구하는 범위의 G1~G11 산출물 |
| 출력 | 답변 1건 + 인용 출처 목록 |
| 도구 권한 | **G1~G11 산출물 파일 읽기 + 답변 로그 쓰기까지만.** 웹·실행·발신 권한은 `disallowed-tools`로 물리적으로 없음(도구 자체가 없다). **G1~G11 산출물에 안 쓰는 것은 도구 차단이 아니라 지침**이다 — `Write`는 로그를 쓰려면 열려 있어야 해서 경로 단위로는 못 막는다(위 「제약」) |
| 독립 컨텍스트 | **질문 1건 = 조회 1단위.** 이전 질문·답변이 맥락으로 이어질지는 확인 후 채울 것(아래) — 자기검증 오염 방지 목적(G7·G11의 독립 컨텍스트 원칙)과는 다른 성격의 판단이라 별도로 정한다 |

## 출력 형식
**파일: 질문 1건당 `질의응답로그/{일시}.md` 1개.** `{일시}`는 초 단위까지 포함한 `YYYY-MM-DD-HHMMSS`(이 저장소의 다른 산출물과 같은 하이픈 표기, 예: `2026-08-10-090512`). **같은 초에 두 번째 호출이 들어오면(파일명 충돌) `-2`, `-3`처럼 끝에 일련번호를 붙인다** — 기존 파일이 있으면 다음 번호를 쓴다(2026-08-06 정정, `../docs/90_미결정과_리스크.md` 3절 G12).

- 질문 원문 · 조회 시각
- 답변
- **인용 출처** — 파일명 + 항목(예: `발송기록/honeys-co-jp-2026-08-10-0900.md` 세그먼트란 — 실제 파일명 형식은 소비 시점에 `../specs/G5_제안메일제작발송.md` 「출력 형식」을 다시 확인한다, 이 예시로 고정하지 않는다) 목록
- (해당 시) **"확인 불가" / "조회 범위 밖"** 표시 + 사유

## 성공 기준

**무관용 — 하나라도 어기면 그 답변을 사용자에게 보내지 않는다**
- [ ] 답변마다 출처(파일명+항목) 인용이 있다 — 어기면 사용자가 답변을 검증할 수 없다
- [ ] 데이터에 없는 값을 지어낸 사례가 없다 — 어기면 사용자가 틀린 정보로 판단한다
- [ ] G1~G11 산출물 파일이 이 기능에 의해 수정된 적이 없다 (0건 — `Write`는 열려 있으나 쓰는 자리를 답변 로그 하나로 제한하는 지침으로 지켜진다, 2026-08-06 정정: 이전 "도구 권한으로 원천 차단"은 사실과 달랐다)

**서식 점검**
- [ ] `-미확정` 식별자 레코드가 확정 사실처럼 섞여 들어간 답변 0건
- [ ] 조회 범위를 벗어난 요청에 실행 대신 안내가 나감 (스스로 실행한 사례 0건)
- [ ] 질문마다 답변 로그가 남음(질문+답변+인용 출처)
- [ ] 조회 시각이 있음

## 확인 후 채울 것
- **답변 로그의 보존 기간·조회 방법** ← 실제 운영에서 로그가 얼마나 쌓이는지 보고 정한다
- **같은 대화 세션 내 이전 질문 맥락 유지 여부** ← Build Order 단계에서 UX로 정한다. 자기검증 오염 방지가 목적이 아니므로 다른 기능의 "독립 컨텍스트" 원칙을 그대로 가져올 필요는 없다
- **조인 키 불일치(`-미확정`) 완화책의 실제 표현 방식** ← 화면/응답에서 "식별 불가"를 어떻게 보여줄지는 화면 설계 단계(`../docs/31_기능구조.md` 7절)에서 정한다
