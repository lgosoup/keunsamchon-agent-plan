# spec.md – 회신 해석·정리 (G7)

## 목표
일본어 회신 메일 1통을 **원문을 보존한 채** 한국어로 해석하고, 회신 성격을 8분류 중 하나로 판정하고, **번역이 정확한지 별도 단위가 검증한 결과**를 붙여, 사용자가 읽고 판단할 수 있는 레코드 1건을 만든다.

## 맥락
대상: 큰삼촌컴퍼니 담당자(한국어로 판단한다)
사용 목적: 보낸 메일에 온 일본어 회신을 놓치지 않고, 오해 없이 읽고, 다음 행동을 결정한다. **보내는 메일이 일본어이므로 오는 회신도 일본어다.**
**회신 1통의 가치가 크고, 오역 1건의 비용도 크다.** 그래서 해석과 **별도 단위로** 번역 검증이 붙는다 — 근거는 `../docs/33_설계근거.md` D7.
판정 기준 정본: **`../기준/G7_회신판정기준.md`** — 8분류 정의, 어떤 일본어 표현이 어느 칸인가(완곡 거절 목록 포함), 번역이 맞다고 볼 조건이 여기 있다. **이 Spec과 함께 반드시 읽는다.**

## 입력
**실행 단위가 둘이고, 반드시 갈라야 한다.** 같은 주체가 번역하고 자기가 검증하면 그것은 검증이 아니다.

**단위 T (해석) — 회신 1통씩 넣는다**
- 회신 원문 (일본어 텍스트. 줄바꿈·서명·인용부 포함한 그대로)
- 헤더 — 발신 주소 / 수신일시 / 제목 / 스레드 식별자
- 첨부가 있으면 파일명·형식 목록만 (내용은 범위 밖)
- **참조 발신 정보 (있으면)** — 아래 6항목. **없으면 `참조 문안 없음`으로 두고 작업을 계속한다**
  1. 어느 기업에 보냈는가 (식별자)
  2. 언제 보냈는가
  3. 어떤 **세그먼트**의 문안이었는가 — *세그먼트 = 비슷한 기업끼리 묶은 무리. 같은 무리는 같은 문안을 받는다*
  4. 본문에서 무엇을 근거로 인용했는가
  5. 무엇을 제안했는가 / 무엇을 물었는가
  6. 발신에 쓴 언어와 발신측 번역 검증 결과

**단위 V (검증) — T의 산출물을 받는다**
- **원문(일본어)과 한국어 해석, 이 둘만 받는다**
- **분류 결과·요구 추출·조치 요청은 받지 않는다** — 결론을 먼저 보면 번역을 결론에 맞춰 읽는다
- T가 어떻게 판단했는지의 과정도 받지 않는다

## 범위
포함: 원문 보존 / 한국어 해석 / 애매한 표현의 애매 표시 / 회신 성격 8분류와 근거 인용 / **수신 거부 판정과 발송 금지 기록** / **자동응답 판정** / 상대의 요구·기한 추출 / 담당자 이관 정보 추출 / **번역 검증 3층** / 사용자 결정 요청 항목 / 판정 불가 기록
제외: **답장 작성·발송**(사람이 결정한다) / 보내는 메일 제작 / 바운스·주소 오류 판정(메일 시스템 응답을 보는 별개 작업) / 무응답 원인 분석 / 첨부 파일 내용 해석 / 회신율 집계 / **미팅·견적·계약·결제 이후 전 과정**(기업의 실무 준비 상태가 미확인이라 의도적으로 비웠다)

## 제약
- 일본어 원문을 지우지 않는다 — 원문과 해석을 같은 레코드에 병기한다
- 번역과 판단을 다른 칸에 쓴다 — "무엇이라고 썼는가"(해석)와 "관심 있어 보인다"(분류)는 다른 것이다
- **애매한 것을 확실하게 쓰지 않는다** — 원문이 완곡·중립이면 그대로 표시하고 두 읽기를 병기한다
- **번역한 쪽이 그 번역을 검증하지 않는다** — 단위 T와 V를 다른 호출로 분리한다
- **검증하는 쪽은 분류 결과를 보지 않는다**
- **수신 거부는 애매하면 거부로 처리한다** — 위법 발송의 비용이 리드 하나를 잃는 비용보다 크다
- 자동응답을 사람 회신으로 세지 않는다
- 답장 권한을 갖지 않는다 — 발신 도구에 접근하지 않는다
- 회신에 담긴 개인 정보는 연락처 갱신 칸에만 두고 다른 칸에 복제하지 않는다
- **회신 1통 = 작업 1단위.** 앞 회신 내용이 다음 판정에 남지 않게 한다
- 미확인 값(응대 준비 상태·응대 인력)을 추정으로 채우지 않는다

**실행 형태 — Workflow다.** T(해석) → V(검증)의 순서로 돌고 **실패하면 멈춘다.** 애매한 것을 자기 판단으로 확정해 넘기지 않는다. 실패 3종의 처리:

| 실패 | 처리 |
|---|---|
| 판독 불가 (인코딩 손상 · 본문 없음 · 언어 불명) | **C8(판정 불가)**로 기록하고 **원문을 그대로** 사용자에게 올린다. 추측해 해석하지 않는다. **검증할 해석이 없으므로 단위 V를 호출하지 않고 검증층에 `검증 대상 없음`을 적는다** — 아래 3행의 "비어 있다"에 해당하지 않는다 |
| 번역 검증이 불일치 | **재번역 1회.** 두 번째도 안 맞으면 **C8로 내리고** 원문 + 두 번역본 + 안 맞은 지점을 함께 사람에게 올린다 |
| 검증층이 비어 있다 | **그 건을 사용자에게 보내지 않는다.** 무관용 3종은 검증층이 채워진 뒤에만 판정된다 |

**단, 수신 거부는 이 순서를 기다리지 않는다.** 분류·검증의 성패와 무관하게 **병렬로 즉시** `발송금지.md`에 올린다 — 법 요건이다.

**실행체 경계 4개**

| 경계 | 값 |
|---|---|
| 입력 | **T = 회신 1통씩** / **V = 원문(일본어)과 한국어 해석 둘만.** 분류 결과·판단 과정을 V에 주지 않는다 — **레코드 파일 경로를 주지 않고 그 두 조각만 뽑아 넘긴다**(경로를 주면 나머지 층을 읽을 수 있다) |
| 출력 | T·V가 채운 레코드 파일 1개 + 수신 거부면 `발송금지.md` 1행 추가 |
| 도구 권한 | 회신 텍스트 읽기 + 결과 파일 쓰기까지만. **발신 도구 권한이 없다** — *"답장을 보내지 않는다"*를 사후 점검이 아니라 권한으로 막는다 |
| 독립 컨텍스트 | **회신 1통 = 컨텍스트 1단위.** 그리고 **T와 V는 서로 다른 컨텍스트여야 한다** — 같은 컨텍스트에 두면 절을 나눠도 자기 검증이 그대로 남는다 |

## 출력 형식
**파일 1 — 회신 1통당 `replies/{수신일시}-{식별자}.md` 1개**
식별자는 **"어느 발송 건에 대한 답인가"(원문층) 판정 결과에서 가져온 G1 식별자**를 쓴다 — G1의 식별자 규칙(홈페이지 도메인)과 일치를 보장하는 유일한 경로가 이것이다. 그 판정이 **특정 불가**면 발신 메일 주소의 도메인을 **임시 식별자**로 쓰되, 파일명에 `-미확정`을 붙인다. **발신 도메인이 G1 식별자와 같다는 보장이 없다** — 미확정 건은 G11 집계에서 기업 단위로 조인하지 않고 별도 집계한다(`../specs/G11_반응집계_기준조정.md` 참조).

원문층
- 회신 원문(일본어, 받은 그대로) · 헤더 · 첨부 파일명 목록
- 참조 발신 정보 6항목 **또는 `참조 문안 없음`**
- 어느 발송 건에 대한 답인가 **또는 `특정 불가` + 사유**

해석층
- 한국어 해석 전문 — 원문과 **문장 대응이 유지되는** 번역. 매끄러움보다 대응을 우선
- 요지 3줄 이내
- **애매 표시** — 완곡·중립·다의적 구간과 가능한 읽기 병기

판단층
- 회신 성격 — C1 관심·진행 / C2 조건부 관심 / C3 거절(이유 있음) / C4 거절(이유 없음) / C5 담당자 아님·이관 / C6 자동응답 / C7 무관·스팸 / C8 판정 불가 **+ 근거 원문 인용**
- **수신 거부** — 거부 / 거부 아님 / 의심→거부 처리 **+ 근거 원문 인용**
- **자동응답 여부** — 예 / 아니오. **예면 이 회신을 사람 회신으로 세지 않는다**(뒤 집계가 이 칸을 읽는다)
- 상대의 요구·기한 + 회사가 지금 응대할 수 있는가 (모르면 `미확인`)
- **담당자 정보 갱신분**(있으면) · 판정 불가 사유 — **식별자가 확정된 건에 한해** `../specs/G4_연락처확보.md` 입력으로 넘어가 기존 연락처를 갱신한다. **식별자가 `-미확정`이면 넘기지 않고 이 레코드에만 남긴다** — 어느 기업 것인지 모르는 채로 넘기면 엉뚱한 `contacts/` 파일이 갱신될 위험이 있다
- **사용자 조치 요청** — *"무엇을 결정해야 하는가"* 형태. 요약이 아니다. **식별자가 `-미확정`이면서 담당자 정보 갱신분이 있는 경우, "어느 기업 연락처인지 수동으로 확인해 갱신하라"를 이 칸에 반드시 넣는다** — G4로 자동으로 넘어가지 않으므로 이 칸이 유일한 도달 경로다

검증층 (단위 V가 채운다)
- 번역 검증 3층 각각 일치 / 불일치 + 불일치 지점(원문 문장 ↔ 해석 문장) + 권고 처리. **해석이 없는 건(C8 판독 불가)은 `검증 대상 없음`**
- 처리일시 · **해석 주체 · 검증 주체** (서로 달라야 한다)

**파일 2 — `발송금지.md` (append 전용, 공용 1개)**
수신 거부가 「거부」 또는 「의심→거부 처리」이면 **여기에 한 줄 추가한다** — 메일 주소 / 근거 원문 인용 / 수신일시 / 출처 파일명.
**왜 별도 파일인가**: 거부 의사가 개별 레코드에만 있으면 발송할 때 누군가 전 레코드를 훑어야 하고, **그게 위법 발송이 나는 방식이다.** 이 파일에서 지우는 일은 없다(append 전용).

## 성공 기준
회신 1통마다 확인한다.

**무관용 — 하나라도 어기면 그 건을 사용자에게 보내지 않는다**
- [ ] 일본어 원문이 레코드에 그대로 있다 — 어기면 **오역을 검출할 수단이 사라져 되돌릴 수 없다**
- [ ] 부정·조건·가능/불가능의 방향이 뒤집히지 않았다 — 어기면 **거절을 관심으로 읽어 없는 기회를 쫓거나, 관심을 거절로 읽어 기회를 잃는다**
- [ ] 수신 거부·의심 건이 `발송금지.md`에 빠짐없이 추가됐다 — 어기면 **다음 발송이 일본 특정전자메일법 위반**

**위 셋은 검증층이 채워진 뒤에만 판정할 수 있다. 검증층이 빈 건은 사용자에게 보내지 않는다.**

**서식 점검 — 세어서 확인하고, 빠지면 채워서 다시 낸다**
- [ ] 고유명사·수치·날짜·금액·기한이 원문과 일치한다
- [ ] 해석에 원문과 대응하지 않는 문장이 없다 (추가·누락)
- [ ] 해석 칸에 판단 문장이 섞이지 않았다
- [ ] 원문이 완곡·중립인데 단정해 해석한 곳이 없다 (애매 표시)
- [ ] 회신 성격이 8분류 중 하나이고 근거 원문이 인용됐다
- [ ] 자동응답이 사람 회신으로 분류되지 않았다
- [ ] 해석 주체와 검증 주체가 다르다
- [ ] 사용자 조치 요청이 "무엇을 결정해야 하는가" 형태다 (요약뿐이면 다시 쓴다)
- [ ] 판정 불가가 분류와 다른 칸에 사유와 함께 있다
- [ ] 수신일시·발신 주소·스레드·처리 주체가 있다

> **답장을 보내지 않는 것은 성공 기준이 아니라 제약이다.** 사후에 세는 것이 아니라 **발신 도구 권한을 주지 않는 것**으로 막는다.

## 확인 후 채울 것
- 8분류가 실제 회신을 덮는지 ← **실제 회신 10건.** 그때까지 안 들어가는 회신은 `미분류`로 남긴다
- 상시 사람 검수 지점을 둘지 ← **일본어 응대 인력.** 지금은 사람 검수 없이 돌고, 사람은 실패 경로에서만 부른다
- 「우리가 지금 응대할 수 있는가」 칸을 채울지 ← **견적·계약·결제 준비 상태**
- 회신을 **어떻게 받는지** ← 붙여넣기로 시작. 메일함 자동 수신은 반자동 범위 확정 후
