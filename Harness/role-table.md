# 역할표 — G7 회신 해석·검증

| Skill(Subagent) | 역할 | 입력 형식 | 출력 형식 | 도구 권한 |
|---|---|---|---|---|
| `g7-회신처리` (Skill, 오케스트레이터 겸) | 회신 1통을 받아 T→V 순서로 호출, 검증 입력 추출(원문+해석만), 실패 3종 분기, 최종 레코드 병합, 성공 기준 자체 점검까지 담당 | 회신 원문 1통(헤더·첨부목록·참조발신정보 포함) | `replies/{수신일시}-{식별자}.md` 레코드 1개 + (수신거부 시) `발송금지.md` 1행 | 세션 상속 — 오케스트레이션·검증입력 추출 자체를 세션 권한으로 수행한다(아래 「알려진 한계」 참조) |
| `g7-회신해석` (Subagent, 단위 T) | 원문 보존 + 한국어 해석 + 회신 성격 8분류 + 수신거부·자동응답 판정. 검증층은 만들되 비운다 | 회신원문·헤더·첨부목록·참조발신정보(1회차) 또는 원문+불일치지점(2회차, 1회차 해석은 안 줌) | 레코드 파일(원문층·해석층·판단층) + 수신거부 시 `발송금지.md` 1행 | `Read, Write, Edit` — 발신·웹 도구 없음 |
| `g7-번역검증` (Subagent, 단위 V) | 번역 검증 3층(의미 보존 / 고유명사·수치 / 어조·방향) 대조, 불일치 지점 지목 | 프롬프트에 인라인된 원문 전문 + 해석 전문 **이 둘만** (파일 경로 없음, 판단층 없음) | 검증층 판정 텍스트 — 층별 일치/불일치 + 불일치 지점(원문 문장 ↔ 해석 문장) + 권고 | `Read`만 — 대조 기준(`기준.md`) 열람 외에는 아무것도 하지 않는다. 파일 쓰기·번역 교정 권한 없음 |

## 작성 방법 대조 (템플릿 4단계 확인)

1. **작업 분해 기준**: 기존에 하나의 실행으로 뭉쳐 있던 "번역하고 그 번역이 맞는지 스스로 확인하는" 작업을 T(번역)와 V(검증)로 쪼갰다. 기준은 절 구분이 아니라 **누가 그 판단을 내리는가** — 같은 주체가 번역하고 검증하면 자기 오역을 통과시킨다(`docs/33_설계근거.md` D7).
2. **객관적 계산 vs 주관적 판단**: 이 파이프라인엔 순수 객관적 계산(숫자 세기·합산) 단계가 없다 — 해석도 검증도 둘 다 사람 수준의 판단이 필요한 작업이다. 그래서 "스크립트로 유지"할 단계는 없고, 대신 **판단이 갈리는 두 판단(번역/검증)을 서로 다른 전담 서브에이전트로 분리**하는 쪽으로 이 원칙을 적용했다.
3. **입력·출력 정합성**: `g7-회신해석`의 레코드 출력(원문층+해석층) 중 두 항목만 뽑은 것이 `g7-번역검증`의 입력이고, `g7-번역검증`의 판정 텍스트가 그대로 레코드의 검증층 입력이 된다 — 표 형식이 단계 사이에서 어긋나지 않는다.
4. **도구 권한 최소화**: `g7-번역검증`은 번역을 고치지도, 파일에 쓰지도, 판단층을 보지도 못한다(`Read`만). 검증 실패 시 되돌리는 것은 T의 일이지 V가 스스로 고치는 게 아니다 — 권한을 좁혀 "V가 자기가 지적한 것을 자기가 고치는" 자기검증 재발을 원천 차단했다.

## 점검 체크리스트

- [x] 표에 관련 Skill/Subagent 모두 역할·입력·출력이 명확히 적혀 있는가
- [x] 한 Skill의 출력 형식이 다음 Skill의 입력 형식과 정확히 일치하는가
- [x] 한 Skill 안에 객관적 계산과 주관적 판단이 동시에 섞여 있지 않은가 — T·V 모두 판단 단위이므로 섞임 여부보다 **같은 판단을 같은 주체가 두 번 하지 않는가**로 확인했다
- [x] 도구 권한이 그 역할에 실제로 필요한 만큼만 부여되었는가 (`g7-번역검증`은 글을 고치지 않으므로 쓰기 권한이 없다)

## 알려진 한계 (숨기지 않고 남긴다)

`g7-회신처리`는 별도 서브에이전트가 아니라 **스킬 + 오케스트레이션**이라, 4단계(검증 입력 추출)를 세션 자신의 권한으로 수행한다 — T·V처럼 도구 권한이 파일 층에서 물리적으로 좁혀져 있지 않다. 지금은 실행 단위가 T·V 둘뿐이라 이 격차가 크지 않지만, 오케스트레이션 로직이 커지면 오케스트레이터도 별도 서브에이전트로 등록해 권한을 좁히는 편이 나을 수 있다(`워크플로우_절차서.md`의 에이전트 구성 절 참조).
