# g3-fit-scoring — 후보 1곳 채점, 후보 전체 정렬

이 스킬은 **정본 두 문서를 그대로 실행하는 호출 계약**이다 — 새 판정 규칙을 만드는 자리가 아니다.

- **구조(무엇을 만들고 어떤 형태로 내놓는가)**: `specs/g3-fit-scoring.md`
- **판정 값과 문장(채점 축, 축별 점수, 합산, 동점 처리, 채점 불가 처리)**: `criteria/g3-fit-scoring.md`

**매 실행마다 두 문서를 다시 읽는다** — 이 카드의 값은 전부 잠정이고 기업 답이 오면 크게 바뀐다. 이 스킬 본문과 두 문서가 어긋나면 **문서가 이긴다.**

**업종 라벨의 정본은 `criteria/g1-company-screening.json`의 `필수조건[3].매핑`이다** — G1이 산출물에 적어 넣는 값이 거기서 나온다. `criteria/g3-fit-scoring.md`의 점수표 라벨과 그 값이 문자 그대로 다르면 **아래 「멈추는 경계」에 걸린다.**

## 산출물 자리

- **입력**: `data/candidates/후보목록.md` — G1의 실제 산출물. Spec 「출력 형식」이 `data/candidates/후보목록.md`로 적은 그 파일이다.
- **출력**: `data/scores/{기업식별자}.md`(채점) · `data/scores/순위표-{작성일}.md`(정렬). G1·G2 산출물과 같은 디렉터리 층에 둔다. 디렉터리가 없으면 만든다.

**Spec 「출력 형식」은 순위표에 디렉터리를 적지 않았다.** 채점 파일과 같은 자리에 두는 것으로 잠정 처리했다 — 사람이 다른 자리를 정하면 그쪽이 이긴다.

## 인자 — 모드가 둘이고 컨텍스트 단위가 다르다

```
/g3-fit-scoring cocacoca-jp        # 채점 모드 — 기업 1곳
/g3-fit-scoring 정렬                # 정렬 모드 — 채점된 후보 전체
```

**인자에 기업이 둘 이상 식별되면 실행하지 않고** "기업 1곳씩 나눠 호출해 달라"고 되돌린다 — Spec의 「기업 1곳 = 채점 1단위, 앞 기업의 채점이 다음 기업 채점에 남지 않게 한다」 경계를 실행 층에서 지키는 조치다. **인자가 없으면 어느 모드인지 확정하지 않고 되돌린다.**

**채점 모드에서 다른 기업의 채점 결과를 열지 않는다.** 후보 목록에서도 해당 기업 섹션만 조회한다(파일 전체를 컨텍스트에 넣지 않는다) — 규모 축은 「극단적으로 작다」를 보는 축이라, 옆 기업의 값이 컨텍스트에 남으면 그것이 곧 없는 판별선의 자리를 대신한다.

## 규칙이 없는 경계에서 멈춘다 — 이 스킬의 가장 중요한 문장

**카드가 침묵하는 자리에서 점수를 만들어 채우지 않는다.** 만드는 순간 그 점수는 어디에도 근거로 남지 않고, 순위가 그 발명 위에 세워진다. 아래에 걸리면 **그 축을 비우고 「보류 — 카드에 규칙 없음」과 무엇이 없는지를 채점 파일에 적은 뒤 사용자에게 올린다.**

| 자리 | 멈추는 조건 |
|---|---|
| **업종 축 라벨** | G1 관찰값의 업종 라벨이 카드 점수표의 라벨과 **문자 그대로 일치하지 않을** 때. 두 라벨이 같은 것을 가리키는지 이 실행체가 판단하지 않는다 — 판단하는 순간 어느 카드도 딛지 않은 매핑이 하나 생긴다 |
| **규모 축** | 카드가 「극단적으로 작다」의 **선이 없다고 명시**한 자리. 그 선을 이 실행에서 만들어 감점 여부를 가르지 않는다. 관찰값은 그대로 옮겨 적고 점수만 비운다 |
| **재료가 G1에 존재하지 않는 축** | 카드의 채점 불가 규칙은 관찰값이 `?`(판정 불가)로 **남아 있는** 경우를 다룬다. **「관찰 항목 자체가 없다」는 그것과 다른 상태**이므로 같은 칸으로 합치지 않는다 — 「관찰 안 함」과 「관찰했는데 0」을 하나로 묶으면 0점이 근거를 얻는다 |

**축을 비우는 것과 전체를 막는 것은 다르다.** Spec 「제약」과 실패표가 *"그 축만 비우고 전체를 막지 않는다"*로 정해 두었다 — 비운 축은 합산에서 빼고, 나머지 축으로 합산해 순위를 낸다. **보류·채점 불가 축이 몇 개였는지는 반드시 채점 파일과 순위표 양쪽에 남긴다.**

## 실행 — 채점 모드

1. 후보 목록에서 **기업식별자로만 조회**해 그 섹션을 연다. 섹션이 없으면 실행하지 않고 되돌린다.
2. **규칙층의 후보 판정이 「포함」이 아니면 채점하지 않고 종료한다.** Spec 「입력」이 통과분만 받는다고 정했고, 성공 기준이 이것을 0건으로 센다. **여기서 판정을 다시 하지 않는다** — 제외·판정 불가를 뒤집는 것도 이 기능의 일이 아니다.
3. 카드가 정한 축·점수·합산 방식으로 채점한다. 위 「멈추는 경계」에 걸린 축은 점수를 비우고 사유를 적는다.
4. `data/scores/{기업식별자}.md`를 쓴다. 항목·구조는 Spec 「출력 형식」의 파일 1 그대로이며, **점수마다 「어느 관찰값이 어느 방향으로 작용했는가」를 붙인다**(Spec 「제약」이 근거의 정의를 그렇게 두었다).
5. **머리에 「시험 실행 — 확정 순위 아님」과 사용한 채점 기준이 잠정판임을 명시한다.** 카드가 *"이 규칙으로 낸 순위를 확정 순위로 쓰지 않는다"*고 못박았고, 이 표시가 없으면 뒤 작업(G4 탐색 순서·G5 발송 순서·G9·G10)이 시험 결과를 확정 순위로 받는다.
6. **자체 점검.** `specs/g3-fit-scoring.md` 「성공 기준」의 채점 산출물 항목으로 대조하고 **대조 결과를 산출물 안에 남긴다.** 걸리는 항목은 고치고 다시 확인한다.

- **위 「멈추는 경계」에 걸려 비운 축은 고쳐서 통과시키지 않는다.** 보류를 없애려면 카드에 없는 점수를 만들어야 하고, 그것이 이 경계가 막으려는 바로 그 일이다.
- **표본 검사 항목(같은 기업을 두 번 채점해 대조)은 이 실행에서 자체 판정하지 않는다** — 절차를 점검할 때 도는 것이고, 한 컨텍스트에서 두 번 채점하면 두 번째가 첫 번째를 보고 있어 대조가 성립하지 않는다.

## 실행 — 정렬 모드

1. `data/scores/` 아래 채점 파일 전체를 모은다. **여기서는 전체를 한 컨텍스트에 놓는다** — 정렬 자체가 상대 비교라 그래야 성립한다(Spec 「독립 컨텍스트」 경계).
2. **채점 파일에 적힌 합산 점수를 그대로 쓰지 않고, 축별 점수로 한 번 다시 계산해 대조한다.** 성공 기준이 재계산 불일치를 0건으로 세는 자리다. 어긋나면 그 건은 순위에 넣지 않고 어긋난 사실을 적는다.
3. 카드가 정한 대로 정렬하고 **동점은 그룹으로 묶어 표시한다.** 그룹 안의 순서를 만들지 않는다 — Spec 실패표가 *"임의 순서로 정하지 않고 사람에게 넘긴다"*로 닫아 두었다.
4. **합산할 축이 하나도 남지 않은 기업은 순위에 넣지 않고 「채점 불가로 빠진 건」으로 센다.** 0점으로 내려 꼴찌에 두지 않는다 — 그건 필터가 되고, 이 기능은 통과분을 다시 떨어뜨리지 않는다.
5. `data/scores/순위표-{작성일}.md`를 쓴다. 항목은 Spec 「출력 형식」의 파일 2 그대로. **채점 파일과 순위표 행은 1:1로 연결된다** — 짝 없는 행을 만들지 않는다.
6. **자체 점검.** 성공 기준의 정렬 산출물 항목으로 대조하고 결과를 산출물 안에 남긴다.

## 보고

**동점 그룹의 크기와 비운 축의 개수를 중심으로 전한다.** 이 기능의 존재 이유가 *"접촉 순서를 적합도로 정한다"*이므로, **순위가 실제로 갈렸는지 아니면 대부분 동점으로 남았는지**가 사용자에게 도달해야 이 실행이 끝난다. 「멈추는 경계」에 걸려 보류한 축이 무엇인지도 함께 올린다.

## 이 스킬이 하지 않는 것

`specs/g3-fit-scoring.md` 「범위」의 제외 목록과 같다 — 새로운 관찰(G1의 일. 이 스킬에는 웹 권한이 없다), **후보를 탈락시키는 것**(필터는 G1에서 끝났다), 세그먼트 배정(G2), 연락처 탐색·발송 가능 판정(G4), 메일 제작·발송(G5), 소비처별 기준선 적용(척도는 하나만 낸다), **축·가중치를 스스로 조정하는 것**(G11이 제안하고 사람이 승인한 뒤에만 바뀐다). 그리고 **판정 기준 문장 자체를 고치는 일**(시험 실행에서 드러난 결함은 사람이 `criteria/g3-fit-scoring.md`에 직접 고치고, 바꾼 줄과 이유를 그 카드 변경 이력에 남긴다).
