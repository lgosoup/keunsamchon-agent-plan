# g4-연락처확보 — 기업 1곳의 연락 창구 확보·발송 가능 여부 판정

이 스킬은 **정본 두 문서를 그대로 실행하는 호출 계약**이다 — 새 판정 규칙을 만드는 자리가 아니다.

- **구조(무엇을 만들고 어떤 형태로 내놓는가)**: `specs/G4_연락처확보.md`
- **판정 값과 문장(유효 등급 3종, 옵트인 예외 판정 5단계, 미확보 사유에 무엇을 적는가)**: `기준/G4_연락처유효성기준.md`

**매 실행마다 두 문서를 다시 읽는다.** 이 스킬 본문과 두 문서가 어긋나면 **문서가 이긴다.**

**거부 표시 문구 목록은 이 카드에 없다** — `기준/G4_연락처유효성기준.md` 0절이 `기준/G1_기업판정기준.json`을 정본으로 지목했다. 그 파일도 매 실행마다 함께 읽는다.

## 산출물 자리

G1 산출물(`specs/candidates/후보목록.md`)과 같은 디렉터리 층에 둔다 — `g7-회신처리`가 `replies/`를, `g2-세그먼트화`가 `segments/`를 놓은 것과 같은 규칙이다.

| 무엇 | 자리 |
|---|---|
| 입력 — G1 통과분 | `specs/candidates/후보목록.md` (식별자로 해당 섹션만 조회) |
| 입력 — G2 세그먼트 정의 | `specs/segments/SEG-{축코드}-v{버전}.md` 중 **가장 최신 버전 1개** |
| 입력 — 수신 거부 목록 | `specs/발송금지.md` |
| 입력 — G9 사람이 찾아온 주소 (있으면) | `specs/연락처후보/{기업식별자}.md` |
| 출력 — 상태와 무관하게 항상 | `specs/contacts/{기업식별자}.md` (디렉터리가 없으면 만든다) |
| 출력 — [메일 없음]·[미확보]만 추가로 | `specs/candidates/보류목록.md` 표에 **한 줄 append** |

- **`specs/발송금지.md`가 아직 없으면 등재 0건이다.** 파일 부재를 확인 근거로 그대로 적는다(`발송금지.md 없음(등재 0건) 확인 — {확인일}`). 없는 파일을 이 스킬이 만들지 않는다 — 그 파일은 G7·G1이 쓰는 자리다.
- **쓰기 대상은 위 두 출력뿐이다.** `후보목록.md`·`segments/`·`발송금지.md`는 읽기만 한다.
- **`보류목록.md`는 기존 줄을 읽지도 고치지도 않는다**(그 파일 머리의 소유권 규칙). 표 끝에 한 줄만 더한다.

## 인자

```
/g4-연락처확보 cocacoca-jp
/g4-연락처확보 "株式会社サンプル" https://sample.co.jp     # 후보 목록에 아직 없는 기업
```

**인자에 기업이 둘 이상 식별되면 실행하지 않고** "기업 1곳씩 나눠 호출해 달라"고 되돌린다 — Spec의 「기업 1곳 = 작업 1단위」 경계를 실행 층에서 지키는 조치다.

## 실행

**1. 대상 확인.** `specs/candidates/후보목록.md`에서 **식별자로만 조회**해 그 섹션만 읽는다(파일 전체를 컨텍스트에 넣지 않는다 — 앞 기업의 창구 패턴이 이번 판정에 남는다). 확인할 것은 **후보 판정 값**과 **O8 관찰값**, **G1이 열어본 URL 목록** 셋이다.

- **후보 판정이 「포함」이 아니면 실행하지 않고 되돌린다** — Spec 「입력」이 받는 것은 G1 통과분이다. 「판정 불가」는 통과분이 아니라 재관찰 대상이다.

**2. 탐색 순서 게이트 — G2가 정한 순서를 실행 층에서 강제한다.** 최신 세그먼트 정의 파일에서 이 기업이 **어느 무리의 소속인지, 대표인지**를 조회한다.

| 이 기업이 | 처리 |
|---|---|
| 어느 무리의 **대표** | 그대로 진행 |
| 어느 무리의 **소속(대표 아님)** | 그 무리의 **대표 기업 `specs/contacts/{대표식별자}.md`가 이미 있는지** 확인한다. **없으면 실행하지 않고 "대표({대표식별자})를 먼저 돌려 달라"고 되돌린다** — Spec 「성공 기준」의 *"순서 위반 0건"*은 호출 사이의 순서라 이 자리에서만 지켜진다 |
| **미분류**(어느 무리에도 없음) | 그대로 진행한다. **Spec이 정하지 않은 자리에 대한 이 실행체의 처리다** — 대표 우선 규칙은 무리 안의 순서라 소속이 없는 기업에는 걸리지 않는다. 사람이 Spec 「입력」에 미분류의 순서를 써 넣으면 그쪽이 이기고 이 줄은 지운다 |

**세그먼트 정의 파일 머리에 「시험 실행 — 확정 배정 아님」 표시가 있으면 그 사실을 산출물의 「세그먼트 소속」 칸에 그대로 옮겨 적고 보고에서도 말한다.** 거르지도 멈추지도 않는다 — **Spec 「입력」에 시험 실행본을 거르는 조건이 없어 이 실행체가 그 조건을 만들면 발명이 된다**(`docs/90_미결정과_리스크.md` 3절 ⑬, G2 빌드에서 이관된 미해결 항목). 지금 할 수 있는 것은 잠정 배정으로 정한 순서가 산출물에 흔적을 남기게 하는 것뿐이다.

**3. 사람이 찾아온 주소를 먼저 받는다.** `specs/연락처후보/{기업식별자}.md`가 있으면 그 주소를 **원값 그대로** 후보에 넣는다. 다시 찾지는 않되 4·5번을 똑같이 거친다 — 사람이 찾아왔다는 이유로 등급 판정과 거부 표시 확인을 건너뛰는 지름길을 만들지 않는다(Spec 「입력」).

**4. 창구 탐색.** 공식 홈페이지를 먼저 본다 — 문의·회사 개요·회사 소개, 그리고 **일본 사이트에서 이메일 주소가 실제로 공개되는 자리**인 특정상거래법 표기(特定商取引法に基づく表記)·개인정보 방침 페이지. 여기서 안 나오면 Spec 「범위」가 연 딥서치(공개 SNS·업계 디렉토리·기업 정보 사이트)로 확장한다.

- **G1이 이미 열어본 URL은 다시 열지 않아도 되지만, G1의 O8 판정을 다른 주소에 옮겨 쓰지 않는다** — 카드 2절 1·2행이 그 둘을 가르는 자리다.
- **연 URL을 전부 기록한다.** [미확보]로 끝날 때 이 목록이 곧 산출물의 본체다(카드 3절).

**5. 주소마다 세 가지를 순서대로 확인한다.** 주소를 찾을 때마다 이 순서로 돌고, 어느 하나라도 걸리면 거기서 그 주소의 판정이 끝난다.

1. **`specs/발송금지.md`에 이미 있는가** → 있으면 새로 관찰할 것 없이 **[발송 금지]**(Spec 「제약」).
2. **거부 표시가 있는가** → 판정은 카드 2절, 문구 목록은 `기준/G1_기업판정기준.json`.
3. **어느 등급인가** → 카드 1절.

**6. 상태를 확정하고 파일을 쓴다.** 4상태와 각 상태가 요구하는 항목은 Spec 「출력 형식」 그대로다. **상태와 무관하게 `specs/contacts/{기업식별자}.md`를 항상 쓴다.**

**7. [메일 없음]·[미확보]는 `보류목록.md`에도 한 줄 append한다.** 「어느 기능」 칸은 `G4`, 「다시 볼 것」 칸에는 다음 사람이 볼 자리를 적는다.

**8. 자체 점검.** `specs/G4_연락처확보.md` 「성공 기준」 체크리스트로 이 산출물을 대조하고, **대조 결과를 산출물 안에 남긴다** — 파일만 받은 사람이 점검이 돌았는지 알 수 있어야 한다. 걸리는 항목은 고치고 다시 확인한다.

- **`보류목록.md` append 항목은 그 파일을 실제로 다시 열어 그 줄이 있는지 확인하고 통과시킨다.** 산출물에 *"append 완료"*라고 쓴 것을 근거로 자기 점검을 통과시키지 않는다 — 그러면 쓰기 실패가 통과로 기록된다(실제로 한 번 발생: `docs/90_미결정과_리스크.md` 3절 G4 ③).

- **표본 검사(같은 기업을 두 번 돌려 상태가 같은가)는 이 실행에서 자체 판정하지 않는다** — 절차를 점검할 때 사람이 도는 항목이다.

**9. 보고.** **상태 1개와 그 상태가 어디로 가는지**(Spec 「출력 형식」의 다음 기능 연결)를 중심으로 전한다. [발송 금지]면 무엇을 보고 그렇게 판정했는지가, [미확보]면 어디까지 찾아봤는지가 사용자에게 도달해야 이 실행이 끝난다.

## 규칙이 없는 경계에서 멈춘다

**카드가 침묵하는 자리에서 판정 문장을 스스로 만들지 않는다.** 아래에 걸리면 그 건을 확정하지 않고 산출물에 「판정 보류 — 카드에 규칙 없음」과 무엇이 없는지를 적은 뒤 사용자에게 올린다.

| 자리 | 멈추는 조건 |
|---|---|
| **유효 등급** | 카드 1절의 어느 행에도 대응하지 않는 창구를 등급으로 올려야 할 때. **애매함은 여기 해당하지 않는다** — 카드가 이미 「낮은 등급(일반)」으로 처리하라고 정했고, 「주소가 있는가 / 폼만 있는가」는 애매함의 대상이 아니라고 못박았다 |
| **옵트인 예외** | 카드 2절 5행(판정이 갈림)에도 해당하지 않는 새로운 유형이 나올 때. **갈리는 것 자체는 멈추는 조건이 아니다** — 카드가 [발송 금지]로 정해 두었다 |

- **이메일도 문의 폼도 없이 전화·팩스·SNS 계정만 있는 경우는 [미확보]다** — 카드 1절 미확보 행(*"위 셋 다 확인 안 됨"*)의 문언에 그대로 걸린다. 다만 **무엇이 있었는지(전화만 있었다 등)를 사유에 적는다** — 그 정보가 있어야 G9가 다음에 어디를 볼지 판단한다. **이 경우가 카드 1절의 「창구 자체를 못 찾음」이라는 괄호 설명과는 어긋나 보인다는 점은 보고에 함께 올린다.**
- **법인 공개 창구가 아닌 주소는 후보에 넣지 않는다**(Spec 「제약」). 그렇게 걸러 남는 주소가 없으면 [미확보]이며, **거른 주소의 값을 산출물에 옮겨 적지 않고** 「법인 창구가 아닌 주소만 확인됨」이라고만 적는다.

## 이 스킬이 하지 않는 것

`specs/G4_연락처확보.md` 「범위」의 제외 목록과 같다 — 연락처의 가치 판단·순위(G3), 메일 제작·발송(G5), **웹 문의 폼에 내용을 채워 제출하는 것**, 개인 연락처 수집, 유료 DB 조회. 그리고 **판정 기준 문장 자체를 고치는 일**(실제로 탐색해 본 사람이 `기준/G4_연락처유효성기준.md`에 직접 고치고 그 카드 4절 변경 이력에 남긴다).
