# H9 — criteria 수정 감지 → 정합성 검토 질문 전달

| 항목 | 내용 |
|---|---|
| 트리거 종류 | 이벤트 |
| 트리거 조건 | `criteria/*.md` 파일이 수정됨 |
| 캡처할 신호 | 수정된 파일명 + 변경 전/후 값(diff) — 어느 항목·값이 바뀌었는지 |
| 호출 대상 | `/g12-qna` |
| 인자 형식 | 정합성 검토 요청 형태의 질문 텍스트로 조립해 전달 — 예: `<파일명>의 <항목>이 <이전 값>에서 <새 값>으로 바뀌었다. 이 변경이 다른 기준·스펙과 충돌하는지 검토해줘` + diff 원문을 이어서 붙임 |
| 비고 | `g12-qna`는 질문이 어디서 왔는지(Hook/사람) 구분하지 못한다 — 이 Hook이 조립한 질문도 사람이 직접 물은 것과 똑같이 "질문 1건"으로 처리된다(`../specs/g12-qna.md` 「제약」·실패표 예외). **효과 예측(회신율 개선 여부 등)까지 묻는 문구는 조립하지 않는다** — 정합성 대조 질문만 만든다. `g12-qna`는 그 질문에 답할 뿐 criteria 파일을 직접 고치지 않는다(승인·반영은 여전히 사람 몫) |

**실제 구현 예시**: `settings.json` + `hook_h9_criteria_review.sh`(같은 폴더). 11개 Hook 중 이것만 Claude Code 자체 메커니즘으로 실제 동작하는 예시가 있다 — 나머지는 이 실행 환경 밖의 사건이라 이 형태로 구현할 수 없다.
