2. **"현지화 가능성"과 "커뮤니케이션 방식"은 B 기존 계획서·C 팀원 초안 어디에도 반영되지 않았다.** 현지화 가능성은 상담에서 논의됐으나 카톡 로그에 남지 않아 A 정리에서도 누락된 항목이므로, 국가 선정 기준의 축 하나를 새로 만들어야 한다.
3. **B의 정량 기준(50개 SKU, 0.85 유사도, 7영업일, 90일 등)이 C에는 전부 빠져 있다.** C의 서술이 더 매끄럽지만 "근거 있는 자료로 기준을 만들라"는 A의 원칙과 충돌하므로, C의 구조 + B의 수치로 합친다.

## 2. 확정 뼈대 — 문제정의 → 해결 아이디어 → 기업 활용 제안

```
[문제 정의]
  큰삼촌컴퍼니의 진짜 문제 = "조사가 느리다"가 아니라
  "신뢰할 근거 위에서, 다음 세 조건을 동시에 만족하는 기업을 원점에서 찾아야 한다"
    (1) K문화를 받아들일 수 있는 시장에 있는가
    (2) 큰삼촌컴퍼니가 현지화로 대응할 수 있는 상대인가
    (3) 그 기업 자체가 해외 확장 여력이 있는가
  + 찾아낸 뒤에도 "생소한 한국 스타트업을 왜 신뢰해야 하는가"를 먼저 설득해야 한다

[해결 아이디어] — 필수구현 2축
  ① 기업조사(찾기)  : 접근범위 → 국가선정 → 조사 이원화 → 기업발굴
  ② 메일 보내기      : 매칭 → 메일 방식 결정 → 커뮤니케이션 방식 결정 → 발송 → 반응처리
  + 관통 원칙       : 수동 우선 설계 → 자동화 / 방법론 비교검증을 결과물로

[기업 활용 제안]
  장점·효율·필요성을 "직접 주장"하지 않고
  담당자의 실제 업무 동선 위에 올려놓아 스스로 느끼게 서술
```

## 3. 문제 정의 — 정리 (D 본인 뼈대 중심 + B의 근본원인 분석)

기존 B에 이미 있는 논리(동대문 오프라인 네트워크 기반 → 해외는 고객기반·다국어 인력 없이 원점 시작 → 신뢰 인식이 비용 논리보다 먼저)는 유지하되, **D가 제시한 "찾아야 하는 기업의 3조건"을 문제 정의의 중심으로 올린다.** 이유: 이게 있으면 뒤의 모든 선정 기준이 여기서 파생되는 구조가 되고, 없으면 "그냥 패션 기업 찾기"로 읽힌다.

| 조건 | 왜 문제인가 | 어디서 판단하는가 |
|---|---|---|
| ① K문화 수용성 | 제품이 좋아도 K-패션 자체에 대한 수용도가 낮은 시장이면 설득 비용이 과도하다 | 4절 ② 국가 선정 |
| ② 현지화 가능성 | 큰삼촌컴퍼니가 언어·결제·물류·규제 측면에서 실제로 대응 가능한 상대여야 계약이 성립한다 | 4절 ② 국가 선정 + ④ 기업 발굴 |
| ③ 기업의 확장 여력 | 상대 기업이 신규 소싱·해외 확장 의지가 없으면 제안 자체가 무의미하다 | 4절 ④ 기업 발굴 |

여기에 B의 구현 난점 3가지를 그대로 붙인다: (a) 공개 정보만으로는 실제 의사결정권자 연락처 확보가 어렵다, (b) 국가별 콜드메일 규제를 고려해야 한다, (c) 비용 절감 논리보다 신뢰 인식이 먼저 필요하다.

## 4. 해결 아이디어 — 통합 목차

C 팀원 초안의 ①~⑥ 순서를 골격으로 쓰고, B의 상세 로직과 D의 신규 요소를 각 자리에 채워 넣는다. 결과적으로 **①~⑦** 구조가 된다.

### ① 접근 범위 — 단일 국가 집중
- C ① 그대로 채택. 근거 문장도 좋다: 여러 국가를 동시에 다루면 자동화 로직이 국가별 예외 처리로 복잡해지고 근거도 얕아진다.
- A의 원칙 추가: 한 국가에서 방법론을 **검증한 뒤** 다른 국가로 확장 가능한 구조 (= 청사진 재사용, 기업 활용 제안의 핵심 논거가 여기서 나옴).

### ② 국가 선정 기준 — 코트라 + 다각도 지표 (D 반영으로 확장)
C ②를 3개 축으로 재편한다. **축 1만 있던 것을 축 2·3으로 확장하는 것이 D의 기여.**

| 축 | 보는 것 | 후보 지표 (실제 확보 가능성 확인 필요) |
|---|---|---|
| 축1 — 시장 수요 | 패션 B2B 품목 수요·성장세 | 코트라 국가·산업 정보, 의류/패션 품목 수출입 통계, 시장 성장률 |
| 축2 — **K문화 수용성** | K패션만 보지 않고 K문화·K뷰티·K콘텐츠까지 넓혀 "K를 이미 받아들이고 익숙한 시장인가" | 한류 관련 실태조사, K뷰티·K콘텐츠 수출 실적, 현지 한류 소비 지표 |
| 축3 — **현지화 가능성** | 큰삼촌컴퍼니가 실제로 대응 가능한가 | 언어(영어 통용도), 이커머스·결제 인프라, 물류 소요, 수입 규제·인증 장벽 |

- **핵심 논리**: 축2가 D의 "K문화를 받아들일 수 있고"에, 축3이 "현지화도 가능한"에 대응한다. 세 축을 함께 봐야 "수요는 있지만 대응이 불가능한 시장" 또는 "대응은 쉽지만 K에 무관심한 시장"을 걸러낼 수 있다.
- A의 원칙: 감이 아니라 정량 근거로 정한다. 각 축에 실제 수치와 출처가 붙어야 한다.
- **확인 필요(리스크)**: 코트라 데이터의 접근 범위. A에서 "우리가 코트라에 정보요청이 안 된다"고 정리했으므로, 공개 열람 가능한 범위가 어디까지인지 확인하고 대체 소스(공개 무역통계 DB 등)를 함께 준비해야 한다 → 이 대체 소스 비교 과정 자체가 ⑦의 재료가 된다.

### ③ 조사 방식 이원화 — "국가 선정"과 "기업 발굴"은 다른 문제
- C ③ 그대로 채택. A의 원칙과 정확히 일치한다.
- 국가 선정 기준 = ② (공신력 있는 무역·문화 데이터 기반 정량 지표)
- 기업 선정 기준 = ④ (취급 품목 적합성 + 온라인 활성도 + 규모, 정성·정량 혼합)

### ④ 기업 발굴 기준 — B의 신호 수집을 여기에 배치
C ③의 "기업 선정 기준"을 B의 구체적 수집 필드로 채운다. C에는 기준 이름만 있고 판별 방법이 없다.

| 수집 신호 | 관찰 방법 (B에서 그대로) | 문제정의 어느 조건에 대응 |
|---|---|---|
| 이미지 전문성 등급 | 통일된 스튜디오 배경·조명·구도 있으면 "전문", 제품만 놓거나 실사용 환경 배경이면 "비전문" | ③ 확장 여력 / AI-Studio 니즈 |
| 판매채널 수 | 공식몰·마켓플레이스·오프라인 등 홈페이지 명시 채널 개수 | ③ 확장 여력 / ERP 니즈 |
| 취급 SKU 규모 | 카탈로그 노출 상품 수, 50개 이상이면 "큼" | ③ 확장 여력 |
| (신규 검토) 다국어·해외배송 여부 | 홈페이지 언어 옵션·해외배송 안내 유무 | ② 현지화 가능성 / ③ 확장 여력 |
- 탐색 소스: 코트라는 **국가 선정**용, 개별 기업 발굴은 국가별 패션 도소매 디렉토리·협회·전시회 참가기업 목록 + 개별 홈페이지 보완 (B에서 이동).
- 트렌드 변화 시 후보군 자동 재조정 로직 (A·C 공통) — 초기 방대한 조사 + 이후 변화 감지 시 갱신의 2단계 구조.

### ⑤ 메일 방식과 커뮤니케이션 방식 결정 (D 신규 — 5절에서 최종 결정)
D가 제시한 2축을 별도 항목으로 신설한다. C·B에는 "맞춤형 메일"이라는 결론만 있고 **왜 그 방식인지 대안 비교가 없다.** A의 "여러 대안 비교 후 최적 선택 과정을 보여줘라"는 원칙에 정확히 걸리는 지점이므로, 선택지를 드러내고 근거와 함께 고르는 형태로 쓴다.

- **축1 — 메일 형식**: (a) 전원 동일 메일 / (b) 타겟별 맞춤 메일 / (c) 자사 소개 자료 동봉 + "협업하자"는 시그널형
- **축2 — 커뮤니케이션 깊이**: (a) 단발성 제안 / (b) "우리 회사는 이렇고, 귀사는 이런 것이 필요해 보이며, 그래서 이 조합이 유효하다"는 **분석 내용을 메일에 포함**
- 이 두 축의 선택 결과가 B의 매칭 로직(Clo.D vs AI-Studio) + 톤 결정 + 언어 정책과 연결된다.

### ⑥ 수동 프로세스 우선 설계 → 자동화 (A·C 공통, A의 논리가 더 강함)
- C ④의 서술이 이미 좋다. 여기에 A의 정의를 명시적으로 넣는다: **자동화 = 일반화. 무엇을 일반화할지 알려면 사람이 먼저 그 일을 해봐야 한다.**
- 제약과 절충: 학생 신분·시간 제약 + 코트라 등 일부 데이터 접근 제한 → 수동 프로세스는 **계획 단계로 설계**하고, 해커톤 실제 구현은 그 계획에 근거한 자동화 파이프라인으로 진행.
- 이 절충의 정당화(A 원문 논리): 실제로 수동으로 했을 때 성공하는 단계가 무엇인지를 먼저 설계해두고, 자동화가 그 성공 단계를 재현하도록 만든다. 나중에 실제 수동 검증 결과가 나오면 그에 맞춰 자동화를 확장할 수 있다는 것까지 보여준다.
- 자동화 파이프라인 전체 순서 (B + C ⑤ 병합):
  `국가 확정 → 기업 자동 탐색·리스트업 → 정보 구조화(신호 수집) → 기준별 자동 분류·우선순위화 → Clo.D/AI-Studio 적합도 판별 → 메일 방식·톤 결정 → 맞춤 메일 생성 → 승인 후 발송 → 반응 트래킹 → 후속 대응 → 결과 집계·기준 개선`
- **반자동 원칙 유지(B)**: 발송은 항상 사용자 승인. 기업과제 원문이 "반자동"을 요구했으므로 완전 자동 발송 경로는 두지 않는다.
- 반응 처리(B 수치 + A 채널 확장): 7영업일 내 회신 없으면 미응답 분류 → 14일 시점 팔로우업 메일(승인 필요). A에서 "읽지 않았을 때 전화할 것인가"까지 논의됐으므로 메일 외 채널 후속 조치 여부도 5절에서 결정.

### ⑦ 방법론 검증 과정 자체를 결과물로 제시 (A 핵심 + C ⑥)
- C ⑥ 그대로 채택. A의 예시 논리가 그대로 들어맞는다.
  - (O) "코트라도 구상하고 다른 데이터 소스도 검토해 시뮬레이션했더니 코트라가 정확도·데이터양 모두 우수했다"
  - (X) "그냥 코트라를 썼습니다"
- 포함할 검증 항목: 데이터 소스 비교 결과 / 어떤 AI를 왜 썼는지 / 생성 결과물의 정확성 검증 방법 / 기준 수치(50개, 7영업일 등)를 무엇에 근거해 정했는지.
- B의 v1~v3 시뮬레이션 반복 검증 기록도 같은 성격이므로 재활용 가능.

## 6. 기업 활용 제안 — 논리 뼈대

**서술 원칙(본인 지시)**: "우리 기획이 효율적이고 필요하다"를 직접 주장하지 않는다. 담당자의 실제 업무 동선 위에 결과물을 올려놓고, 읽는 사람이 스스로 필요성을 느끼게 한다. → **"~할 수 있습니다 / ~하지 않아도 됩니다"의 사실 서술로만 쓰고, "효율적입니다 / 필수적입니다" 같은 평가어는 쓰지 않는다.**

C 팀원 초안의 활용 제안 4단락이 이 원칙에 이미 잘 맞는다. 순서를 아래로 정리하고 B·D 요소를 보강한다.

| 순서 | 논거 | 어디서 왔는가 | 느끼게 하려는 것 |
|---|---|---|---|
| 1 | 해외 진출 시 반복 수행해야 하는 잠재고객 탐색·제안 메일 작성의 시간·인력 부담을 줄이는 데 활용 | C 1단락 | 지금 이 업무가 반복 노동이라는 자각 |
| 2 | 한 국가에서 검증된 프로세스를 **동일한 청사진(국가 선정 기준 → 기업 탐색 → 메일 생성 → 트래킹)으로 다른 국가에 재사용** → 신규 시장마다 조사 체계를 처음부터 다시 세울 필요가 없다 | C 2단락 + A "확장 가능 구조" | 1회성 결과물이 아니라 자산이 된다는 감각 |
