# g11-반응집계 — 반응률 집계 + 기준 조정 제안

이 스킬은 **정본 문서를 그대로 실행하는 호출 계약**이다 — 새 판정 규칙을 만드는 자리가 아니다.

- **구조(무엇을 만들고 어떤 형태로 내놓는가) + 제약 + 실패 3종**: `specs/G11_반응집계_기준조정.md`
- **판정 문턱 없음 — 짝 기준 카드가 없다**(`specs/README.md` 파일 표). G9·G10·G12와 같은 처리다. 다만 그 셋과 다른 점이 하나 있다: **이 기능에는 값이 있어야 할 임계값이 실제로 둘 있다**(최소 표본 크기 · 신호 상충 판정선). **2026-08-11 정정 — 이전엔 이 둘이 "아직 없다"고 적혀 있었는데 틀렸다.** `docs/92_기업답변_대기_임의값.md`·`docs/93_구현_검증대기.md`의 2026-08-10 "기업 답 대기 정책 전환"으로 `specs/G11_반응집계_기준조정.md` 「지금 쓰는 값」에 **이미 임의값이 채워져 있다**(최소 표본 5건, 신호 상충 20%p) — 이 SKILL.md만 그 갱신을 반영하지 못한 채 남아 있었다(`.claude/skills/g2-세그먼트화/SKILL.md`가 겪었던 것과 같은 종류의 드리프트, H9가 그때 잡아낸 패턴). **값이 임의값에서 확정값으로 바뀌면** 그 자리는 이 스킬 본문이 아니라 `기준/` 카드로 옮긴다(`.claude/README.md` 「Skill이 조건 값을 다루는 방법」) — 지금은 아직 Spec 「지금 쓰는 값」에 있으므로 카드를 새로 만들지 않는다.

**매 실행마다 위 Spec을 다시 읽는다.** 이 스킬 본문과 Spec이 어긋나면 **문서가 이긴다.** 실패 3종 표는 Spec 「제약」이 정본이며 **여기 옮겨 적지 않는다.**

## 이미 난 결론을 다시 판정하지 않는다 — 이 경계가 이 기능의 존재 이유다

- **G6 상태·G7 회신 성격·G8 원인 가설을 그대로 센다.** 재해석은 Spec 「범위」의 제외 항목이다. 회신 원문을 다시 읽고 분류를 고쳐 잡거나, 바운스 코드를 다시 매핑하지 않는다 — 그 자리는 각각 G7·G6이고, 여기서 다시 판정하면 같은 데이터에 두 개의 결론이 생긴다.
- **G6·G7이 이미 정정한 값을 쓴다**(Spec 「제약」). 자동응답(C6)은 G6에서 이미 무응답으로 정정돼 있으므로 회신으로 다시 세지 않는다 — 이중 집계 방지.
- **G2·G3 파일을 고치지 않는다.** 조정은 **제안**으로만 내고 사람이 승인한 뒤 별도 작업으로 반영한다.
  **이것이 도구 권한으로 막히지 않는다는 것을 분명히 해 둔다** — `Write`는 아래 집계 파일을 쓰려면 열려 있어야 하고 `disallowed-tools`는 경로 단위가 아니다. **쓰는 자리를 집계 출력 하나로 제한하는 지침**으로 지킨다(`g10-재수집판단`·`g12-질의응답`이 같은 이유로 같은 방식을 쓴다). 도구 권한이 실제로 막는 것은 **웹·셸·위임**(`Agent`)뿐이며, 그것이 막는 것은 *"집계하다 말고 직접 조사하러 나가는 것"*이다.
- **읽는 대상 전부가 다른 기능의 소유 파일이다.** 이 기능은 상류 산출물을 **읽기만** 한다 — 어느 파일에도 append하지 않는다.

- **Spec 「출력 형식」은 자리를 `집계/`로만 적었다.** `specs/` 아래로 두는 것은 `specs/G12_질의응답.md`를 실행하는 `g12-질의응답`이 이미 이 경로를 조회 대상으로 등재해 둔 것과 맞춘 결과이며(다른 상류 산출물과도 같은 층이다), **사람이 Spec에 다른 자리를 써 넣으면 그쪽이 이긴다**(`docs/90_미결정과_리스크.md` 3절 G11).
- **같은 집계일 파일이 이미 있으면 덮어쓰지 않고 멈춘다.** 같은 날 두 번 집계하면 어느 쪽이 그 날의 집계인지가 갈리는데 Spec이 그 경우의 파일명을 정하지 않았다 — 접미사를 스스로 만들지 않고 사람에게 알린다.
- **조인 키는 `기업식별자` + `발송일시`다.** 파일 본문의 항목값을 쓰고 **파일명을 쪼개 추측하지 않는다** — 기업식별자 자체에 하이픈이 여러 개 들어가는 경우(`junonline-jp-rope-picnic`)가 있어 파일명만으로는 마지막 구간이 날짜인지 식별자의 일부인지 안 갈린다.

## 인자

```
/g11-반응집계
/g11-반응집계 2026-09-01
```

- **인자가 없으면 오늘을 집계일로 쓴다.** 집계 범위는 언제나 **그 시점까지 쌓인 전체**이며, 기간을 잘라 받지 않는다 — Spec 「입력」이 *"그 시점까지 쌓인 데이터 전체를 한 벌"*로 못박았고, **세그먼트 간 비교는 전체를 한 컨텍스트에서 봐야 성립한다**(Spec 「제약」).
- **기간·세그먼트·기업을 좁히는 인자가 오면 실행하지 않고 되돌린다.** 부분 집계는 세그먼트 간 비교를 깨뜨린다.

## 실행

**1. 입력 자리를 전수 확인한다.** 위 표의 여섯 자리를 실제로 열어 **각각 몇 건인지 센다.** 없는 디렉터리는 `없음(0건)`으로 적고, **없음을 「없음 확인」으로 바꿔 적지 않는다.**

- **`specs/발송기록/`이 0건이면 집계 자체가 성립하지 않는다.** 파일을 만들지 않고 **어느 자리가 몇 건인지와 무엇이 선행돼야 하는지**를 보고하고 끝낸다 — 행이 하나도 없는 집계표는 "아직 안 돌았다"와 "돌았는데 반응이 없었다"를 구분하지 못한다. (Spec은 이 경우의 처리를 정하지 않았다 — `docs/90` 3절 G11)

**2. 한 벌로 조인한다.** 발송 기록 1건을 축으로 G6 상태 → G7 회신 → G8 원인을 붙인다.

- **G7 레코드 중 식별자가 `-미확정`인 것은 기업 단위 조인에 넣지 않는다**(Spec 「제약」). 발신 도메인 추정이라 G1 식별자와 일치를 보장할 수 없다. **「식별 불가」 건수로만 별도 집계**하고, 그 건수를 산출물에 반드시 적는다 — 안 적으면 분모에서 조용히 빠진다.
- **상류 파일 머리에 「시험 실행」·「확정 아님」·「확정 배정 아님」 표시가 있으면 그 표시를 산출물에 그대로 물려 적는다.** 잠정 입력에서 확정 결론을 만들지 않는다.
- **G6 상태가 [대기중]인 건은 비율 계산에서 뺀다** — Spec 「입력」이 이 기능에 넘기는 상태를 회신/무응답/주소 오류 **셋으로** 지정했고 [대기중]은 아직 결과가 아니다. **뺀 건수를 표에 별도로 적는다**(분모가 발송 건수와 다른 이유가 설명되지 않으면 표를 읽을 수 없다).

**3. 축을 세운다 — Spec이 「조건 조합」을 정의하지 않아 잠정 축을 쓴다.**

`specs/G5_제안메일제작발송.md` 「출력 형식」 표가 **소비처를 G11로 명시한 항목**을 조건 축으로 쓴다 — 인용한 근거 / 제안 내용 / 발신 언어·번역 검증 결과. 세그먼트 ID(버전 포함)는 별도 축이다.

- **이것은 Spec에 없는 잠정 축이다.** 근거는 상류 Spec이 *"이 항목은 G11이 본다"*고 스스로 표시했다는 것뿐이며, **그 사실과 지울 조건("사람이 `specs/G11` 「범위」에 조건 축을 써 넣으면 이 절은 사라진다")을 산출물 머리에 노출한다.** 적어 두지 않은 판별선은 명시한 것이 아니라 즉석 판단이다.
- **축을 여기서 늘리지 않는다.** 상류 Spec이 G11 소비로 표시하지 않은 항목(제목·본문 전문 등)을 조건 축으로 승격하지 않는다.

**4. 집계표(1절)를 만든다.** 항목은 `specs/G11_반응집계_기준조정.md` 「출력 형식」이 정본이다.

- **표본 부족 여부 칸은 `specs/G11_반응집계_기준조정.md` 「지금 쓰는 값」의 최소 표본 크기(5건, 임의값)로 판정한다.** 조합의 발송 건수가 5건 미만이면 「표본 부족」으로 표시한다(2026-08-11 정정 — 이전엔 이 값을 "미확정"으로 잘못 취급해 항상 판정을 보류했다).
- 비율은 **분자·분모를 함께 적는다**(예: `2/7`). 비율만 적으면 표본 크기가 사라져 다음 회차가 같은 판단을 다시 할 수 없다.

**5. 조정 제안(2절)을 낸다.** 표본 5건 이상인 조합만 대상으로 한다.

- **신호 상충 판정** — 같은 세그먼트 안에서 조건 조합별 회신율 차이가 20%p 이상이면(Spec 「지금 쓰는 값」, 임의값) Spec 실패표 2행대로 "신호 상충 — 재검토 필요"로 표시하고 그 조합엔 제안을 내지 않는다.
- **표본 부족 조합에는 제안을 내지 않는다**(성공 기준 (a) 무관용). 표본 5건 이상 + 신호 상충 아님 조합만 "무엇을·왜(근거 데이터)·어느 방향으로 얼마나"를 갖춘 제안 문장을 쓴다. "얼마나"의 단위·범위는 Spec이 정하지 않았으므로 **관찰된 비율 차이 자체를 크기로 인용**하고 지어낸 척도를 만들지 않는다.
- **이전 회차 대조는 그래도 돈다.** `specs/집계/`의 이전 파일을 열어 그때 낸 제안과 그 처리 결과를 확인하고, **기각 이력이 기록될 자리가 없으면 `기각 이력 확인 불가 — 기록 자리 없음`으로 적는다**(`docs/90` 3절 G11). 기각을 확인하지 못한 것을 "기각 없음"으로 바꿔 적지 않는다.

**6. 쓰고 점검한다.** 다 쓴 뒤 `specs/G11_반응집계_기준조정.md` 「성공 기준」 **(a) 항목만**으로 이 산출물을 대조하고 결과를 파일에 남긴다 — 걸리는 항목은 고치고 다시 확인한다. **(b)는 실제 데이터가 있어야 판정되므로 여기서 판정하지 않는다**(대기 항목을 통과 처리하지 않는다).

**7. 보고.** *"무엇이 통했고 무엇을 아직 못 말하는가"*가 사용자에게 도달해야 이 실행이 끝난다. **집계표에서 읽히는 것과, 최소 표본 기준이 없어 말할 수 없는 것을 갈라서 전한다.**

## 임의값으로 낸다 — 확정치가 아니라는 것을 보고에 남긴다 (2026-08-11 정정)

**이전 버전은 이 절에서 "최소 표본 기준 값이 없다"고 적고 조정 제안을 통째로 보류했다 — 틀렸다.** Spec 「지금 쓰는 값」에 이미 임의값(최소 표본 5건 · 신호 상충 20%p)이 채워져 있고, 이 프로젝트의 "기업 답 대기" 정책(`docs/92`·`docs/93`)은 "임의값으로 채우고 Spec엔 지금 쓰는 값만 둔다"이지 "값이 임의값이면 기능을 멈춘다"가 아니다. 위 4·5번 절차가 그 값을 실제로 쓴다.

- **그래도 임의값이라는 사실은 숨기지 않는다.** 조정 제안마다 "이 판단은 임의 임계값(5건·20%p, `docs/93` #1·#18) 기준이며 실제 데이터 분포로 재조정될 수 있다"를 함께 적는다 — 확정 기준인 것처럼 말하지 않는다(성공 기준 (b)가 이 값 자체의 타당성을 아직 검증 안 했다는 것과 모순되지 않게 하기 위해서다).
- **숫자를 새로 짓지는 않는다.** Spec에 이미 있는 5건·20%p 두 값만 쓰고, 그 밖의 값(예: 조정 폭의 단위)은 여전히 Spec에 없으므로 위 5번처럼 관찰값을 그대로 인용하는 선에서 멈춘다.
- **표본이 5건에 못 미치는 조합**은 그대로 「표본 부족」으로 남기고 제안하지 않는다 — 이 부분은 이전 버전과 결론이 같다.

## 규칙이 없는 경계에서 멈춘다

Spec이 침묵하는 자리에서 판정 문장을 스스로 만들지 않는다. 아래에 걸리면 확정하지 않고 **무엇이 없는지**를 산출물과 보고에 함께 적는다.

| 자리 | 멈추는 조건 |
|---|---|
| **최소 표본 크기·신호 상충 판정선** | **2026-08-11 해소 — Spec 「지금 쓰는 값」의 임의값(5건·20%p)을 그대로 쓴다.** 값 자체가 없어서 멈추는 경계였는데, 이제 값은 있고(임의값) "확정치가 아니다"를 보고에 남기는 것으로 대체됐다(위 「임의값으로 낸다」 절) |
| **조건 조합의 정의** | Spec 「범위」가 이름만 쓰고 정의하지 않았다. 잠정 축(3번)을 쓰되 그 사실을 노출하고, **축을 스스로 늘리지 않는다** |
| **기각 이력의 기록 자리** | Spec 「범위」는 기각 이력을 참조하라고 하는데 **사람이 기각을 적을 칸이 어느 출력 형식에도 없다.** 확인 불가로 적고 없는 칸을 만들어 채우지 않는다 |
| **G7 회신 성격·G8 원인 가설의 집계 자리** | Spec 「입력」에는 있는데 「출력 형식」 1절 집계표에 담을 칸이 없다. **집계표에 칸을 새로 만들지 않고**, 2절 제안의 근거로만 쓴다(그 2절이 지금 보류이므로 실질적으로 대기 상태다) |
| **조정 제안의 「크기」** | *"어느 방향으로 얼마나"*의 단위·범위가 정해진 곳이 없다. 제안이 열릴 때 함께 정해질 값이라 지금 만들지 않는다 |

## 이 스킬이 하지 않는 것

`specs/G11_반응집계_기준조정.md` 「범위」의 제외 목록과 같다 — **조정을 스스로 적용하는 것**(G2·G3 파일을 고치지 않는다) / G6·G7·G8이 이미 낸 결론의 재해석 / 신규 발송·조사. 그리고 **판정 기준 문장·임계값을 고치는 일**(최소 표본 크기는 실제 데이터를 본 사람이 정하고, 정해지면 `기준/` 카드가 그 자리다).
