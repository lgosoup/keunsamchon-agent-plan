# g1-기업판정 — 일본 기업 1곳 관찰·판정

이 스킬은 **정본 두 문서를 그대로 실행하는 호출 계약**이다 — 새 판정 규칙을 만드는 자리가 아니다.

- **구조(무엇을 만들고 어떤 형태로 내놓는가)**: `../../specs/G1_대상기업발굴.md`
- **판정 값(무엇을 보고 O/X/`?`를 주는가)**: `../../기준/G1_기업판정기준.json` (2026-08-05 — 마크다운에서 이관. 옛 `.md`는 이 파일을 가리키는 안내만 남아 있다)

**매 실행마다 두 문서를 다시 읽는다** — 기준 카드는 검증 결과로 자주 바뀐다. 이 스킬 본문과 두 문서가 어긋나면 **문서가 이긴다**.

## 인자

```
/g1-기업판정 "株式会社サンプル" https://sample.co.jp https://sample.co.jp/shop
```

첫 번째는 기업명(원어 그대로), 두 번째 이후는 공개 페이지 URL(홈페이지 하나만 와도 성립한다). **인자에 기업이 둘 이상 식별되면 실행하지 않고** "기업 1곳씩 나눠 호출해 달라"고 되돌린다 — Spec의 「기업 1곳 = 컨텍스트 1단위」 경계를 실행 층에서 지키는 조치다.

## 실행

1. 입력 URL을 열어본다. 접근 차단 응답(HTTP 403·WAF 안내·타임아웃)이면 바로 판정불가로 종료하지 않고, `기준/G1_기업판정기준.json`의 `접근차단_자사도메인재시도`를 따라 WebSearch로 같은 기업의 별도 자사 공식 도메인이 실재하는지 먼저 확인한다(소스가 라쿠텐이든 Qoo10이든 동일 적용). 실재가 확인되면 그 도메인을 이후 단계의 "홈페이지"로 쓴다. 못 찾으면 원래 절차대로 판정불가로 종료한다.
2. 기업식별자 = 홈페이지 도메인의 `.`을 `-`로 바꾼 것 (Spec 출력 형식 참조).
3. `specs/candidates/후보목록.md`에서 **식별자로만 조회**해 그 섹션이 이미 있는지 확인한다(파일 전체를 읽어 컨텍스트에 넣지 않는다). 있으면 **재수집**이다 — 기존 관찰값을 참고하지 않고 새로 관찰한다(맥락 오염 방지). 그 섹션만 교체한다.
4. 두 정본 문서가 정한 대로 관찰층(O1~O6·O8~O9)을 채우고 규칙층을 계산해, `specs/candidates/후보목록.md` **끝에 섹션(`## {기업식별자}`)으로 추가**한다(재수집이면 해당 섹션만 교체).
5. `specs/G1_대상기업발굴.md` 「성공 기준」 체크리스트로 이 산출물을 자체 점검한다. 걸리는 항목이 있으면 고치고 다시 확인한다 — 걸린 채로 내지 않는다.

## 이 스킬이 하지 않는 것

`specs/G1_대상기업발굴.md` 「범위」의 제외 목록과 같다 — 명단 수집 소스 선택, 세그먼트화(G2), 적합도 순위(G3), 연락처 유효성·위법 여부 판정(G4), 그리고 **판정 기준 문장 자체를 고치는 일**(그건 검증 결과를 사람이 보고 `기준/G1_기업판정기준.json`에 직접 고친다 — 2026-08-05 JSON 이관 후 `.md`는 승계 안내 스텁이다).
