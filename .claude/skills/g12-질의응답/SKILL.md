# g12-질의응답 — G1~G11 산출물 읽기 전용 질의응답

이 스킬은 **정본 문서를 그대로 실행하는 호출 계약**이다 — 새 판정 규칙을 만드는 자리가 아니다.

- **구조(무엇을 만들고 어떤 형태로 내놓는가)**: `specs/G12_질의응답.md`
- **판정 문장 없음** — G12는 조회 기능이라 문턱을 판정하는 기준 카드가 없다. 단, **읽기만 한다는 경계**와 **인용 없는 답변을 내보내지 않는 규칙**은 이 스킬이 지킨다(Spec 「제약」·「성공 기준」 무관용 3종).

**매 실행마다 위 Spec을 다시 읽는다.** 이 스킬 본문과 Spec이 어긋나면 **문서가 이긴다.**

## 산출물 자리

**읽는 쪽 — 파일마다 키가 다르다. 파일명만 보고 짐작하지 않고 이 표로 확인한다.** (2026-08-06 정정 — 이전엔 "전부 기업식별자 키"라고 적혀 있었다, 틀렸다)

| 소유 기능 | 자리 | 키 |
|---|---|---|
| G1 | `specs/candidates/후보목록.md` | 기업식별자(섹션 헤더). **현행 단일 파일** |
| G1 (이력) | `specs/candidates/{기업식별자}.md` 개별 파일 | 기업식별자. **구 형식 — 위 후보목록.md로 대체됨. 답변 근거로 쓰지 않는다**(아래 「멈추는 경계」) |
| G1→G4 | `specs/candidates/보류목록.md` | 기업식별자(행) |
| G2 | `specs/segments/SEG-{축코드}-v{버전}.md` | 세그먼트 ID(파일 1개 = 여러 기업) |
| G3 | `specs/scores/{기업식별자}.md` | 기업식별자 |
| G3 | `specs/scores/순위표-{작성일}.md` | **작성일** — 기업식별자 키가 아니다. `scores/` 안에서 채점 파일과 섞여 있으니 글롭할 때 구분한다 |
| G4 | `specs/contacts/{기업식별자}.md` | 기업식별자 |
| G4→G9 | `specs/연락처후보/{기업식별자}.md` | 기업식별자 |
| G5 | `specs/발송대기/{세그먼트ID}-{작성일}.md` | 세그먼트 ID(파일 1개 = 여러 기업) |
| G5 | `specs/발송기록/{기업식별자}-{발송일시}.md` | 기업식별자(앞) |
| G6 | `specs/상태/{기업식별자}-{발송일시}.md` | 기업식별자(앞) |
| G7 | `specs/replies/{수신일시}-{식별자}.md` | **날짜가 앞, 식별자가 뒤 — 유일하게 순서가 반대다** |
| G7 | `specs/발송금지.md` | 메일 주소(행). **2026-08-06 기준 파일 자체가 없다(등재 0건)** — 없으면 "데이터 없음"으로 답한다 |
| G8 | `specs/원인분석/{기업식별자}-{발송일시}.md` | 기업식별자(앞) |
| G9 | `specs/위임브리프/{기업식별자}.md` | 기업식별자 |
| G10 | `specs/재수집대상/{기업식별자}-{판정일}.md` | 기업식별자(앞) |
| G11 | `specs/집계/{집계일}.md` | **집계일 — 기업식별자 키가 아니다.** 세그먼트 단위 집계라 개별 기업을 묻는 질문엔 안 맞는다 |

- **입력**: 질문 1건 + 위 표에서 그 질문이 요구하는 범위만. 전체를 매번 다 읽지 않는다(G11과 다른 점, Spec 「입력」).
- **출력**: `specs/질의응답로그/{일시}.md` 1개 — 질문 원문 · 조회 시각 · 답변 · 인용 출처(파일명+항목) 목록 · 해당 시 "확인 불가"/"조회 범위 밖" 표시 + 사유. 파일명 규칙(충돌 처리 포함)은 `specs/G12_질의응답.md` 「출력 형식」이 정본.

**읽기 전용으로 쓴다는 것이 정확한 표현이다.** `Write`·`Edit` 도구 자체는 열려 있다(위 로그를 쓰려면 필요하다) — **G1~G11 산출물 파일에 안 쓰는 것은 도구 차단이 아니라 이 스킬의 유일한 쓰기 대상을 로그 하나로 제한하는 지침**이다(`g10-재수집판단`이 같은 이유로 같은 방식을 쓴다). "이 기능은 파이프라인을 조정하지 않는다"를 물리적으로 강제하는 것은 **웹·발신·실행 도구가 `disallowed-tools`로 없다는 것**이다.

## 인자

```
/g12-질의응답 이번 주 회신 몇 건 왔어
/g12-질의응답 이 기업은 왜 제외됐어
/g12-질의응답 후보 순위 어떻게 돼
```

**인자에 질문이 둘 이상 식별되면 실행하지 않고** "질문 1건씩 나눠 호출해 달라"고 되돌린다 — Spec의 「질문 1건 = 조회 1단위」 경계를 실행 층에서 지키는 조치다. **인자가 없으면 되돌린다.**

## 실행

**1. 질문을 읽는다.** 질문 원문을 그대로 기록한다. **요약·재서술해서 조회 범위를 스스로 좁히지 않는다** — 질문 원문과 조회 범위의 대응은 나중에 답변 로그가 증명한다.

**2. 조회 범위를 판별한다.** 질문이 요구하는 G1~G11 산출물의 범위를 위 「산출물 자리」 표에서 고른다.  
**매번 G1~G11 전체를 읽지 않는다.** G11은 세그먼트 간 비교라 전체가 필요하지만, G12는 질문마다 필요한 범위가 다르다 — Spec 「입력」이 그 차이를 명시한다.

질문 유형 예시 → 여는 자리:

| 질문이 이런 걸 물으면 | 연다 |
|---|---|
| "이번 주 회신 몇 건" | `specs/replies/` (날짜 범위로 훑는다 — 파일명이 날짜 먼저인 유일한 자리) |
| "이 기업은 왜 제외됐어" | `specs/candidates/후보목록.md`에서 그 기업 섹션. **`candidates/{기업식별자}.md` 개별 파일은 구 형식이라 열지 않는다**(아래 「멈추는 경계」) |
| "후보 순위 어떻게 돼" | `specs/scores/순위표-{작성일}.md` 중 **가장 최신 것 하나** — 파일 머리의 "확정 아님" 표시 여부를 반드시 확인해 답변에 옮긴다 |
| "발송 상태 확인해줘" | `specs/상태/{기업식별자}-*.md` |
| "이 기업 연락처 확보됐어" | `specs/contacts/{기업식별자}.md` |
| "이 기업 발송해도 돼" | `specs/발송금지.md`(없으면 "데이터 없음") + `specs/contacts/{기업식별자}.md`의 등급 |

- **파일 본문의 「기업 식별자」 항목값만 조인 키로 쓴다 — 파일명을 쪼개 추측하지 않는다.** 기업식별자 자체에 하이픈이 여러 개 들어가는 경우(예: `junonline-jp-rope-picnic`)가 있어 `{기업식별자}-{판정일}` 같은 파일명은 마지막 구간이 날짜인지 식별자의 일부인지 파일명만으로 안 갈린다.
- **기업식별자로 조인이 안 되는 `-미확정` 식별자(G7 발신 도메인 폴백)는 기업 단위 조인에 넣지 않는다.** G1 식별자와 일치를 보장할 수 없기 때문이다. 이런 레코드가 섞이면 "식별 불가"로 표시하고 확정 사실처럼 말하지 않는다 — G11이 쓰는 같은 완화책을 재사용한다.
- **파일 머리에 「시험 실행」·「확정 아님」·「확정 배정 아님」 같은 경고가 있으면 그대로 답변에 옮긴다.** 경고를 지우고 확정 사실처럼 말하지 않는다.
- **같은 기업을 다루는 파일이 둘 이상이고 값이 다르면 최신 형식·최신 파일을 우선한다**(예: 구 `candidates/{식별자}.md` vs 현행 `후보목록.md`). 어느 쪽이 최신인지 판단이 안 서면 "판정 불가 — 상충하는 기록 있음"으로 답한다.
- 질문 범위를 벗어나서 읽어야 할 이유가 없는 파일은 열지 않는다.

**3. 답변한다.** 근거는 **파일명 + 항목**으로 인용한다. 인용 없는 답변은 내보내지 않는다 — 사용자가 답변을 검증할 방법이 없기 때문이다.

- **인용을 확정하기 전에 그 파일·항목을 다시 열어 실제로 그렇게 적혀 있는지 대조한다.** 대조 없이 기억이나 요약으로 인용을 만들지 않는다 — 이 스킬의 유일한 산출물이 "답변 + 그 답변이 스스로 붙인 근거"라 인용 확인이 곧 이 기능의 자기검증이다.
- **데이터에 없는 값을 추정으로 채우지 않는다.** 질문에 답할 근거가 없으면 "확인 불가"로 답한다.
- **조회 범위를 벗어난 요청(실행·발송·재조사·예측·기획 판단 요구)이 오면 답하지 않고 범위 밖임을 알린다.** 해당하는 기능·문서로 안내만 한다 — 스스로 판단해 실행하지 않는다.

**4. 실패는 `specs/G12_질의응답.md` 「실행 형태」 실패표(2026-08-06 6종으로 확장)가 정본이다.** 여기 다시 옮겨 적지 않는다 — 매 실행 그 표를 다시 읽고 그대로 따른다(3번의 규칙들이 그중 일부를 이미 실행 절차에 적용해 뒀다).

**5. 로그를 쓴다.** `specs/질의응답로그/{일시}.md` 1개를 쓴다. 파일명 형식(초 단위, 충돌 시 일련번호)은 `specs/G12_질의응답.md` 「출력 형식」이 정본.

- 질문 원문 · 조회 시각
- 답변
- **인용 출처** — 파일명 + 항목 목록
- (해당 시) **"확인 불가" / "조회 범위 밖"** 표시 + 사유

## 이 스킬이 하지 않는 것

`specs/G12_질의응답.md` 「범위」의 제외 목록과 같다 — **산출물 수정**(G1~G11 파일에 쓰지 않는다) / **파이프라인 실행·재실행**(G1~G11 어느 기능도 이 기능이 대신 돌리지 않는다) / G11의 기준 조정 제안 실행 / 발송·접촉 행위 / 질문 범위 밖의 예측·추천(데이터에 없는 판단을 스스로 만들어내지 않는다). 그리고 **판정 기준 문장 자체를 고치는 일**.

## 이 스킬이 특히 막는 것

- **인용 없는 답변을 내보내지 않는다.** Spec 「성공 기준」 무관용 1번 — 어기면 사용자가 답변을 검증할 방법이 없다.
- **데이터에 없는 값을 지어낸 답변을 내보내지 않는다.** 무관용 2번 — 어기면 사용자가 틀린 정보로 판단한다.
- **G1~G11 산출물 파일을 이 스킬이 수정하지 않는다.** 무관용 3번 — `Write`는 로그를 쓰려면 열려 있어야 해서 도구 자체로는 못 막는다. **쓰는 자리를 답변 로그 하나로 제한하는 지침**으로 지킨다(위 「산출물 자리」).
- **`-미확정` 식별자 레코드를 확정 사실처럼 섞어 넣지 않는다.** 서식 점검 1번.
- **조회 범위를 벗어난 요청에 실행 대신 안내가 나가게 한다.** 서식 점검 2번.
- **질문마다 답변 로그를 남긴다.** 서식 점검 3번.
- **조회 시각이 로그에 남는다.** 서식 점검 4번.

## 보고

답변이 나오면 **무엇을 근거로 답했는지(파일명+항목)**를 중심으로 전한다. 인용 출처가 길면 답변 본문에 요약하지 말고 로그 파일에 남기고, 보고에는 핵심 출처만 적는다. "확인 불가"·"조회 범위 밖"으로 끝난 질문은 그 사유를 함께 올린다.
