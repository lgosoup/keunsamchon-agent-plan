# g7-회신처리 — 일본어 회신 1통 해석·검증

이 스킬은 **정본 두 문서를 그대로 실행하는 호출 계약**이다 — 새 판정 규칙을 만드는 자리가 아니다.

- **구조(무엇을 만들고 어떤 형태로 내놓는가)**: `specs/G7_회신해석정리.md`
- **판정 문장(어느 칸에 넣는가, 무엇을 거부로 보는가, 번역이 맞다고 볼 조건)**: `기준/G7_회신판정기준.md`

**매 실행마다 두 문서를 다시 읽는다.** 이 스킬 본문과 두 문서가 어긋나면 **문서가 이긴다.**

**산출물 자리**: `replies/`와 `발송금지.md`는 G1 산출물(`candidates/후보목록.md`)과 같은 디렉터리 층에 둔다. T 호출 프롬프트에 이 자리를 함께 넘긴다 — **두 실행이 서로 다른 `발송금지.md`에 쌓이면 그게 곧 위법 발송 경로다.**

## 인자

회신 원문을 그대로 붙여넣는다. **인자에 회신이 둘 이상 식별되면 실행하지 않고** "회신 1통씩 나눠 호출해 달라"고 되돌린다 — Spec의 「회신 1통 = 작업 1단위」 경계를 실행 층에서 지키는 조치다.

## 실행

**1. 해석 — `g7-회신해석`(T)을 Agent 도구로 호출한다.**
받은 회신 원문·헤더·첨부 파일명·참조 발신 정보를 **요약하지 말고 그대로** 프롬프트에 넣는다. T가 레코드 파일 경로 / 판독 가능 여부 / `발송금지.md` 등재 여부를 돌려준다.

**2. 수신 거부는 여기서 이미 끝나 있어야 한다.** T의 응답에서 등재 여부를 확인하고, 거부·의심인데 등재가 안 됐으면 **그 자리에서 등재한다.** 검증 결과를 기다리지 않는다.

**3. 판독 불가(C8)면 V를 호출하지 않는다.** 검증할 해석이 존재하지 않기 때문이다. 검증층에 `검증 대상 없음 — 해석 없음(C8 판독 불가)`과 처리일시·해석 주체 `g7-회신해석`·검증 주체 `해당 없음`을 적는다. 이것은 "검증층이 비어 있는" 상태가 아니다(`specs/G7` 실패표 1행이 이 건은 **원문 그대로 올리라고** 지시한다). **7번으로 간다.**

**4. 검증 입력을 뽑는다 — 여기가 T와 V를 가르는 지점이다.**
레코드에서 **원문층의 회신 원문 블록**과 **해석층의 한국어 해석 전문**, 이 둘만 복사해 `replies/_검증입력/{레코드 파일명}-r1.md`에 쓴다.

| 넣는다 | 넣지 않는다 |
|---|---|
| 일본어 원문 전문 | 요지 3줄 · 별도 항목으로 분리된 「애매 표시」 |
| 한국어 해석 전문 (**손대지 않고 그대로.** 애매 표시가 문장 안에 인라인돼 있으면 그 표기까지 그대로 넘긴다 — 해석을 편집하면 레코드에 없는 문장을 검증하게 된다) | 판단층 전체(8분류·수신 거부·자동응답·요구·조치 요청) |
| | 헤더(발신 주소·제목) · 참조 발신 정보 · 첨부 목록 |

이 파일은 **감사 기록**이다 — V가 실제로 무엇만 봤는지의 증거이자, 재번역이 일어났을 때 「두 번역본」을 보존하는 자리다. 지우지 않는다.

**5. 검증 — `g7-번역검증`(V)을 Agent 도구로 호출한다.**
**V에게 파일 경로를 주지 않는다** — 파일명에서 레코드 경로와 라운드 번호가 복원된다. 4번의 두 블록을 **프롬프트에 그대로 인라인**해 넘긴다(요약·재서술하지 않는다).

V가 돌려준 판정을 **그대로** 레코드 검증층에 옮겨 적는다. 처리일시 · 해석 주체 `g7-회신해석` · 검증 주체 `g7-번역검증`를 함께 적는다.

**6. 분기.**

| 상태 | 처리 |
|---|---|
| 3층 전부 일치 | 7번으로 |
| 한 층이라도 불일치 (1회차) | **T를 새로 호출해 재번역 1회.** 원문 전문 + V가 지목한 불일치 지점만 준다 — **1회차 해석 전문은 주지 않는다**(그 문장에 맞춰 다시 쓰게 된다). T가 해석층·판단층을 다시 만들면 `-r2.md`로 4번을 되풀이하고 **V를 새로 호출한다** — 검증한 컨텍스트가 이어지면 자기 지적을 통과시킨다 |
| 2회차도 불일치 | 기준 카드가 정한 대로 분류를 내리고, 원문 + 두 번역본(`-r1`·`-r2` 추출 파일의 해석 전문) + 안 맞은 지점을 레코드에 함께 남긴다. **이 건은 보류가 아니라 올린다** — 8번 보고에서 원문과 불일치 지점을 중심으로 전하고, 해석 두 벌은 어느 쪽도 확정으로 제시하지 않는다 |
| 검증층을 채우지 못했다 (V 호출 실패·응답 없음) | 레코드 첫 줄에 `상태: 검증 미완 — 사용자 제출 보류`를 남기고, **8번 보고에 해석·분류를 옮기지 않는다.** 무관용 3종은 검증층이 채워진 뒤에만 판정할 수 있다 |

**7. 자체 점검.** `specs/G7_회신해석정리.md` 「성공 기준」 체크리스트로 이 산출물을 대조한다. 서식 점검에 걸리는 항목은 고치고 다시 확인한다 — 걸린 채로 내지 않는다.

**무관용 3종에 걸리면 사용자에게 내지 않는다.** 단 **판정 불가(C8)로 끝난 건은 여기 걸리지 않는다** — 방향 뒤집힘은 확정한 해석이 있어야 성립하는 조건이고, C8은 애초에 판정을 하지 않은 것이다. 원문 보존과 `발송금지.md` 등재는 해석 없이도 판정되므로 그 둘만 확인한 뒤 원문 중심으로 올린다.

**8. 보고.** 판단층의 **「사용자 조치 요청」**을 중심으로 전한다. 요약이 아니라 *"무엇을 결정해야 하는가"*가 사용자에게 도달해야 이 실행이 끝난다.

## 이 스킬이 하지 않는 것

`specs/G7_회신해석정리.md` 「범위」의 제외 목록과 같다 — 답장 작성·발송, 보내는 메일 제작, 바운스·주소 오류 판정(G6), 첨부 파일 내용 해석, 회신율 집계(G11), 미팅·견적 이후 과정. 그리고 **판정 기준 문장 자체를 고치는 일**(실제 회신을 판정해 본 사람이 `기준/G7_회신판정기준.md`에 직접 고친다).
