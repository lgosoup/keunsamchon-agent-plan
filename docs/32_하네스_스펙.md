| 근거 | 내용 |
|---|---|

## 2. 성공 기준 — 두 층으로 나눈다

**성공 기준은 예/아니오로 판단 가능해야 한다**(`docs/수업/00_개념정리.md` 7-1). 그런데 우리 기준값 일부는 아직 미확인이다. 미확인 값을 기다리며 성공 기준 전체를 비워 두면 Build Order ①이 영구히 미완이 되고, 반대로 지금 숫자를 지어내면 `01` C2 게이트("값 없는 표가 하나도 없는가")를 위반한다.

그래서 **미확인 값에 걸리지 않는 기준과 걸리는 기준을 갈라 둔다.** 관찰층/규칙층을 가른 것과 같은 기법이다(`02` 9절 원칙 ③).

### (a) 지금 확정 — 미확인 값에 걸리지 않는다

| # | 기준 | 어떻게 판정하나 |
|---|---|---|
| 1 | **관찰 항목 모든 칸**에 값과 근거가 함께 채워졌는가 | 빈 칸을 센다. 0이어야 한다 |
| 2 | 근거가 **본 페이지 URL과 무엇을 봤는지**를 포함하는가 | "전문적으로 보임" 같은 인상 서술만 있으면 불합격 |
| 3 | 제외 처리된 건에 3종 사유(품목 무관 / 연락처 미확인 / 90일 초과) 중 하나가 명시됐는가 | 사유 없는 제외 건을 센다. 0이어야 한다 |
| 4 | **판정 불가** 건이 제외와 구분돼 사유와 함께 남았는가 | 아래 ※ |
| 5 | 모든 행에 수집일이 있는가 | 빈 칸을 센다. 0이어야 한다 |
| 6 | 관찰층 칸에 규칙층 결론(추천 제안·우선순위)이 섞여 들어가지 않았는가 | 관찰층 칸을 훑어 결론 문장을 센다. 0이어야 한다 |
| 7 | 연락처가 **공식 홈페이지의 어디에서** 확인된 것인지 적혔는가 | 출처 없는 연락처를 센다. 0이어야 한다 |

※ **4번은 이번에 새로 생긴 항목이다.** `30` ④의 제외 조건 3종은 전부 "판정 결과가 부적합"인 경우이고, **"판정을 하지 못한"** 경우(사이트 접속 불가 / 스크립트 렌더링으로 상품 목록을 읽을 수 없음 / 로그인·회원가입 요구 / 상품 수가 페이지에서 세어지지 않음)는 정의돼 있지 않았다. 이 둘을 구분하지 않으면 **"보고 부적합했다"와 "못 봤다"가 같은 칸에 섞여** 90일 뒤 재수집 때 어느 쪽을 다시 열어야 하는지 알 수 없다. 판정 불가는 제외가 아니라 **별도 상태**로 남기고 재시도 대상으로 둔다 (`90` 리스크 17).

### (b) 대기 — 무엇을 기다리는가

| # | 기준 | 기다리는 것 | 왜 지금 못 정하나 |
|---|---|---|---|
| 8 | 목록 건수가 처리 가능한 상한 안에 있는가 | `12` Q9·N6⑦ (월 제작 캐파) | 캐파를 모르면 상한이 없다. 캐파 초과 리드는 성과가 아니라 낭비다 (`90` 리스크 11) |
| 9 | 목록에 수주 불가 규모의 기업이 섞이지 않았는가 | `12` Q10·N6⑤ (최소 수주 금액) | 하한이 없으면 영세 셀러를 걸러낼 기준이 없다 |

### 상위 시스템의 성공 기준 (이 단위의 범위 밖, 그러나 잊으면 안 되는 것)

**사람 승인 없이 발송된 메일이 0건인가.** 브리프 요구 ③(반자동)의 성공 기준이며, 이 단위는 1절 제약 ⑥(발송 권한 없음)으로 이를 **위반할 수 없게** 만드는 방식으로 기여한다.

## 3. Subagent 4경계

이 단위를 독립 실행 단위로 성립시키는 네 경계다. 넷이 정해지지 않은 것은 Subagent가 아니다(`docs/수업/00_개념정리.md` 7-3).

| 경계 | 내용 |
|---|---|
| **입력 형식** | 기업 1곳 분량 — 기업명·국가 + 공개 페이지 URL 집합(홈페이지 / 상품 목록 / SNS / 쇼핑몰). **1건씩 넣는다.** 여러 기업을 한 번에 넣지 않는 이유는 독립 컨텍스트 경계가 무너지기 때문이다 |
| **출력 형식** | `30` ④ 산출 스키마 1행. 관찰층(값 + 근거)과 규칙층을 가른 마크다운 표 |
| **도구 권한** | **공개 웹페이지 읽기 + 결과 파일 쓰기까지만.** 메일 발송·외부 전송 권한을 주지 않는다(1절 제약 ⑥). 비공개 소스 조회 권한도 주지 않는다(1절 제약 ①) |
| **독립 컨텍스트** | **기업 1곳 = 컨텍스트 1단위.** A사를 보며 관찰한 내용이 B사 판정에 남지 않아야 한다. 사람이 연속으로 여러 기업을 볼 때 앞 기업의 인상이 다음 판정에 남는 문제를 이 경계로 막는다 |

**독립 컨텍스트가 이 하네스의 존재 이유 중 하나다.** 한 맥락에 여러 기업을 넣으면 앞에서 정한 판정 기준이 뒤에서 밀려나 "기준을 확인하지 않고 판정을 내는" 상태가 된다(Context Rot). 단위를 쪼개는 것이 그 대응 구조다.

## 4. Build Order 현재 상태 — B는 뒤에서부터 만들어져 있다

| 단계 | 상태 | 어디에 있나 |
|---|---|---|
| **① Spec** | **부분** — 목표·맥락·범위·제약·출력 형식은 확정(이 문서 1절). **성공 기준은 (a) 7건 확정 / (b) 3건 대기**(2절) | 이 문서 |
| **② Skill** | **없음** — 판정 절차 카드가 없다. `40` V1-a로 고쳐진 기준 문장이 이 카드의 초안이 된다 | — |
| **③ Subagent** | **이 문서 3절에서 처음 정의.** 실행체는 아직 없다 | 이 문서 3절 |
| **④ Workflow** | **있음** — 10단계 파이프라인(체이닝) + 조건 분기(제외 3종 / 신호 약하면 보류·60일 후 재탐색) | `30` ⑦ |
| **⑤ Hook** | **있음(설계)** — 90일 초과 시 재수집 / 7영업일 미응답 판정 / 14일 팔로우업 / 60일 재탐색 | `30` ④·⑥ |
| **⑥ Checklist** | **없음** — 2절 (a)가 그대로 초안이 된다. (b)는 값이 오면 추가 | — |

**진단**: ④⑤가 먼저 만들어지고 ①②③⑥이 비어 있다. **Build Order의 역순**이며, 그 결과가 *"실행 순서는 그려져 있는데 언제 완료인지 아무도 모르는"* 상태다 — 붕괴 지점 1(막연한 요청)과 3(검증 없는 실행)을 동시에 안고 있다. 이 문서와 `40` V1이 ①②③⑥을 앞에서부터 메우는 작업이다.

**따라서 지금 만들 것은 ①뿐이고, ②는 `40` V1-a 직후, ③의 실행체는 V1-b를 위한 최소 1개, ⑥은 (a) 확정분으로 시작한다.** ④⑤를 더 정교하게 만드는 일은 `01` E단계로 미룬다 — 이미 앞서 있는 단계를 더 앞세우면 역순이 심해진다.

## 5. 이 하네스가 풀지 않는 것

자동화로 풀리지 않는 것을 하네스에 기대하면 그 기대가 리스크가 된다.

| 풀지 않는 것 | 왜 | 어디서 푸나 |
|---|---|---|
| 실제 구매 의사결정권자의 연락처 | 공개 정보에 없다 (`90` 리스크 7) | 대표 문의창구로 수렴하는 것을 **전제로** 메일 문안·팔로우업을 설계 (`30` ⑥) |
| 회신 응대 언어 인력 | 사람의 문제다 | `12` N4·Q12 확인 후 `30`에 단계 추가 (`90` 리스크 14) |
| **판정 기준 자체가 옳은가** | 하네스는 기준을 **일관되게 적용**할 뿐, 기준의 타당성을 만들지 못한다 | `40` V1(기준이 모호한가) / V2(규칙층이 맞는가) / V6(국내 고객 역산) |

세 번째가 가장 중요하다 — **하네스를 만들면 판정이 재현 가능해지지만, 재현 가능한 오답도 재현된다.** 그래서 `40`이 `32`와 짝으로 존재한다.

## 6. 이 Spec이 뒤집히는 조건

| 무엇이 오면 | 무엇이 뒤집히나 | 살아남는 것 |
|---|---|---|
| `12` **Q1** (해외 판매가 AI-Studio 단독인가, Clo.D 포함인가) | "Clo.D 포함"이면 **모집단 자체**가 달라진다(동대문 소싱을 원하는 해외 바이어가 추가). 신호 4종의 유효성도 재검토 | 3절 4경계, 2절 (a) |
| `12` **N2** (지불 고객이 원래 촬영을 하던 곳인가) | **규칙층** — 신호의 방향 | 1절 목표·제약, 관찰층, 3절, 2절 (a) |
| `12` **N7** (회사가 먼저 보고 싶은 산출물) | 이 단위를 **먼저** 만들 것인가의 순서 (메일이 급하면 순서가 바뀐다) | 이 Spec 자체 — 메일의 맞춤 근거도 결국 이 단위의 출력에서 나온다 |
