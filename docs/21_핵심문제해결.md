## 1. 근본원인

> **해외영업 판단(누구를 접촉할지 + 무엇을 어떻게 제안할지)이 회사 내부 자산이 아니라, 협력사라는 외부의 암묵적 경험에 갇혀 있다.**

협력사는 자기 경험 영역만 다루고(F10), 그 판단이 회사에 명시적으로 옮겨진 적이 없다. 이 하나의 결핍이 아래 두 병목을 동시에 만든다.

## 2. 두 병목 — 근본원인의 두 갈래

| | 기업서치 | 이메일 제작·발송 |
|---|---|---|
| **병목** | 협력사 경험 밖의 후보를 판별할 기준과 근거가 없다 (`20` 5절, 확정) | 기업마다 제안 논리·문안을 처음부터 다시 판단해야 해서, 기업 수가 늘수록 작성·검수 부담도 같은 비율로 늘어난다 (`20` 5-1절) |
| **지지사실** | F10·F11·F14·F15 (`20` 2절) | F10·F14·F28(출처 C)·`13` 116행(A, 1회성 — 방향성 참고) |

두 병목을 각각 독립으로 정당화하지 않는다 — 둘 다 1절의 근본원인에서 나온다.

## 3. 해결 — 하나의 자산, 두 방향

> **협력사의 암묵적 판단을 회사 내부의 명시적·재사용 가능하고, 반응으로 계속 갱신되는 자산으로 옮긴다.**

| 방향 | 무엇을 하는가 | 어느 병목에 대응하는가 |
|---|---|---|
| **재사용** (공간적 확장) | 한 번 확정한 판단(세그먼트·기준 문안·단일 척도)을 여러 기업에 적용한다 | 이메일 제작·발송 |
| **학습** (시간적 개선) | 실제 접촉 반응으로 그 판단을 계속 고친다 | 기업서치 |

## 4. 기능(G1~G11) 연결 — 그리고 구현 범위

**기능 자체는 `31_기능구조.md`의 11개 그대로다.** 대부분(G1·G2·G4·G6·G7·G11)이 두 방향 모두를 뒷받침하므로, 아래는 "어느 함수가 어느 축 전용인가"의 트리가 아니라 **각 함수가 재사용/학습 중 무엇을 주로 담당하는가**만 표시한다. 근거는 `31` 3-2절에 이미 있고 여기서 재서술하지 않는다.

| 함수 | 주로 | MVP 상태 |
|---|---|---|
| G1 대상 기업 발굴 | 재사용+학습 (관찰 근거가 둘 다의 재료) | **MVP** |
| G2 세그먼트화 | 재사용 | **MVP** |
| G3 적합도 평가 | 학습 (다음 접촉 순서에 기준 적용) | 부가 이연 |
| G4 연락처 확보 | 재사용+학습 | **MVP** |
| G5 제안 메일 제작·발송 | 재사용 | **MVP** |
| G6 발송 결과 판정 | 재사용+학습 (반응의 원재료) | **MVP**(최소 반응처리) |
| G7 회신 해석·정리 | 재사용+학습 | **MVP**(최소 반응처리) |
| G8 원인 분석 | 학습 | 부가 이연 |
| G9 사람 접촉 위임 브리프 | 재사용 | 부가 이연 |
| G10 재수집 판단 | 학습 | 부가 이연 |
| G11 반응 집계·기준 조정 | 학습 (루프를 닫는 지점) | 부가 이연 |

**지금 시연 가능한 것은 "재사용" 방향뿐이다.** "학습"(반응으로 기준을 갱신하는 G11 및 그 전 단계 G3·G8·G9·G10)은 구조만 확정돼 있고 실제 가동은 발송·회신 데이터가 쌓인 뒤다(`31` 8-1절, `33` D11·D15). **발표·시연에서 이 둘을 섞어 말하지 않는다.**

## 5. 발표용 한 줄

> 협력사에게만 있던 해외영업 판단을 회사 내부의 재사용 가능한 자산으로 옮기고, 실제 반응으로 그 자산을 계속 고친다.
