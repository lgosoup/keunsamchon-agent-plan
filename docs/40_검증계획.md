# 40. 검증 계획 — 우리가 세운 기준이 맞다는 걸 어떻게 확인하는가

> **이 문서의 성격**: `30_해결설계.md`가 세운 판별 기준·임계값이 **실제로 작동하는지 확인하는 절차**. 기준 자체는 `30`에, 확인 방법은 여기에 쓴다. 하네스 쪽 완료 판정(성공 기준)은 `32_하네스_스펙.md` 2절에 있고, 이 문서는 그 기준을 **실제로 재는** 절차다.
> **왜 이 문서가 심사에 직결되는가**: 심사는 결과물보다 **"왜 그 선택을 했고, 그 선택의 정확성을 검증했는가"**를 본다 (`00_과제_정의.md` 5절, `02_작업원칙.md` 7절). 이 문서의 실행 기록이 그 답이다.

## 0. 왜 지금 세울 수 있게 됐는가

이 문서는 `91_진행로그.md` 공백표에 **"검증 대상(판별 기준)이 폐기 대기 상태라 지금 세우면 다시 만들어야 한다 — `12` Q1·N2 답 이후"**로 잡혀 있었다. 그 판단을 **부분 철회**한다.

`30` ④의 신호는 두 층으로 나뉘고, 폐기 대기인 것은 그중 한 층뿐이다.

| 층 | 내용 | `12` Q1·N2에 걸리는가 |
|---|---|---|
| **관찰층** | "상품 사진에 통일된 스튜디오 배경·조명·구도가 있는가" — 페이지를 보고 사실을 기록 | **걸리지 않는다.** 답이 어느 쪽으로 나와도 관찰 항목과 관찰 방법은 그대로다 |
| **규칙층** | "그러므로 AI-Studio를 제안한다" — 기록된 사실로 결론을 냄 | **걸린다.** N2가 신호 방향을 뒤집을 수 있다 (`91` 2026-07-29) |

따라서 **관찰층 검증은 미팅 답을 하나도 기다리지 않고 지금 할 수 있다.** 규칙층 검증만 대기한다.

## 1. V1 — 신호 판정 일치 검증 (지금 실행) ★

### 무엇을 확인하는가

`30` ④는 신호 4종을 **"주관적 인상이 아니라 누가 봐도 같은 결론에 이르는 관찰 기준"**으로 정의했다. **이 전제는 한 번도 확인된 적이 없다.**

이게 무너지면 무너지는 범위가 넓다 — 목록의 신뢰도, `30` ⑤ 매칭의 입력, `30` ⑥ 메일에 들어갈 "귀사의 공개 정보에서 이런 점을 확인했다"의 근거가 전부 이 전제 위에 있다. 브리프 요구 ①(자동 탐색·목록화)과 ②(고객 특성 맞춤)가 함께 걸린다.

### 두 갈래로 나눠 잰다 — 이 구분이 V1의 핵심이다

| 갈래 | 무엇을 비교 | 불일치가 뜻하는 것 | 고쳐야 할 곳 |
|---|---|---|---|
| **V1-a** | 사람 ↔ 사람 | **기준 문장 자체가 모호하다** | `30` ④의 관찰 방법 서술 |
| **V1-b** | 사람 ↔ LLM(하네스) | 기준은 명확한데 **하네스가 못 따른다** | 하네스 프롬프트·입력 범위 |

둘을 섞으면 기준을 고칠지 하네스를 고칠지 알 수 없다. **V1-a를 먼저 끝내고 V1-b로 간다** — 기준이 모호한 상태에서 하네스를 맞춰봐야 무엇에 맞춘 것인지 모른다.

### 절차

1. **대상 선정** — 실제 해외 패션 도소매·브랜드 기업의 공개 페이지 **5~10곳**.
   - 타겟 국가는 미정(`90` 미결정 #5)이지만 **상관없다.** 신호 판정은 국가와 무관하다는 것이 이 검증의 전제이자 확인 대상이다.
   - 편향을 막기 위해 "잘 맞을 것 같은 곳"만 고르지 않는다. 이미지가 좋은 곳/나쁜 곳, 채널이 많은 곳/적은 곳을 섞는다.
2. **독립 판정** — 서로 다른 두 사람이 `30` ④ 표만 보고 각자 판정한다. **판정 중 상의하지 않는다.** 판정이 끝나기 전에 서로의 답을 보면 이 검증은 무의미해진다.
3. **기록** — 아래 양식으로 남긴다. 값만이 아니라 **그렇게 본 근거**를 반드시 적는다. 근거가 없으면 왜 갈렸는지 분석할 수 없다.
4. **대조** — 항목별로 일치/불일치를 표시하고, 불일치 건은 두 사람의 근거를 나란히 놓고 **무엇 때문에 갈렸는지**를 한 줄로 적는다.
5. **기준 수정** — 불일치의 원인이 기준 문장에 있으면 `30` ④를 고친다. 고친 내용과 이유를 `91`에 남긴다.
6. **V1-b** — 수정된 기준으로 하네스가 같은 5~10곳을 판정하게 하고, 3~5를 반복한다.

**V1-b는 무엇을 상대로 재는가 — 이것이 없으면 V1-b는 실행할 수 없다**

V1-b의 수정 대상은 "하네스 프롬프트"인데, **그 프롬프트가 저장소에 없으면 잴 대상이 없다.** V1-b를 돌리기 위한 최소 산출물은 다음 하나다.

| 무엇 | 어디에 | 무엇으로 정의되나 |
|---|---|---|
| 판정 규칙 문장의 **정본** | `32_하네스_스펙.md` 1절 제약 + `30` ④ 관찰 방법 (V1-a가 고친 문장) | Build Order ② Skill의 초안 |
| **실행체** 1개 | `.claude/skills/` 아래 (A의 도구로 만들어 즉시 돌린다) | `32` 3절 Subagent 4경계 — 입력 1건씩 / 출력 스키마 1행 / 도구는 공개 페이지 읽기까지 / 기업 1곳 = 컨텍스트 1단위 |

- **이 실행체는 구현 범위(⑤)가 아니라 ③의 검증 도구다.** `01` C4가 "지금 실행"이므로 여기 필요한 최소 1개는 E단계를 앞당기는 것이 아니다.
- **4경계를 지키지 않은 실행체로 V1-b를 돌리면 안 된다.** 특히 여러 기업을 한 맥락에 넣으면 앞 기업의 관찰이 다음 판정에 새어, 재고 있는 것이 기준인지 맥락 오염인지 구분되지 않는다.

### 기록 양식

```
기업: <이름>  URL: <홈페이지>  판정일: YYYY-MM-DD

| 신호 | 판정자 A | A의 근거 | 판정자 B | B의 근거 | 일치 | 갈린 이유 |
|---|---|---|---|---|---|---|
| 이미지 전문성 | 전문/비전문 | 어느 페이지의 무엇을 봤는지 | | | O/X | |
| 판매채널 수   | N개 | 어디에 명시돼 있었는지 | | | O/X | |
| 취급 SKU      | N개 | 어느 목록 페이지인지 | | | O/X | |
| 해외 대응     | 다국어/해외배송 유무 | | | | O/X | |
| 제외 여부     | 포함/제외 + 사유 | | | | O/X | |
| 판정 불가     | 해당 신호 / 사유 | 무엇 때문에 못 봤는지 | | | O/X | |
```

**판정 불가 행을 별도로 둔 이유**: 이 칸이 없으면 "못 본 것"이 옆 칸의 값으로 흘러 들어간다. 판정자 A가 못 보고 B가 봤다면 그건 기준 문장 문제가 아니라 **접근 조건 문제**이므로, 기준을 고쳐도 해결되지 않는다.

### 비율 합격선을 두지 않는다 — 그 이유

**표본 5~10건에서 나온 일치율(%)은 통계적 의미가 없다.** "80% 이상이면 합격" 같은 선을 그으면 근거 없는 임계값을 하나 더 만드는 것이고, 그건 `CLAUDE.md` 2절이 금지하는 "구체적인 척"이다.

이 검증의 목적은 **합격 판정이 아니라 결함 탐지**다. 따라서 규칙은 하나다 — **어느 항목이든 불일치가 1건이라도 나오면 그 항목의 기준 문장을 고친다.** 5~10건이라는 규모도 정밀 측정용이 아니라 결함 탐지용으로 잡은 것이며, 이 판단은 우리 것이지 외부 근거가 있는 값이 아니다.

**단, 이것은 성공 기준이 없다는 뜻이 아니다.** 위 규칙은 그대로 예/아니오로 판정된다 — **"불일치 항목이 0건인가."** 비율 임계값을 거부한 것이고, 판정 가능성을 포기한 것이 아니다(`02` 9절 원칙 ①). 비율 기준보다 **더 엄격한** 형태다.

### 판정 불가와 제외를 섞지 않는다

V1을 실제로 돌리면 바로 부딪히는 상태가 하나 있다 — **"봤는데 부적합"이 아니라 "못 봤다"**인 경우(사이트 접속 불가 / 스크립트 렌더링으로 상품 목록을 읽을 수 없음 / 로그인·회원가입 요구 / 상품 수가 페이지에서 세어지지 않음). `30` ④의 제외 조건 3종은 전부 앞쪽이고 뒤쪽은 정의돼 있지 않았다.

**판정 불가는 제외가 아니라 별도 상태로 남기고, 그 사유를 적는다.** 섞으면 90일 뒤 재수집 때 어느 쪽을 다시 열어야 하는지 알 수 없고, 판정자 간 불일치의 원인 분석도 오염된다("A는 못 봐서 비전문으로 적고 B는 봐서 전문으로 적었다"가 기준 문장 문제로 집계된다). `32` 2절 (a) 4번·`90` 리스크 17.

### 인원이 두 사람이 안 될 때

한 사람이 **시차를 두고 두 번** 판정한다(같은 날 연속으로 하면 앞 판정이 기억에 남아 일치가 부풀려진다). 그래도 V1-a의 목적인 "기준 문장이 모호한가"는 확인된다. 다만 **한 사람 안에서의 일관성**만 재는 것이므로 결과에 그 한계를 명시한다.

### 이 검증이 만들어내는 것

- `30` ④ 관찰 기준의 **수정본** — 실제로 갈린 지점을 근거로 고친 것
- 하네스 프롬프트에 그대로 들어갈 **판정 규칙 문장**
- `02` 7절이 요구하는 검증 기록 — *"신호 기준을 세웠고, 두 사람이 독립 판정해 어디가 갈렸고, 그래서 기준을 이렇게 고쳤다"*. **미팅 답 없이 지금 확보할 수 있는 유일한 검증 근거다.**

## 2. 대기 중인 검증 항목

| # | 검증할 것 | 무엇을 기다리는가 | 왜 지금 못 하는가 |
|---|---|---|---|
| V2 | **규칙층** — 신호 조합 → 제안 서비스 판별이 맞는가 | `12` Q1(AI-Studio 단독/Clo.D 포함)·N2(신호 방향) | 판별 규칙 자체가 폐기 대기(`30` 머리말). 지금 검증하면 검증 대상이 사라진다 |
| V3 | **국가 선정 임계값** — 축2 지출액 기준선이 국가를 실제로 가르는가 | 해외한류실태조사 **국가별 패션 지출액 분해**의 존재 여부 (`11` 7절 1번) | 확보한 $33.9는 30개 지역 전체 평균이라 국가 간 비교가 성립하지 않는다 |
| V4 | **메일 품질** — 생성된 메일이 회사 톤과 어긋나지 않는가 | `12` N6③(기존 영업 메일 실물)·Q16(금지 표현) | 비교 기준이 될 회사 화법 자료가 없다. 우리가 창작한 톤을 우리가 검증하는 것은 검증이 아니다 |
| V5 | **목록 규모의 적정성** — 만든 리드 수가 처리 가능한 범위인가 | `12` Q9(월 캐파)·Q10(최소 수주 금액) | 상한·하한이 미확인이라 판정 기준이 없다 (`90` 리스크 11) |
| **V6** | **신호 4종 자체의 타당성** — 이 신호로 고른 기업이 실제로 살 만한 기업인가 | `12` **N6⑧ 국내 고객사 업종·규모 분포** | **미팅 답이 아니라 자료를 기다린다** — 국내에서 실제로 통한 고객 유형이 있으면 거기서 신호를 **역산**해 우리가 세운 4종과 대조할 수 있다. 지금은 대조할 실데이터가 없어 신호가 우리 추론 위에만 서 있다 |

**V6는 V1·V2와 무엇이 다른가.** V1은 *기준 문장이 모호한가*, V2는 *신호 → 제안 규칙이 맞는가*를 재는데, V6는 **신호 항목 자체를 잘못 골랐을 가능성**을 잰다. 셋 중 가장 근본을 겨냥하지만 우리 힘으로 확보할 수 없는 자료에 걸려 있다 — V1을 먼저 하는 이유이기도 하다.

**V2~V6는 검증 방법을 지금 설계하지 않는다.** 대상이 확정되기 전에 절차를 만들면 대상이 바뀔 때 절차도 버려진다. 여기서는 **무엇을 기다리는지만** 고정해 둔다.
