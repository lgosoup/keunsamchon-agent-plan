## 1. 전체 목표

### 1-1. 기업이 파는 것 — 이것이 플로우의 출발점

**Clo.D AI-Studio**: 제품 또는 제품 사진만 있으면, 상대적으로 저렴한 가격에 **AI로 모델을 생성해 광고용 사진·영상을 만들어 준다.**

이 한 문장이 타겟 조건을 그대로 결정한다.

| 조건 | 왜 이 조건인가 | 지위 | 출처 |
|---|---|---|---|
| **제품이 있다** | 제품이 없으면 만들 것이 없다. 제품 사진이 있으면 최적이고, 없으면 제품 실물을 받아 직접 촬영한다 | **필수** | `13S` K9 |
| **커머스가 있다** | 광고 사진·영상을 쓸 자리가 있다는 뜻. 커머스를 운영하면 제품 사진도 이미 존재한다 | **필수** | `13S` K2 |
| **업종이 패션·뷰티·푸드다** | 기업이 대상 영역으로 지목한 것. 레퍼런스가 이 영역에 쌓여 있다. 그 안에서 **패션 → 코스메틱** 순 | **필수** | `13S` K4·K3 |

- **커머스를 "우선순위 높음"에서 "필수"로 확정했다.** 이전 서술은 1-1절이 "높음", 목표 문장이 "제품과 커머스를 가진"(둘 다 필수), 규칙층이 이진 판정으로 세 곳이 어긋나 있었다. **필수로 통일한 근거**: 커머스가 없으면 광고 사진·영상을 쓸 자리가 없어 제안 자체가 성립하지 않는다. 커머스 없는 제조사를 넣으려면 별도 제안 논리가 필요하고 그건 지금 범위 밖이다.
- **"한국 진출을 원한다"는 조건은 2026-08-03 완전히 뺐다 (경위 요약, 상세는 `90` 리스크 24·`91` 로그).** K4(기업이 직접 말한 제약, `13S` A/09:34)는 존중하되, ① `12` N22로 기업에 직접 재확인한 결과 *"한국 진출 계획이 없는 브랜드도 대상"*이라는 답을 받았고 ② 예비 실측(일본 기업 3곳)에서 4개 관찰 신호가 전부 0/3으로, 이 카드가 예고해 둔 하향 조건(관찰률 0)이 충족됐다. 우선 필수 게이트에서 적합도(G3) 가점으로 내렸다가(2026-08-01), MVP가 "컨택 기회 확보"로 재정의되며(8-1절) **G1 관찰 자체에서도 뺐다** — 부가 기능 G3이 착수되면 필요 여부를 다시 본다.
- `30` ④가 1차 판별축으로 삼았던 "이미지 전문성 전문/비전문"은 여기서 교체된다. 1차는 **위 세 조건**이고, 이미지 전문성은 그다음 층의 우선순위 항목으로 내린다 (`13S` H4).

### 1-2. 왜 막혀 있는가 — 기업의 실제 상태

기업은 해외에 AI-Studio를 쓰게 하고 싶다. 그런데,

- **직접 일본에 가서 해봤고, 어려웠다.** 시장 조사부터 잠재고객 수집까지 쉽지 않았다 (`13S` F10)
- **협력사 의존적이다.** 협력사를 통해야 진행되고, 협력사는 자기가 경험한 영역만 다룬다 (`13S` F10)
- **지금은 일본 협력사의 시간이 나지 않아 진행 자체가 멈춰 있다** *(출처: 사용자 전언. `13`의 설명회 기록에는 없다 — 확인 항목)*

→ **그래서 이 접촉 과정을 AI로 반자동화 루틴으로 만든다.** 목적은 사람을 없애는 것이 아니라 **협력사 일정에 묶여 멈추는 구조를 푸는 것**이다.

### 1-3. 왜 일본인가

**국가 자체는 기업이 지정했다** — *"1차적으로 일본 시장을 생각하고 있다"* (`13` 1-7절, A/13:37). 우리가 고른 것이 아니다.

**그 이유로 든 세 가지는 출처가 갈린다. 섞어 쓰면 안 된다.**

| 이유 | 출처 | 지위 |
|---|---|---|
| 거리 — 가장 가깝다 | 사용자 작성 플로우 원문 | **우리 판단 (근거 4순위, 미검증)** |
| K문화 적합도가 높다 | 사용자 작성 플로우 원문 | **우리 판단 (근거 4순위, 미검증)** |
| **이미 일본에 협력사가 있다** | `13S` F10 | **기업 발언 (근거 1순위)** |

- **기업이 "가깝고 K문화 적합도가 높아서 일본"이라고 말한 기록은 없다.** 설명회 발언에서 확인되는 것은 국가 지정과 일본 방문·협력사 의존뿐이다. 심사나 미팅에서 이 둘을 기업 발언으로 인용하면 사실이 아니다.
- K문화 적합도는 검증할 재료가 있다 — `11_대안탐색_비교.md` 축2(해외한류실태조사 패션 지출액). **일본을 그 축으로 대조해 두면 우리 판단이 관측과 맞는지 확인된다** (`13` 7-1절 R1).

**일본 하나로 만들고, 성공하면 다른 국가로 확대한다**(7절).

### 1-4. 목표 문장

> **일본에서, 제품·커머스를 갖고 패션·뷰티·푸드를 다루는 기업을 찾아 적법하게 연락 가능한 담당자에 도달하고, 세그먼트별로 설계된 제안 메일을 일본어로 보내고, 그 반응을 사람이 판단할 수 있는 형태로 되돌리는 — 반자동 접촉 플로우를 설계한다.**

### 1-5. 이 프로젝트가 검증 게이트를 다루는 방식 — Build Order 전체가 참조하는 정신 (2026-08-03)

**컨택 기회를 확보하는 것이 1순위다.** 이 프로젝트의 자동화는 넓게 접촉을 시도하는 것이 목적이고, 근거 없는 검증 게이트·관찰 항목이 쌓여 후보를 사전에 다 걸러내면 그 목적 자체가 성립하지 않는다. 실제로 이 원칙에 따라 필수 조건 4종을 3종으로 줄이고(1-1절), G1의 관찰 항목에서 근거 없이 비용만 늘리던 값들을 뺐다(`기준/G1` 변경 이력). **순위매기기(G3)는 부가 기능으로 이연됐다** — 컨택 기회를 넓히는 것 다음의 일이기 때문이다(8-1절).

**Spec은 목표와 조건만 못박고, 그것을 이루는 "how"는 각 기능을 실행하는 서브에이전트의 판단에 맡긴다.** 목표 문장이 설계 목표이면서 동시에 검증 기준이 된다 — Skill·Subagent를 만드는 사람은 "이 절차를 그대로 따랐는가"가 아니라 "이 목표를 달성했는가"로 자기 산출물을 점검해야 한다. 이는 새 규칙이 아니라 이미 이 저장소의 Spec 6요소 형식(목표+성공 기준만 쓰고 절차는 안 쓴다, `../specs/README.md`)과 `CLAUDE.md` 5절 "절차 상한"(지우면 출력이 바뀌는가) 원칙이 요구해 온 것이다 — 이 문서가 그 정신을 프로젝트 전체 목표 층위에서 다시 확인해 두는 것뿐이다. 지금 무엇이 MVP이고 무엇이 부가인지는 8-1절.

## 2. 전체 플로우

> **이 그림은 전체 설계다 — 지금 다 만드는 것은 아니다.** MVP 범위(지금 만드는 것)와 부가 범위(이연)는 8-1절 표를 본다. 이 그림의 G3·G8·G9·G10·G11 관련 간선(적합도 순위·재시도·위임·재수집·집계)은 부가 범위이며, MVP 쪽 기능(G4·G5)이 이 간선에 의존하던 자리는 대체 규칙(세그먼트 대표 우선/라운드로빈)으로 대신한다.

```
[대상 만들기]                                          ┌──── 재조사 ────┐
  G1 일본 기업 발굴 ─── 제품 있는가 / 커머스 있는가 ◀──┤                │
        │                                              │                │
        ├──→ G2 세그먼트화 ─── 메일을 같은 방식으로    │                │
        │         써도 될 기업끼리 (품목·규모 등)      │                │
        │                                              │                │
        ├──→ G3 적합도 평가 ─── 자원을 쓸 가치의      │                │

        │                                              │                │

### 이 플로우의 두 가지 설계 의도

**① 노력을 기업 수가 아니라 그룹 수에 비례하게 만든다.** G2에서 묶고, G5에서 그룹 대표 한 곳만 집중해 문안을 만들어 그룹 전체로 확장한다. 기업이 100곳이어도 그룹이 5개면 집중 작업은 5번이다.

**② 사람이 직접 움직이는 대상을 좁힌다.** G9로 넘어가는 두 경로 모두 **적합도(G3)가 높은 곳만** 넘긴다. 넘길 때 자료를 던지지 않고 "어떤 기업이고 왜 우리와 맞는지"를 정리해 넘기므로, 사용자가 시간을 크게 들이지 않고 판단할 수 있다. 1-2절의 협력사 병목에 직접 대응하는 장치다.

**③ 한 번 흐르고 끝나지 않는다 — 되돌아오는 경로가 둘이다.**

- **G10 재수집 판단** — 잘못 조사된 것(G8 조사 오류), 지금은 연락처를 못 찾은 것(G4 미확보), 지금은 적합도가 낮은 것(G3 보류)은 **버리는 게 아니라 다시 열 대상**이다. 시장이 바뀌면 판정도 바뀐다.
- **G9에서 사람이 찾아낸 연락처** — 사람이 주변·협력사를 돌려 연락처를 확보하면 그 결과가 **G4 확보분에 합류해 G5로 흐른다.** 사람의 작업이 플로우 밖으로 새지 않는다.

이 두 경로가 없으면 한 번 걸러진 기업이 영구히 사장되고, 사람이 애써 찾은 연락처가 어디에도 쓰이지 않는다.

## 3. 기능 분해

기준: **완결된 산출물 하나 = 기능 하나.** 순서는 경계가 아니다.

### 3-1. 기능 목록

| ID | 기능 | 한 줄 정의 | 완결 산출물 |
|---|---|---|---|
| **G1** | 대상 기업 발굴 | 조건을 만족하는 일본 기업을 찾아 관찰 사실로 기록한다 | 기업 후보 목록 + 각 판정의 관찰 근거 |
| **G2** | 세그먼트화 | 메일을 같은 방식으로 대해도 될 기업끼리 묶는다 | 세그먼트 체계 + 각 기업의 소속 + 분류 근거 |
| **G3** | 적합도 평가 | 이 기업에 자원을 쓸 가치를 하나의 척도로 잰다 | 기업별 적합도 + 그 판단 근거 |
| **G4** | 연락처 확보 | 실제로 의미 있는 연락 창구를 찾는다 | 유효 연락처 **또는** 미확보 사유·탐색 범위 |
| **G5** | 제안 메일 제작·발송 | 그룹별 문안을 만들어 일본어로 발송한다 | 발송 기록 (어느 기업에 언제 어떤 문안으로) |

### 3-2. 기능별 입출력

#### G1 — 대상 기업 발굴

| | |
|---|---|
| **입력** | 국가(일본) ← 외부 · **타겟 조건 3종**(제품 / 커머스 / 업종 — 1-1절) ← 외부 · **탐색 소스**(아래) ← 외부 · **G10 재수집 대상** |
| **출력** | **관찰층 + 규칙층 두 층으로 나눠 저장**(아래) |
| **소비처** | G2 · G3 · G4 (그리고 G5·G8·G9가 관찰층 근거를 다시 참조) · **판정 불가분은 G10** |
| **독립 근거** | 산출물이 "목록"이고, 뒤 기능 세 개가 각자 다른 용도로 이 목록을 받는다 |

**탐색 소스 — 후보이며 확정 아님**

| 후보 | 근거 |
|---|---|
| **Qoo10 · 라쿠텐 등 일본 커머스 플랫폼** | **기업이 실제로 여기서 리스트를 뽑아본 적이 있다** (`13S` F14). 검증은 안 했지만 수백 개 규모가 나왔다 — 실증된 유일한 후보 |
| 일본 패션 업계 디렉토리 · 협회 · 전시회 참가기업 목록 | 커머스 플랫폼에 없는 기업을 잡는 보완 경로 |
| 개별 기업 홈페이지 | 위에서 찾은 기업의 관찰 항목을 채우는 데 쓴다 |

- **어느 소스를 쓸지는 여기서 확정하지 않는다.** 소스 선택은 비교·검증 근거가 필요한 사안이고 `11_대안탐색_비교.md`가 담당한다. 다만 **기업이 써본 소스가 1순위 후보**라는 것은 근거 1순위에서 나온 사실이다.
- KOTRA는 국가 정보 중심이라 **기업 발굴 소스로는 역할이 다르다** — 국가 선정용이지 이 기능의 입력이 아니다.

**출력 — 관찰층과 규칙층을 갈라 저장한다**

```
[관찰층] 페이지를 보고 기록한 사실. 타겟 조건이 바뀌어도 그대로 남는다
  기업명 · URL · 취급 품목
  제품 사진 보유     : 있음/없음    + 근거(본 페이지와 무엇을 봤는지)
  커머스 보유        : 있음/없음    + 근거
  업종               : 패션/뷰티/푸드/기타 + 근거
  기업 규모 신호     : 관찰된 것    + 근거   ← G2 분류가 요구(상품수·채널수만, 2026-08-03)
  광고 메일 거부 표시: 있음/없음/?  + 근거   ← 있음·애매면 2026-08-03부터 여기서 바로 발송금지 목록行, 그룹화(G2) 대상 제외. 없음 확인된 것만 G2로
  판정 불가          : 해당 항목 + 사유 (제외와 다른 상태)
  수집일

[규칙층] 관찰층으로 낸 결론. 조건이 바뀌면 이 층만 다시 계산한다
  타겟 조건 충족 여부 / 제외 여부 + 사유 / 발송 가능 여부
```

- **기업 규모는 뒤 기능(G2)이 요구해서 추가했다.** G2는 분류축에 "기업 규모"를 쓰는데, 관찰 항목에 규모가 없으면 **G2의 Spec을 쓰는 순간 G1을 다시 열어야 한다** — 이 문서 머리말이 세운 경계 시험에 걸린다. (**한국 진출 희망 신호는 2026-08-03 관찰층에서 뺐다** — 8-1절, `기준/G1` 변경 이력)
- **무엇을 규모 신호로 볼지는 지금 정하지 않는다.** 관찰 가능한 후보(취급 품목 수·입점 채널 수·회사 소개의 규모 기재 등)는 G1 Spec에서 고른다. 여기서는 **항목의 존재만 확정**한다.

- **층을 가르는 이유**: 타겟 조건이 조정되거나 G10이 재수집을 걸 때 **관찰층만 갱신하면 규칙층은 다시 계산된다.** 한 덩어리로 저장하면 조건이 바뀔 때마다 조사를 처음부터 다시 한다. (`02` 9절 ③ — 뒤집힐 것과 안 뒤집힐 것을 갈라 저장)
- **관찰층의 근거 칸이 이 플로우 전체의 원재료다.** G5 메일 본문의 "귀사의 공개 정보에서 이런 점을 확인했다"와 G9 브리프의 "우리와 맞는 이유"가 모두 여기서 나온다. **근거가 비면 맞춤 근거도 빈다.**
- **"봤는데 아니다"와 "못 봤다"를 같은 칸에 넣지 않는다.** 사이트 접속 불가·상품 목록을 읽을 수 없음 등은 판정이 아니라 **판정 불가**이며 사유와 함께 남긴다. 전자는 결론이고 후자는 **G10 재수집 대상**이다 (`90` 리스크 17).
- 어느 항목이 어느 층인지는 잠정이다 — 사람 간 판정이 갈리는 항목은 관찰이 아니라 판정이므로 규칙층으로 내린다(`40` V1).

#### G4 — 연락처 확보

| | |
|---|---|
| **입력** | G1 후보 목록 · G3 적합도 · **G9에서 사람이 찾아낸 연락처** · **G10 재탐색 대상** |

- **"유효"는 존재가 아니라 의미 있는 창구인지**다. 담당자·제안 접수처에 닿는가를 본다. 일반 문의 폼만 있는 경우와 담당자 주소를 확보한 경우를 구분한다. **Spec·기준 카드 확정**: `specs/G4_연락처확보.md`·`기준/G4_연락처유효성기준.md`(2026-07-30).

**[발송 금지] 상태가 왜 있는가 — 일본 특정전자메일법**

일본은 광고·선전 메일에 **사전 동의(옵트인)를 원칙**으로 한다. 예외는 **웹에 메일 주소를 공개한 단체·영업 영위 개인**이며, 우리가 노리는 B2B 콜드메일은 이 예외에 해당한다. **그런데 예외에는 조건이 있다.**

> 공개된 주소 **바로 앞이나 뒤에** "특정전자메일·광고메일·선전메일·迷惑메일" 등의 말과 "거부·お断り·送信しない" 등이 결합된 **수신 거부 의사 표시가 있으면 예외가 적용되지 않는다.** 그 주소로 보내면 위법이다.

→ **연락처를 찾는 것과 그 주소로 보낼 수 있는지는 다른 판정이다.** 그래서 G4의 출력을 확보/미확보 둘이 아니라 **네 상태**로 둔다([메일 없음]은 2026-08-03 추가 — 폼-only는 [확보]가 아니다).

- **[발송 금지]는 제외·판정 불가·미확보와 모두 다르다.** 제외는 조건 미달, 판정 불가는 못 봤음, 미확보는 주소를 못 찾음이다. 발송 금지는 **주소를 찾았고 보내면 위법인 것**이므로 G10 재수집 대상에서도 빼야 한다 — 다시 열어도 결론이 같다.
- **이 회사는 같은 유형의 사고를 이미 겪었다** — SNS 규정 변경을 실시간으로 추적하지 못해 계정 정지·1주간 발송 불가·증빙자료 반복 제출(`13S` F12). 규제 확인을 발송 뒤로 미루면 그 사고를 메일에서 반복한다.
- 판정 기준의 구체적 문구·표시 위치 판별은 G4의 Spec에서 정한다.

**발송 기록에 반드시 남겨야 하는 항목 — 지금 정한다**

> ⚠ **이 표는 G5 Spec 단계로 미루지 않는다.** 나머지는 미뤄도 되지만 이것은 안 된다 — **기록하지 않은 데이터는 나중에 소급해서 만들 수 없다.** 발송이 시작된 뒤 "세그먼트별로 무엇이 통했는지 집계하자"고 해도, 발송 시점에 세그먼트를 남기지 않았으면 그 집계는 영구히 불가능하다.

| 항목 | 누가 요구하는가 |
|---|---|
| 기업 식별자 · 발송일시 · 수신 주소 · 제목 · 본문 | **G6·G7** (최소 요구) |
| **어느 세그먼트의 문안이었는가** | **G11** — 세그먼트별 반응 차이를 보는 축. 이게 없으면 G2의 분류축이 맞았는지 영구히 확인 불가 |
| **본문에서 G1 관찰층의 무엇을 근거로 인용했는가** | **G11** — 어느 근거가 통했는지 |
| **무엇을 제안했는가** | **G11** · G7(회신이 답인지 판정) |
| 발신 언어와 번역 검증 결과 | G7(회신이 어긋난 원인 구분) · **G11** |

- **G5 출력 규격의 상한은 G7이 아니라 G11이 정한다.** `specs/G7`은 최소(제목·본문·발송일시·수신 주소)만 요구하고 **없어도 성립하게 닫았다** — 병렬 작업에는 그게 옳다. 그러나 **G7만 보고 G5를 설계하면 G11이 성립하지 않는다.**
- 각 항목의 세부 형식(식별자 체계·날짜 형식 등)은 G5 Spec에서 정한다. **항목의 존재만 여기서 확정한다.**

**이 기능 안의 하위 설계** (지금 쪼개지 않고 G5의 Spec 단계에서 다룬다)

- 그룹 대표 기업 1곳에 대한 **집중 문안 제작**
- 그 문안을 그룹 전체로 **확장 생성**. G1 관찰층 근거를 본문에 인용해 **"왜 귀사인가"를 메일 안에서 설명한다** (원안 D-4 커뮤니케이션 깊이 승계, `99` 4절)

#### G7 — 회신 해석·정리

| | |
|---|---|
| **입력** | 회신 메일(일본어) ← 외부 · G5 발송 문안(무엇에 대한 답인지 대조) |
| **출력** | **한국어 해석** + 회신 성격 분류 + **번역 검증 결과** |
| **소비처** | 사용자 (주 종점) · **수신 거부분 → G4·G5 발송 금지 목록** · **자동응답 판정분 → G6 판정 정정** · **회신 성격 → G11**(무엇이 통했는지의 재료) |
| **독립 근거** | 산출물이 "사용자가 읽을 수 있는 상태의 회신"이고, 발송 결과 판정(사실)과 달리 **해석**이다 |

**되돌아가는 출력 2건 — `specs/G7_회신해석정리.md`가 요구해 2026-07-30 추가했다**

| 출력 | → | 왜 |
|---|---|---|
| **수신 거부 의사** | **G4·G5 발송 금지 목록** | **법 요건이다.** 상대가 거부 의사를 밝혔는데 그것이 발송 대상에 반영되지 않으면 다음 발송이 위법이 된다. G4의 [발송 금지] 상태와 같은 목록으로 들어간다. **분류 결과와 무관하게 병렬로, 즉시** 처리한다 — 거절 메일이든 관심 메일이든 거부 의사가 있으면 그것이 우선이다 |
| **자동응답 판정** | **G6 판정 정정** | 부재중·자동회신은 사람의 응답이 아니다. G6이 "회신 있음"으로 판정한 것을 **G7이 되돌려야** 회신율 통계와 G8의 원인 분석이 오염되지 않는다 |

- **이 두 경로가 G7을 순수 종점에서 벗어나게 한다.** 기능 Spec을 쓰는 과정에서 발견된 것이며, **Spec이 상위 문서(기능 구조)를 고치게 만든 첫 사례**다 — 폭포수라도 뒤 단계가 앞 단계의 결함을 찾으면 앞을 고친다.

**여기가 이 플로우의 경계다 — 그 사실을 명시한다**

회신을 사용자에게 전달한 뒤 미팅 → 견적 → 영문 계약 → 결제가 이어진다. **그 단계는 이 플로우에 없다.** 기업 자신이 이 지점을 짚었다 — *"담당자와 접촉이 성립됐을 때는 아마 **대응이 좀 필요하잖아요**… 보내기에 집중하기보다는 그분들과 관계를 형성해 나가는 부분에 집중할 것"* (`13S` F16).

- **기능을 만들지 않는 이유**: 기업의 실무 준비 상태(견적·영문 계약·결제 수단)가 **미확인**이다 (`13S` U7, `12` N4·Q12). 준비되지 않은 단계를 설계하면 쓰이지 않는 기능이 된다.
- **그런데 답이 "준비 안 됐다"면 이 프로젝트의 우선순위가 바뀐다.** 리드를 늘리는 것보다 회신 처리 경로를 만드는 것이 먼저가 된다. → **`13` 8절에 확인 항목으로 올린다(N20).**
- 경계를 적어 두지 않으면 "리드는 만들었는데 계약이 0건"인 결과가 설계 실패로 읽힌다. 경계인 것과 빠뜨린 것은 다르다.

| | |
|---|---|
| **입력** | **[경로 1]** G4 미확보 + G3 적합도 + G1 근거 / **[경로 2]** G8 재시도 대상 + 원인 + G1 근거 |
| **출력** | ① 기업별 브리프 — **어떤 기업인지 / 우리 회사와 맞는 이유와 그 근거 / 유입 사유**(연락처 미확보·재시도) → 사용자<br>② **사람이 접촉해 찾아낸 연락처** → G4 |
| **소비처** | 브리프 → 사용자 · 찾아낸 연락처 → **G4 확보분에 합류** |
| **독립 근거** | 유입 경로는 둘이지만 **출력 형태가 같다.** 두 기능으로 나누면 같은 산출물을 각자 만들게 된다 |

#### G10 — 재수집 판단

| | |
|---|---|
| **입력** | G3 보류분(적합도 낮음) · G4 미확보분 · **G8 조사 오류·가치 低 판정분** · **시간 경과 / 트렌드 변화 신호** ← 외부 |
| **출력** | 재수집 대상 + 재수집 사유 + **무엇을 다시 볼 것인지** (전체 재조사 / 특정 관찰 항목만 / 연락처만) |
| **소비처** | 전체·항목 재조사 → **G1** / 연락처만 → **G4** |
| **독립 근거** | 네 곳의 출력이 **수렴하는 지점**이고, 산출물이 "재수집 대상"이라는 별개 목록이다. 그리고 **본 플로우와 다른 리듬으로 돈다** — 앞 단계가 끝나야 도는 것이 아니라 주기적으로 판단한다 |

- **왜 필요한가**: 이 기능이 없으면 플로우가 한 번 흐르고 끝나고, **한 번 걸러진 기업은 영구히 사장된다.** 지금 커머스가 없는 곳이 6개월 뒤에 열 수도 있고, 지금 연락처를 못 찾은 곳이 담당자 정보를 갱신할 수도 있다.
- **"무엇을 다시 볼 것인지"가 출력에 반드시 있어야 한다.** 전체 재조사와 연락처만 재탐색은 드는 비용이 전혀 다르다. 이 구분이 없으면 매번 전체를 다시 돌게 된다. **G1의 관찰층/규칙층 분리가 이 구분을 가능하게 하는 전제다** — 관찰 항목 하나만 갱신하고 규칙층을 재계산할 수 있어야 "특정 항목만"이 성립한다.
- **G8의 "조사 오류"가 가장 직접적인 입력이다.** 잘못 조사된 연락처로 보내 실패한 것은 **버릴 대상이 아니라 다시 조사할 대상**이다.
- **재수집 주기·경과 기간 같은 수치는 이 단계에서 정하지 않는다** — G10의 Spec에서 정한다.
- **Spec 확정**: `specs/G10_재수집판단.md`(2026-07-30). 재조사 항목은 **G1 관찰 코드(O1~O9)로만** 지정하고, **재수집 주기(며칠마다)는 수치를 정하지 않는다** — 구 60일·90일은 근거 상실로 폐기됐고(`90` 리스크 4) 새 수치도 만들지 않았다. 별도 기준 카드 없음.

#### G11 — 반응 집계·기준 조정

| | |
|---|---|
| **입력** | G5 발송 기록(어느 세그먼트 문안 / 무엇을 인용·제안했는지) · G6 상태 · G7 회신 성격 · G8 원인 가설 · G2 세그먼트 체계 · G3 적합도 |
| **출력** | 세그먼트·조건 조합별 반응 집계 + **기준 조정 제안** — 어느 세그먼트의 우선순위를 올리거나 내릴지, 어느 조건이 반응과 무관했는지, **각각의 근거와 함께** |
| **소비처** | **G2**(세그먼트 축 재편) · **G3**(적합도 척도 조정) |
| **독립 근거** | 산출물이 "집계와 조정 제안"이라는 별개의 것이고, **다섯 기능의 출력이 수렴한다.** 그리고 본 플로우와 다른 리듬으로 돈다 — 발송·회신 데이터가 쌓인 뒤에야 의미가 생긴다 |

- **왜 필요한가 — 이게 없으면 G2·G3의 기준이 한 번 정해지고 영원히 바뀌지 않는다.** 특히 4-2절에서 **맞춤의 단위를 세그먼트로 골랐으므로**, 그 축이 맞았는지 확인하는 **유일한 경로가 그룹별 반응 집계**다. 세그먼트 축이 틀렸는데 확인할 방법이 없으면 브리프 요구 ②의 근거가 검증되지 않은 채로 남는다.
- **출력은 "조정 제안"이지 자동 적용이 아니다.** 판별 기준이 사람 모르게 바뀌면 "왜 이 기업이 선택됐는가"를 설명할 수 없게 되고, 그건 이 과제가 요구하는 설명 가능성과 반자동 원칙을 동시에 깬다.

## 5. 원문 플로우와 다르게 잡은 곳

### ① 원문의 "자동으로 보낼거지"를 발송 전 확인 지점으로 바꿨다

원문은 자동 발송을 명시했다.

> *"그렇게 만들어진 이메일 형식을 ai를 이용해 자동으로 그 그룹에 대해서 이메일 들을 만들어서 **자동으로 보낼거지**"*

**바꾼 근거**: 브리프 원문이 요구한 것은 "**반자동** 작성·발송"이고, 기업도 *"100% 자동화는 어렵다, 사람의 터치는 없을 수 없다"*고 말했다(`13S` K6). **완전자동 발송 경로를 두면 브리프 요구사항 위반이다.**

→ G5 안에 발송 전 확인 지점을 둔다. **원문과 기업 발언이 어긋나는 지점이며 기업 쪽을 따랐다**(근거 우선순위 1순위, `CLAUDE.md` 4절).

> 이 변경을 기록하는 이유: `reference/`의 원문이 사용자 의도의 정본이므로, 기록이 없으면 다음 사람이 원문을 근거로 자동 발송으로 되돌릴 수 있다. **브리프 3대 요구 중 하나가 이 한 줄에 걸려 있다.**

### ② 연락처 확보에 "발송 금지" 상태를 추가했다

원문은 연락처를 확보/미확보로만 갈랐다. 일본 특정전자메일법의 옵트인 예외 조건 때문에 **주소를 찾았어도 보낼 수 없는 경우**가 존재한다(3-2절 G4). 원문에 없던 상태이며, 없으면 위법 발송이 걸러지지 않는다.

### ③ "읽음 / 안 읽음"을 분기에서 뺐다

원문은 읽음 · 안 읽음 · 주소 오류 3분기였다. 그런데 **읽음 추적은 픽셀 방식이라 차단·규제로 정확도가 낮다**(`90` 리스크 3). 확실히 알 수 있는 것은 **주소 오류(바운스)와 회신 유무**뿐이다.

→ G6을 **회신 / 무응답 / 주소 오류**로 잡고, 읽음 여부는 보조 신호로만 둔다. 원문도 *"봤지만 회신이 없는 건 위에 메일 읽었을 때 회신 안 옴과 같은 경우로 보려 함"*이라 했으므로 **결과는 일치한다.** 그리고 기업이 요구한 "안 읽음 / 주소 오류" 구분은 **바운스 코드 분류**로 실현된다(3-2절 G6).

**위 세 가지 외에는 원문 플로우를 그대로 따랐다.** ①은 기업 발언이 원문을 이기는 경우, ②는 법 요건이 원문에 없던 상태를 만든 경우, ③은 기술적으로 성립하지 않아 바꾼 경우다.

## 8-1. MVP 범위 — 지금 만드는 것 (2026-08-03)

**1-5절의 정신("컨택 기회 확보가 1순위")을 실제 범위로 갈랐다.** 기능은 11개 전부 설계돼 있으나(폐기된 것은 없다), 지금 구현하는 것과 부가 기능으로 이연한 것을 가른다.

| 상태 | 기능 | 왜 |
|---|---|---|
| **MVP — 지금 만든다** | **G1**(탐색, 관찰 항목 축소) · **G2**(그룹화, G1 데이터로 바로 진행) · **G4**(연락처, 세그먼트 대표 우선) · **G5**(발송, 세그먼트 라운드로빈 + 사람 승인 게이트) · **G6·G7**(발송 결과 판정·회신 해석 — 최소한의 반응 처리) | **6개.** 브리프 3대 요구(①자동 탐색·목록화 ②고객 특성 맞춤 ③반자동)는 앞의 4개(G1·G2·G4·G5)로 충족한다(①=G1+G2+G4, ②=G2+G5, ③=G5 승인 게이트). 여기에 **회신을 사람에게 되돌리는 최소 경로로 G6·G7을 더한다** — 이게 없으면 "메일 보낸 뒤 아무것도 안 돌아온다"가 되어 반자동의 취지(사람이 다음 대응을 판단한다)가 발송 이후로는 끊긴다. *"메일 보내야 한다 → 형식을 어떻게 하나 → 유사 그룹을 만들어 대표 하나를 자세히 쓴다(사람이) → 그 형식을 그룹에 적용 → 발송(또는 사람 검토·승인) → 결과·회신을 사람이 확인한다"*가 이 여섯 기능의 흐름 그대로다 |
| **부가 — 나중에 만든다** | **G3**(적합도 순위) · **G8**(원인 분석) · **G9**(위임 브리프) · **G10**(재수집 판단) · **G11**(반응 집계·기준 조정) | 순위매기기·재시도·재수집·학습은 컨택 기회를 넓히는 것보다 뒤에 오는 일이다. G3은 착수 조건(`12` Q3·Q5 답 또는 실제 회신 데이터)이 따로 있고, G8·G9·G10·G11은 발송 데이터가 쌓여야 의미가 생긴다 |

**이연은 폐기가 아니다.** 다섯 기능의 Spec·기준 카드는 그대로 남아 있고, 착수 조건이 오면 그 상태에서 이어 만든다(`../docs/33_설계근거.md` D15). MVP 쪽 기능(G4·G5)이 G3 출력에 의존하던 자리는 대체 규칙(세그먼트 대표 우선/라운드로빈)으로 메웠다 — 대체 규칙 없이 그냥 끄면 G4·G5의 성공 기준이 판정 불가능해진다.

**MVP 잔여 처리.** G4 [미확보]·[메일 없음]·G1 판정 불가·G2 U-정보없음·G6 무응답·주소오류는 정식 소비처(G9·G10)가 부가 이연이라 MVP 기간엔 갈 곳이 없다 — 버리지 않고 `candidates/보류목록.md`(G4 반영 완료, G1·G2·G6은 다음 작업)에 남긴다(`90` 리스크 35). 협업사 등을 통한 추가 컨택 시도(폼 제출 포함) 여부는 기업이 직접 판단한다 — 이 도구는 저장까지만 한다. 세그먼트 대표 기업이 [미확보]면 그룹 차선 대표를 승격하는 규칙은 `기준/G2` 3절.
