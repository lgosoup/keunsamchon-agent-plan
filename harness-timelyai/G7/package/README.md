# G7 TimelyAI 패키지 — 업로드 방법

이 폴더는 TimelyAI 워크스페이스에 **그대로 업로드**하기 위한 것이다. 설계 근거는 `../00_TimelyAI_매핑설계.md`, 정본은 `../spec.md` · `../기준.md`(둘 다 이 harness 폴더 안에 있음 — `keunsamchon-agent-plan` 저장소의 `specs/`·`기준/`에서 복사해온 사본).

## 업로드 순서

0. **G7 전용 새 워크스페이스를 만든다.** 기존 워크스페이스에는 `resend`가 이미 공용으로 연결돼 있어(확인됨, 2026-08-05) 스킬 단위로 끌 수 없다 — 새 워크스페이스에는 **처음부터 어떤 커넥터도 추가하지 않는다.** 이게 "발신 도구 접근 없음"을 권한으로 막는 유일한 방법이다.

1. **스킬 2개**
   - `skills/g7-interpret/` 폴더를 zip으로 압축 → TimelyAI 우측 패널 「스킬」 탭의 `+` → `.skill`/`.zip` 업로드
   - `skills/g7-verify/` 폴더도 동일하게 압축·업로드
   - 업로드 후 두 스킬 모두 **토글을 켜되, 이 스킬들에 `resend` 커넥터를 연결하는 옵션이 있으면 반드시 끈다.**

2. **자동화 1개**
   - `automation/AGENT.zip`(내용물: `AGENT.md`)을 업로드. **확인됨(2026-08-05)**: 파일명이 한글이면(`g7-회신처리.md`) `invalid_name` 오류로 등록이 실패한다 — 파일명·frontmatter의 `name:` 값 모두 영문 소문자·숫자·하이픈만 써야 한다. 그래서 파일명을 `AGENT.md`로, `name:` 값을 `g7-reply-pipeline`으로 고정했다.
   - 자동화 편집창에서 1단계=`g7-interpret` 호출, 2단계=`g7-verify` 호출로 연결한다. **각 단계가 실제로 별도 컨텍스트로 도는지** 업로드 직후 짧은 테스트 회신 1건으로 확인한다.

3. **커넥터**
   - **새 워크스페이스에는 아무 커넥터도 등록하지 않는다.** (0단계 참고 — 이게 1차 방어)
   - 스킬 본문의 "resend를 절대 호출하지 않는다" 지침은 2차 방어로 남아 있다. 실행 로그에서 발신 시도가 없는지 그래도 확인한다.

## 확인 체크리스트 (첫 실행 직후)

- [ ] T 호출과 V 호출이 실제로 별도 대화/컨텍스트로 갈렸는가 (V가 T의 판단층을 못 봤는가)
- [ ] resend가 호출되지 않았는가
- [ ] `발송금지.md`가 V의 결과를 기다리지 않고 T 직후 기록됐는가 (수신거부 테스트 케이스로 확인)
- [ ] 검증 불일치 케이스에서 자동화가 재시도/분기를 실제로 하는지, 못 하면 수동 재실행 경로로 대체됐는지

이 체크리스트가 통과하면 `../00_TimelyAI_매핑설계.md` 5절의 "확인 필요" 두 항목을 지우고 확정으로 옮긴다.
