# G7(회신 해석·정리) × TimelyAI 매핑 설계

## 0. 전제

- 정본 Spec: `./spec.md`(원본 `specs/G7_회신해석정리.md`) · 정본 기준: `./기준.md`(원본 `기준/G7_회신판정기준.md`). 이 문서는 그 둘을 **바꾸지 않고**, TimelyAI 개념(스킬/자동화/커넥터)에 어떻게 얹는지만 정한다.
- TimelyAI 확인된 사실(2026-08-05, 사용자 확인 + `timelyai.png`):
  - **자동화**(Automation) = 오케스트레이터 → 하위 에이전트 체인. **하위 에이전트 호출마다 독립된 컨텍스트**로 실행된다 — G7의 "T와 V는 다른 컨텍스트" 무관용 제약을 그대로 만족시킬 수 있다.
  - **스킬**(Skill) = 워크스페이스에 토글로 켜는 재사용 절차(지침 텍스트).
  - **커넥터**(Connector) = 외부 API 연동. 지금 워크스페이스엔 `resend`(이메일 발송) 하나뿐.
  - 모델: Solar Pro4. 파일 작업 공간(업로드·생성) 존재.
- **확인됨(2026-08-05)**: TimelyAI의 커넥터는 **워크스페이스 전체에 공용** — 개별 스킬/자동화 단위로 껐다 켰다 할 수 없다. 기존 워크스페이스엔 이미 `resend`가 연결돼 있어, 그 워크스페이스에서 G7을 돌리면 T·V가 이론상 발신 도구에 접근 가능하다.
- **결정(2026-08-05, 사용자 확정)**: 그래서 **G7은 `resend`를 아예 연결하지 않은 전용 새 워크스페이스에서 만든다.** Spec의 무관용 제약("답장 권한을 사후 점검이 아니라 권한 자체로 막는다")을 그대로 지키는 유일한 방법이 이것이다 — 프롬프트 지침("resend를 호출하지 마라")만으로 막는 방식은 사후 점검과 다를 게 없어 기각했다. 프롬프트 지침은 그래도 SKILL.md에 남겨 **이중 방어**로 쓴다(새 워크스페이스가 1차 방어, 프롬프트가 2차 방어).
- **미확인** (표시만 하고 지금 결정하지 않음): 자동화가 **조건부 분기/재시도 루프**를 지원하는지. 4절에서 두 가지 경로로 나눠 둔다.

## 1. 구성요소 매핑

| TimelyAI 개념 | G7에서 쓰는 것 |
|---|---|
| 자동화 (오케스트레이터) | `G7-회신처리` 1개 — T 스킬 호출 → V 스킬 호출 → 최종화 |
| 스킬 A | `g7-interpret` — 원문 입력 → 원문층/해석층/판단층 초안 생성 |
| 스킬 B | `g7-verify` — 원문+해석만 입력 → 검증층 생성(+ 필요시 분류 재판정) |
| 커넥터 | **연결 안 함.** G7 전용 새 워크스페이스에는 처음부터 `resend`를 연결하지 않는다 — 이게 1차 방어(권한 차단). T·V 스킬 프롬프트의 "resend를 호출하지 않는다" 지침은 2차 방어 |
| 파일 작업공간 | `replies/{수신일시}-{식별자}.md` 1건 + 공용 `발송금지.md`(append 전용) |

## 2. 실행 흐름 (자동화 단계)

```
[입력: 회신 원문 붙여넣기 + 헤더 + (있으면) 참조 발신 정보]
        │
        ▼
  ① g7-interpret  ── 독립 컨텍스트 1
        │  출력: 원문층 / 해석층 / 판단층(분류·수신거부·자동응답·요구 등)
        │
        ├─▶ 수신거부 = 거부 또는 의심 즉시 → 발송금지.md에 append
        │     (V의 결과를 기다리지 않는다 — T 직후 바로 기록)
        ▼
  ② g7-verify  ── 독립 컨텍스트 2 (T와 다른 호출)
        │  입력: **원문(일본어) + 한국어 해석 이 둘만** — 판단층은 넘기지 않는다
        │  출력: 검증층(3층 일치/불일치 + 불일치 지점) + **원문 자체 재스캔한 수신거부 표현 유무(T 판정과 무관하게 독립 산출)**
        ▼
  ②.5 수신거부 교차확인 (오케스트레이터) — T 판정 vs V의 독립 재스캔을 대조. V만 발견했으면 T가 놓친 것 → 즉시 발송금지.md 추가 + 사람에게 불일치 표시
        ▼
  ③ 최종화 (오케스트레이터가 T의 출력 + V의 출력 + 교차확인 결과를 합침)
        │  검증 결과가 "일치" → replies/{}.md 로 저장, 성공 기준 판정
        │  검증 결과가 "불일치" → 4절 실패 처리로
```

**②.5를 추가한 이유(2026-08-05, 시뮬레이션으로 발견)**: V는 T의 판단층(수신거부 판정 포함)을 못 보게 설계돼 있는데, 그 말은 **T가 수신거부 표현을 놓쳐도 아무도 잡아내지 못하는 구조**였다는 뜻이다. V가 어차피 원문을 갖고 있으니, 번역 검증과는 별개로 "원문에 수신거부 표현이 있는가"를 V가 독립적으로 다시 스캔하게 해서, T의 누락을 잡아내는 이중 확인을 추가했다. 법 위반(무관용) 리스크라 이중화할 가치가 있다고 판단했다.

**"수신거부는 병렬로 즉시"(Spec 제약)를 만족시키는 방법**: 자동화가 순차 체인이라도, ①이 끝나는 즉시(②를 부르기 전에) 발송금지.md 기록을 먼저 실행하면 "V의 성패와 무관하게 즉시"라는 요구를 그대로 만족한다 — 진짜 동시 실행(병렬 스레드)이 필요한 게 아니라 **V를 기다리지 않는 순서**면 충분하다.

## 3. 스킬 경계 (Spec의 "실행체 경계 4개"를 TimelyAI 언어로)

| 경계 | g7-interpret | g7-verify |
|---|---|---|
| 입력 | 회신 원문(일본어, 그대로) + 헤더 + 첨부 파일명 + 참조 발신 정보(또는 `참조 문안 없음`) | **T 출력 중 원문·해석 두 필드만** — 오케스트레이터가 추려서 넘긴다. 분류·판단 과정은 절대 포함하지 않는다 |
| 출력 | 원문층 + 해석층(문장 대응·애매표시) + 판단층(8분류·수신거부·자동응답·요구·담당자정보·조치요청) | 검증층(3층 각 일치/불일치 + 불일치 지점 + 권고 처리) + (3층 불일치 시) 분류 재판정 |
| 도구 권한 | 텍스트 읽기 + `발송금지.md` append 쓰기 + 초안 파일 쓰기. **커넥터 없음(발신 불가)** | 초안 파일의 원문·해석 필드 읽기 + 검증층 쓰기. **커넥터 없음** |
| 독립 컨텍스트 | 회신 1통 = 새 자동화 실행 1회 | T와 별도 하위 에이전트 호출 — TimelyAI가 컨텍스트를 자동 분리 |

## 4. 실패 처리 매핑

| Spec 실패 | TimelyAI 자동화에서 |
|---|---|
| 판독 불가 | T가 즉시 C8로 표시 + 원문 그대로 최종화 — ②(V) 생략하고 바로 ③으로 |
| 검증 불일치 (1회차) | **분기/재시도가 되면**: ②를 1회만 다시 호출(재번역 프롬프트로), 그래도 불일치면 C8 + 원문·두 번역본·불일치 지점을 최종 레코드에 기록 |
|  | **분기/재시도가 안 되면**(3절 미확인): ②가 "불일치"를 출력하면 자동화는 거기서 멈추고, 사용자가 ①을 재번역 지침으로 **수동 1회 재실행**한 뒤 ②를 다시 돌린다. 여전히 불일치면 C8 |
| 검증층이 비어 있음 | ③ 최종화 단계가 검증층 유무를 확인 — 비어 있으면 그 레코드를 사용자에게 올리지 않고 "검증 대기"로만 남긴다 |

## 5. 확인 필요

- TimelyAI 자동화가 **조건부 분기·재시도 루프**를 지원하는지 — 지원 여부에 따라 4절의 두 경로 중 하나로 확정한다. 실제로 자동화 편집창에서 만들어보며 확인.
- **(해결됨 2026-08-05)** 커넥터 스코프는 워크스페이스 공용으로 확인됐고, **G7 전용 새 워크스페이스(resend 미연결)를 만드는 것으로 결정**했다. 이 새 워크스페이스를 만들 때 **resend를 포함해 어떤 커넥터도 추가하지 않는다.** SKILL.md의 "resend를 호출하지 않는다" 지침은 이중 방어로 유지한다.
- 그 외에는 이 매핑대로 A(붙여넣기용 패키지)로 넘어가도 된다.
