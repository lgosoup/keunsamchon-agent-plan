# 40_검증계획.md — G7 TimelyAI 재검증 테스트 케이스

> 목적: `package/README.md`의 "확인 체크리스트" 4개 항목을 실제 TimelyAI 워크스페이스에서 통과시킨다.
> 정본: `spec.md` · `기준.md` · `package/automation/AGENT.md`. 이 파일은 그 셋을 실행 가능한 테스트 입력으로 옮긴 것 — 판정 기준 자체를 바꾸지 않는다.
> 사용법: 아래 "실행 N"을 **한 번에 하나씩**, 자동화(`g7-reply-pipeline`)에 넣어 따로 실행한다. 체크포인트 설명은 결과를 눈으로 대조할 때만 쓰고, 입력에는 포함하지 않는다.

---

## 공통 입력 템플릿 (spec.md 「입력」)

```
회신 원문:
[일본어 텍스트 — 줄바꿈·서명·인용부 그대로]

헤더:
- 발신 주소:
- 수신일시:
- 제목:
- 스레드 식별자:

첨부: 없음
참조 발신 정보: 참조 문안 없음
```

## 실행 1 — 정상 관심 회신 (①·② 확인용)

```
회신 원문:
先日ご提案いただいた件、大変興味深く拝読いたしました。
一度詳しいお話を伺いたく、来週中にお電話でお時間いただけますでしょうか。

헤더:
- 발신 주소: tanaka@example.co.jp
- 수신일시: 2026-08-05 10:00
- 제목: Re: ご提案について
- 스레드 식별자: THREAD-001

첨부: 없음
참조 발신 정보: 참조 문안 없음
```

**체크포인트**
- ① T/V 컨텍스트 분리: V의 검증층 출력에 "C1", "관심" 같은 분류 판단 단어가 새어나오지 않았는가 (나왔으면 분리 실패)
- ② resend 미호출: 실행 로그에 커넥터 호출 이력이 없는가

## 실행 2 — 명시적 수신거부 (③ 확인용)

```
회신 원문:
今後、貴社からのご連絡は一切お控えいただくようお願いいたします。
配信停止の手続きをお願いいたします。

헤더:
- 발신 주소: suzuki@example.co.jp
- 수신일시: 2026-08-05 10:10
- 제목: Re: ご提案について
- 스레드 식별자: THREAD-002

첨부: 없음
참조 발신 정보: 참조 문안 없음
```

**체크포인트**
- ③ `발송금지.md`에 한 줄이 **V의 검증 결과를 기다리지 않고** T 직후 추가됐는가 (AGENT.md 1.5단계)
- 추가된 줄에 메일주소·근거 원문 인용·수신일시·출처파일명 네 항목이 다 있는가

---

## 실행 3 — 부분적 거부 (③ 보강 — T가 놓치는 경우 대비)

```
회신 원문:
今後、このような一斉配信のようなご案内は不要です。

헤더:
- 발신 주소: sato@example.co.jp
- 수신일시: 2026-08-05 10:20
- 제목: Re: ご提案について
- 스레드 식별자: THREAD-003

첨부: 없음
참조 발신 정보: 참조 문안 없음
```

**체크포인트**
- T가 "거부 아님"으로 판정해도, V가 원문에서 독립적으로 수신거부성 표현을 찾아 `발송금지.md`에 들어갔는가 (AGENT.md 3.5단계 교차확인)
- 최종 레코드의 사용자 조치 요청 칸에 "T·V 판정 불일치 — 사람이 재확인" 문구가 남았는가

## 실행 4 — 함정 문장 (④ 검증 불일치·재시도 분기 확인용)

```
회신 원문:
貴社のご提案につきましては、社内で検討させていただきましたが、
価格面で他社と比較検討中のため、今回は見送らせていただきます。
なお、担当が変更となりましたので、後任の山田までご連絡ください。
山田: yamada@example.co.jp

헤더:
- 발신 주소: yamada-old@example.co.jp
- 수신일시: 2026-08-05 10:30
- 제목: Re: ご提案について
- 스레드 식별자: THREAD-004

첨부: 없음
참조 발신 정보: 참조 문안 없음
```

**체크포인트**
- 検討 뒤에 見送り가 바로 이어지므로 애매 표시 없이 C3(거절-이유있음, 가격 비교)으로 확정됐는가
- 담당자 이관 정보(山田, 이메일)가 "담당자 정보 갱신" 칸에만 들어갔는가 (다른 칸에 복제되지 않았는가)
- (우연히 오역이 나오면) V가 3층에서 불일치를 잡아 "분류 재판정 필요" 플래그를 남기고, 오케스트레이터가 재번역 1회 → 재검증을 실제로 도는가. 도지 못하면 AGENT.md "확인 필요" 절대로 자동화가 멈추는지 확인

## 보강 — g7-verify 단독 테스트 (④의 강제 재현)

LLM이 스스로 오역하길 기다리는 대신, `g7-verify` 스킬만 따로 호출해 강제로 불일치를 만들어 V 단독 성능을 확인한다. 자동화(`g7-reply-pipeline`)가 아니라 스킬 실행 화면에서 아래 두 줄만 넣는다.

```
원문(일본어): 今回は見送らせていただきます。
한국어 해석: 이번 제안을 진행하겠습니다.
```

**체크포인트**
- 3층(어조·방향)에서 불일치로 잡아내는가
- 1층·2층은 근거 없이 따라서 불일치로 적지 않는가 (층별 독립 판정, `기준.md` 3절)
- "분류 재판정 필요" 플래그만 남기고 스스로 재분류하지 않는가

## 결과 기록표 (2026-08-05 실행)

> **⚠ 이 표는 실제 TimelyAI가 아니라 Claude Code 하위 에이전트로 파이프라인을 시뮬레이션한 결과다.** `package/README.md`에 명시된 대로 "이 저장소(Claude Code)에서는 TimelyAI를 직접 실행할 수 없어 — 설계·시뮬레이션 검증까지만 이 harness가 보장"한다. 아래 O는 **"시뮬레이션 통과"**를 뜻하고, 실제 TimelyAI 업로드 후 사람이 다시 확인해야 확정이다.
> **확인 방식** 열: `직접확인` = 파일을 직접 열어(cat/Read) 대조함 / `서술` = 하위 에이전트의 출력 설명을 근거로 판단함 (서술 기반은 신뢰도가 낮다 — 아래 실행 4 사례 참조).

| 실행 | 체크포인트 | 통과(O/X) | 확인 방식 | 비고 |
|---|---|---|---|---|
| 1 | ① T/V 컨텍스트 분리 | O (조건부) | 서술 | V 출력에 '조건'·'거절'·'수신거부' 단어는 있었지만, T 판정을 그대로 인용·재생산한 분류 재현 문장은 없었음. 기준 B("T 판정을 그대로 옮겨 분류 재현하지만 않으면 통과")로는 통과. 단어 자체를 0개로 보는 stricter 기준으로는 재검토 여지 있음. V 호출의 실제 입력 payload(원문+해석 두 필드만인지)는 아직 직접 확인 못함 |
| 1 | ② resend 미호출 | O | 서술 | T·V·최종화 모두 발신 도구 호출 없이 replies 저장 + 발송금지.md 확인만 수행했다고 명시. 실제 커넥터 호출 이력 로그까지 확인한 건 아니라 필요하면 로그 수준 재확인 |
| 2 | ③ 발송금지.md 즉시 기록 (T 직후) | O | 직접확인 | 명시적 수신거부 건. T 직후 발송금지.md가 생성되고 한 줄 추가됨. `cat`으로 확인: 메일주소·근거 원문 인용·수신일시·출처파일명(40_검증계획.md) 4항목 모두 포함 |
| 3 | ③ 보강 — V의 독립 수신거부 탐지 + 교차확인 반영 | O (단, 시나리오 상이) | 서술 | 이 건은 T가 처음부터 "거부"로 판정해 "T가 거부 아님으로 판정했는데 V가 잡아내는" 시나리오 자체는 발생하지 않음. 대신 T·V가 모두 독립적으로 수신거부를 찾아 일치했고 발송금지.md에도 sato 줄이 추가됨 — "불일치가 아닌데도 정상 처리되는지"는 확인됨. **진짜 T 누락→V 단독 포착 시나리오는 더 애매한 경계 표현으로 재현 필요** |
| 3 | ③ 보강 — 사용자 조치 요청 칸에 "T·V 판정 불일치" 문구 | 기재 안 됨 (정상) | 서술 | 이 건은 T·V 불일치가 아니므로 문구가 남지 않음 — "불일치일 때만 그 문구가 남는지" 확인용으로 재사용 가능 |
| 4 | 검토→견송 문맥 확정, 애매표시 안 함 | O | 서술 | 「検討させていただきましたが」 뒤 바로 「今回は見送らせていただきます。」로 결론이 나 애매 표시 없이 C3(거절-이유있음, 가격 비교)로 확정됨 |
| 4 | 담당자 정보 갱신 칸 분리 | O (해석 전문 내 원문 보존은 별개) | 서술 | 山田/yamada@example.co.jp는 "담당자 정보 갱신분" 칸에만 들어감. 해석 전문에 같은 문장이 남아 있는 건 원문 보존 요구사항이라 별도 칸 복제 위반은 아님 |
| 4 | 재시도/분기 실제 동작 여부 | 확인 제한 (불일치 미발생) | 서술 | 이 실행은 3층 전체 일치라 "재번역→재검증" 분기까지 실제로 도는지 직접 보진 못함. 대신 보강(단독 V 강제 불일치)에서 3층 불일치를 잡아 "분류 재판정 필요" 플래그를 남기고 스스로 재분류하지 않는 동작은 확인됨 — 분기의 **조건 발동 자체**는 V가 갖추었다고 볼 수 있으나, 오케스트레이터의 **재호출 루프 지원 여부**는 TimelyAI 실제 업로드 후에만 확정 가능(`AGENT.md` "확인 필요" 절) |
| 4 | (부수 발견) 발송금지.md 상태 서술 정확도 | X | 직접확인 | 실행 4 하위 에이전트는 "발송금지.md가 없어서 suzuki/sato 유지 여부 확인 불가"라고 서술했으나, 직접 `cat` 확인 결과 두 줄 모두 살아 있었음(append-only 유지, 데이터 손실 없음). **핵심 체크포인트(C3 확정/담당자 분리/플래그 조건)와는 인과관계 없어 그 결론은 유지** — 방법론 소견으로만 기록 |
| 보강 | g7-verify 단독 — 3층 불일치 탐지 | O | 서술 | 원문(見送る=보류/거절) vs 해석(진행하겠습니다) 강제 입력에서 층1(의미보존)·층3(어조·방향) 불일치를 잡음. 층2는 해당 항목 없어 "일치"로 독립 유지(불일치 층에 안 끌려감). "분류 재판정 필요" 플래그만 남기고 스스로 재분류하지 않음 |

**방법론 소견**: 하위 에이전트의 자체 상태 서술은 실제 파일 상태와 어긋날 수 있음이 확인됨(실행 4). **되돌릴 수 없는 무관용 항목(원문 보존·방향 반전·수신거부 기록)일수록 서술이 아니라 직접 조회로 재확인해야 한다.**

**남은 확인 항목**
- V 호출의 실제 입력 payload가 원문+해석 두 필드만인지 (①의 더 엄격한 확인)
- resend 커넥터 호출 로그 레벨 확인 (②)
- "T가 놓치고 V가 잡는" 수신거부 실사례 재현 (실행 3, 더 애매한 경계 표현 필요)
- TimelyAI의 조건부 재시도/분기 실제 지원 여부 (실행 4, 실제 업로드 후에만 확정 가능)

이 표는 시뮬레이션 결과이므로 `00_TimelyAI_매핑설계.md` 5절 "확인 필요" 항목을 아직 확정으로 옮기지 않는다 — 위 "남은 확인 항목"이 실제 TimelyAI 업로드 후 통과해야 확정된다.
